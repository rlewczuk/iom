# Extract TTNN testing seams

**Order:** 08
**Priority:** P0 — centralizes existing test seam state before queue code moves across translation units
**Blocked by:** None
**Source:** `docs/changes/005-split-big-files/spec.md`

## Outcome

Extract the existing TTNN fault-injection, counter, and testing-hook machinery into the planned private `src/ttnn/testing_internal.hpp` and `src/ttnn/testing.cpp`. Device, copy, queue, binary, and staging implementation code will call the same private seam hooks regardless of which translation unit owns the production operation after the surrounding split. The `iom::ttnn_test` API and every observable fault, counter, ownership, and ordering behavior remain unchanged. This is source factoring only; it adds no capability and no test.

## Scope

- Create private `src/ttnn/testing_internal.hpp` as the declaration boundary for the seam consumers used by TTNN production translation units and the existing `iom::ttnn_test` declarations.
- Create `src/ttnn/testing.cpp` as the single definition and state owner for the existing device/copy testing machinery. Move the state and consumers represented by `src/ttnn/device.cpp:35-113` and the API definitions at `src/ttnn/device.cpp:1050-1108`, plus the state/consumers represented by `src/ttnn/copy.cpp:20-68` and the API definitions at `src/ttnn/copy.cpp:611-654`.
- Keep the ordinary staging implementation in `src/ttnn/staging.hpp`: `TtnnHostStaging`, its upload/download slots and leases, dispositions, retained ownership, retirement, reclaim behavior, and its existing instrumentation state remain there. If a private include is needed, touch `staging.hpp` only to consume the private seam without changing allocation semantics.
- Route existing call sites to the private seam boundary: quarantine-action construction in `TtnnTensor::~TtnnTensor`, copy registration and outcome insertion in `TtnnQueue::execute_copy`, copy-drain finish accounting/faulting in `finish_locked_mesh`, per-plane `copy_planes` submission, and host upload/download submission.
- Keep the existing `iom::ttnn_test` declarations available through `src/ttnn/registry_state.hpp`. If needed, make that header include `testing_internal.hpp` and remove only duplicate declaration text; do not change the declaration names, namespaces, signatures, or test include path.
- Update the TTNN library target in `CMakeLists.txt:114-142` to list `src/ttnn/testing.cpp` and the private seam header. Retain `src/ttnn/device.cpp`, `src/ttnn/copy.cpp`, `src/ttnn/registry_state.hpp`, and `src/ttnn/staging.hpp`. Retain the existing `PRIVATE IOM_ENABLE_TESTING` definition at `CMakeLists.txt:286-288` exactly as a private TTNN target definition.

## Implementation references

- **Create:** `src/ttnn/testing_internal.hpp` — private seam declarations only; no public header or backend-neutral abstraction.
- **Create:** `src/ttnn/testing.cpp` — one guarded definition of all seam state, fault consumers, counters, hooks, and `iom::ttnn_test` API functions.
- **Modify:** `src/ttnn/device.cpp:35-113,397-399,501-518,764-777,1049-1108` — remove local testing storage/helpers and API definitions; preserve the existing call-site timing and the non-testing paths.
- **Modify:** `src/ttnn/copy.cpp:20-68,216-218,244-246,404-418,611-654` — remove local submission-fault storage/helpers and API definitions; call private hooks at the same pre-submission points.
- **Modify only if needed for the private seam:** `src/ttnn/staging.hpp:32-39,258-281` — include the private seam if required by the moved API definitions, but leave staging seam state and all staging allocation, lease, retirement, and reclaim code and semantics intact.
- **Modify:** `src/ttnn/registry_state.hpp:12-67` — preserve the existing `iom::ttnn_test` declaration surface through the private seam include without duplicate declarations.
- **Modify:** `CMakeLists.txt:121-128,286-288` — add the new implementation/header to `iom_ttnn`; preserve the current source list and private testing define otherwise.
- **Read-only behavior references:** `test/ttnn/test_ttnn_conformance.cpp:743-1495` exercises retained staging allocation/reuse, partial-plane submission failure, registration/outcome rollback, binary pre-native failure, repeatable failed waits, finish counting/failure, batching, and quarantine-action failure. Existing staging seam coverage also appears around `test/ttnn/test_ttnn_conformance.cpp:428-435`. These tests are not modified and no new tests are added.

## Requirements

1. Keep all device/copy seam state represented by the assigned ranges in exactly one implementation translation unit, `src/ttnn/testing.cpp`. Under `IOM_ENABLE_TESTING`, preserve the existing atomic types, initial values, and memory-order behavior for armed flags, selected plane indices, consumed flags, registration/outcome faults, remaining finish faults, and finish-attempt counters. Preserve the existing non-atomic quarantine consumed flag and its mutex-protected access rather than changing its synchronization model. The existing staging instrumentation state remains governed by `staging.hpp` and is not relocated by this task.
2. In `testing_internal.hpp`, expose only private hook declarations needed by production code. The boundary must cover the existing consumers: `consume_quarantine_action_fault_locked()`, `consume_copy_registration_fault()`, `consume_copy_outcome_insertion_fault()`, `consume_binary_outcome_insertion_fault()`, `consume_copy_finish_fault()`, `fail_copy_planes_submission_at(std::size_t)`, and `fail_host_transfer_submission_at(std::size_t)`. Hooks that can throw retain their current `noexcept(false)` behavior; non-throwing hooks retain `noexcept`.
3. Preserve the exact public `iom::ttnn_test` API declarations and signatures currently supplied by `registry_state.hpp`: `fail_next_quarantine_action_for_testing()`, `quarantine_action_fault_consumed_for_testing()`, `fail_next_copy_planes_submission_for_testing(std::size_t)`, `copy_planes_submission_fault_consumed_for_testing()`, `fail_next_binary_outcome_insertion_for_testing()`, `binary_outcome_insertion_fault_consumed_for_testing()`, `fail_next_copy_registration_for_testing()`, `copy_registration_fault_consumed_for_testing()`, `fail_next_copy_outcome_insertion_for_testing()`, `copy_outcome_insertion_fault_consumed_for_testing()`, `fail_next_copy_finishes_for_testing(std::size_t)`, `copy_finish_fault_pending_for_testing()`, `reset_copy_finish_count_for_testing()`, `copy_finish_count_for_testing()`, `fail_next_host_transfer_submission_for_testing(std::size_t)`, `host_transfer_submission_fault_consumed_for_testing()`, `fail_next_host_transfer_staging_allocation_for_testing()`, `host_transfer_staging_allocation_fault_consumed_for_testing()`, and `host_transfer_staging_allocation_count_for_testing()`.
4. Keep the current guard boundary for the moved device/copy machinery: its seam storage, consumers, and API definitions are emitted only under `#ifdef IOM_ENABLE_TESTING`; existing call-site guards remain in production files. The staging instrumentation retains its current guard boundary and storage behavior. A build without `IOM_ENABLE_TESTING` must not gain seam calls or change production behavior. The TTNN target remains the owner of the existing private testing define; do not add a new switch or define to another target.
5. Preserve quarantine fault timing and semantics. `consume_quarantine_action_fault_locked()` is called only at the current cleanup-action construction point while the owning device API mutex is held, throws `std::bad_alloc()` only under the currently armed/consumption rules, and leaves the existing fallback that keeps native storage unreachable when construction fails. Do not reset or otherwise reinterpret the existing consumed-state behavior.
6. Preserve transaction-fault timing and categories. Registration fault is consumed before `detail::register_copy_entries`; copy outcome-insertion fault is consumed while holding `outcome_mutex_` immediately before `outcomes_.emplace`; binary outcome-insertion fault remains before any native output upload. Each retains `std::bad_alloc`, existing consumed flags, rollback, sequence behavior, and error mapping.
7. Preserve copy-plane and host-transfer fault timing and messages. The copy-plane hook runs immediately before submitting the selected plane in `copy_planes`; the host-transfer hook runs immediately before `ttnn::copy_to_device` or `ttnn::copy_to_host` for the selected plane. Selected-index arming, one-shot disarming, consumed flags, acquire/release ordering, partial submission behavior, and the existing runtime-error categories/messages are unchanged.
8. Preserve finish counter/fault semantics. The copy-drain finish hook increments the finish-attempt counter before checking the remaining-failure count, decrements that count atomically once per failed attempt, and throws the existing `"injected TTNN copy finish failure"` error when armed. It is used only by the copy-drain path through `finish_locked_mesh`; host-transfer finishes, fence invokes, and quarantine drains remain unaffected. Reset/query/pending APIs retain their current ordering and values.
9. Preserve retained staging semantics exactly. Do not relocate the staging instrumentation state or ordinary `TtnnHostStaging` ownership. If the moved API definitions include `staging.hpp` to query or arm that existing state, count only fresh underlying allocations as before, consume an allocation fault only on growth beyond capacity, and leave a failed-growth slot untouched. Reuse, zero-fill, capacity-only resize, download retirement, upload retirement, and device-owned lifetime are not moved or redesigned.
10. Preserve linkage and ODR. No moved device/copy seam variable may remain as a second definition in a header, `device.cpp`, `copy.cpp`, or another split file. Private hooks have one implementation and are included only through private source paths; the existing staging instrumentation remains in its current owner. Public headers/signatures and TTNN backend capability declarations are unchanged.
11. Add `src/ttnn/testing.cpp` and `src/ttnn/testing_internal.hpp` to the `iom_ttnn` target without altering TTNN test target source lists. The existing TTNN smoke and conformance executables continue to receive their API declarations and link to the same `iom_ttnn` implementation.
12. Keep `src/ttnn/testing.cpp` and `src/ttnn/testing_internal.hpp` at no more than 499 physical lines after normal formatting. The intentionally retained intermediate `device.cpp` and `copy.cpp` may remain oversized until their assigned queue/binary cutovers; the final integrated task enforces the cap for every retained original, touched, or new production `.cpp`, `.cu`, `.hip`, `.hpp`, and `.inl`. Use no permanent scanner or line-count test.

## Non-goals

- Do not implement queue splitting, queue behavior changes, binary factoring, dtype factoring, registry redesign, staging ownership redesign, or any other production factoring assigned to another task.
- Do not move `TtnnHostStaging` or its ordinary allocation/lease/retirement ownership out of `src/ttnn/staging.hpp`; do not relocate its existing instrumentation state. A private include is allowed only when needed to connect the moved seam without changing allocation semantics.
- Do not alter `IOM_ENABLE_TESTING` policy, introduce another backend switch, expose seam state publicly, create a global registry, or add a cross-backend testing abstraction.
- Do not change any public header, public factory, signature, capability, error category, validation order, ownership/lifetime rule, queue ordering, repeatable wait/failure behavior, registry/quarantine semantics, staging allocation behavior, context behavior, or numerical result.
- Do not change `test/ttnn/test_ttnn_conformance.cpp`, add tests, change test source lists, or add a permanent line-count test.
- Do not run builds, tests, linters, formatters, or validation gates while writing this specification.

## Acceptance criteria

- [ ] `src/ttnn/testing.cpp` is the sole definition site for every device/copy seam state, consumer, counter, hook, and `iom::ttnn_test` function listed above; `device.cpp` and `copy.cpp` retain no duplicate seam storage or API definitions.
- [ ] `src/ttnn/testing_internal.hpp` exposes only the private throwing/non-throwing consumers required by TTNN implementation files, and `registry_state.hpp` still supplies the exact existing `iom::ttnn_test` declarations to current consumers.
- [ ] Builds with and without `IOM_ENABLE_TESTING` compile the same production behavior: disabled builds do not execute moved seam calls or bookkeeping, while enabled builds link exactly one moved implementation and preserve ODR/private visibility; existing staging instrumentation behavior is unchanged.
- [ ] Existing fault behavior remains observable at the same points: quarantine action construction, copy registration, copy/binary outcome insertion, selected copy/host-transfer plane submission, and selected count of copy finishes. Existing error types/messages, consumed flags, counting, rollback, and sequence/token behavior are unchanged.
- [ ] Existing staging behavior remains observable: retained slots and leases have identical ownership and retirement, fresh-allocation counts are unchanged, allocation faults leave slots untouched, and host transfer recovery still follows the existing completion-proof rules.
- [ ] The TTNN CMake target contains `testing.cpp` and the private seam header, retains `device.cpp`/`copy.cpp`/existing headers, and retains `target_compile_definitions(iom_ttnn PRIVATE IOM_ENABLE_TESTING)` unchanged.
- [ ] `src/ttnn/testing.cpp` and `src/ttnn/testing_internal.hpp` are each at most 499 physical lines. Later TTNN queue/binary cutovers bring the retained original translation units under the final cap, and no test source or permanent line-count test is added.
- [ ] Existing TTNN conformance behavior references around `test/ttnn/test_ttnn_conformance.cpp:743-1495` remain valid without source changes, including partial-plane recovery, transaction rollback, repeatable failures, native-finish counting/failure, batching, and quarantine tests.
