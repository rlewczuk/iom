# Extract SYCL binary queue execution

**Order:** 15
**Priority:** P1 — completes the SYCL queue split after declarations and lifecycle exist.
**Blocked by:** `14-sycl-queue-core`
**Source:** `docs/changes/005-split-big-files/spec.md`

## Outcome

Move the temporary SYCL `SyclQueue::execute_binary(Task&)` definition, including binary workspace requirement arithmetic and binary execution, out of `src/sycl/copy.cpp` into planned `src/sycl/queue_binary.cpp`. The extracted translation unit remains a responsibility-complete implementation of the four existing binary operations while preserving the accepted workspace range, host-staging algorithm, in-order queue behavior, registry/outcome lifetime, failure mapping, completion proof, and every allocation seam. This is source factoring only: public headers, signatures, capabilities, arithmetic, and queue lifecycle remain unchanged.

## Requirements

- Preserve the pure binary requirement result exactly. Recompute each operand/output extent with whole-plane padded-storage semantics through the highest addressed plane, using checked plane walks, padded plane element/bit/byte arithmetic, and checked multiplication/addition. Return `align_up(lhs_bytes, 32) + align_up(rhs_bytes, 32) + out_bytes` with alignment `32`; check each alignment and sum for overflow and preserve the existing `std::overflow_error` messages/categories.
- Preserve the accepted workspace layout exactly: `lhs` begins at offset `0`, `rhs` at `align_up(lhs_bytes, 32)`, and output at `align_up(lhs_bytes, 32) + align_up(rhs_bytes, 32)`. Obtain the workspace base through the accepted `iom::detail::WorkspaceValidation::address(captured.workspace)` path, retain the existing checked offsets, and never reinterpret the range as host memory or change the capacity/alignment contract.
- Preserve the host-staging-only execution path. Allocate exactly the existing three temporary host-USM buffers with `sycl::malloc_host`, copy each native operand extent into the corresponding device-workspace slice on the in-order queue, copy slices to host staging, drain before host computation, run the existing shared scalar implementation, copy output staging back to the workspace and then to the native output, and perform the existing final drain. Do not add a direct binary device kernel, shared-USM escape hatch, implicit workspace allocation, or device-workspace allocation/free.
- Preserve the single scalar implementation and operation dispatch for `BinaryOperation::Add`, `Mul`, `Sub`, and `Div`, including bit-packed load/store, transformed-view plane addressing, broadcast rows/columns, result-shape traversal, dtype behavior, padding, untouched planes, and numerical bit patterns. Do not add an operation, capability, kernel, or backend switch.
- Preserve task submission context and order. Binary tasks must continue to use the existing captured `BinaryRequest`, in-order `sycl::queue`, immutable sequence, `SyclFenceState`, `detail::BinaryEntryRegistration`, and captured `detail::WorkspaceLease`; extraction must not add a queue, worker, lock, wait, or cross-queue synchronization.
- Preserve outcome and registry publication order: insert the binary `SyclSequenceOutcome` carrying state, binary entries, and workspace lease before native staging work; retain duplicate-sequence detection and the existing submission-fault seam. `queue_binary.cpp` must not independently complete, release, invalidate, or re-register entries; existing `complete_task` remains the owner of registry and workspace completion handling.
- Preserve exact failure and rollback order. The outcome-insertion fault fails before staging; the first-submit fault fails before native enqueue; once a native enqueue is attempted, conservatively retain the accepted outcome even if enqueue reports an error; on failure drain when `staged_enqueued` is true, record completion proof only when that drain succeeds, free all host staging buffers, erase the outcome and clear task state/fence only when nothing was submitted, and otherwise retain the exception as the repeatable asynchronous failure. Entry rollback remains owned by `submit_binary`; do not add a second removal that changes the original error.
- Preserve completion proof and lease lifetime. Mark `SyclFenceState` completion proven only after the existing successful final `queue_.wait_and_throw()` (or the existing successful failure-path covering drain), pass that proof through `complete_task` to `detail::complete_workspace_lease`, and release the `WorkspaceLease` only after proof. Unknown completion must retain/quarantine the lease and all associated registrations according to the existing queue lifecycle; never release it merely because host staging has been freed or an exception was captured.
- Preserve allocation seams and cleanup behavior exactly: `sycl::malloc_host`/`sycl::free` calls, null checks, exception-swallowing staging frees, `SubmissionFault::{outcome_insertion, first_submit, post_launch}`, and the existing SYCL native allocation observer/device-allocation seam must remain unchanged in meaning. Host-USM staging remains separate from device-arena/workspace allocation accounting.
- Keep private visibility and ODR intact. Include only the declarations needed by the new translation unit, define each moved helper and `execute_binary` member exactly once, and avoid making binary helpers public or introducing cross-backend abstractions. `queue.cpp` retains the sole `execute(Task&)` dispatcher; `queue_binary.cpp` must link with it without duplicating symbols retained in `copy.cpp`.
- Update only the SYCL library source list needed for this extraction. Do not change test target source lists, public factory headers, public signatures, `src/sycl/add.cpp`, or unrelated CMake entries.

## Non-goals

- Do not change binary validation, snapshots, public/protected signatures, workspace ownership or leasing contracts, queue admission/lifecycle, regular copy execution, host-transfer behavior, metadata/fence resource setup, or factory behavior.
- Do not add a binary kernel, operation, dtype, broadcast mode, capability, backend switch, allocator, global registry, compatibility alias/shim, or cross-backend binary abstraction.
- Do not redesign synchronization or ordering, replace the in-order queue, alter wait/repeat-failure semantics, move completion/registry responsibility, or release a workspace lease before completion proof.
- Do not alter `src/sycl/add.cpp`, add tests, change test source lists, or add a permanent line-count test. Existing tests are behavior proof; hardware tests must fail rather than skip.
- Do not remove host staging, use shared USM for workspace payload, change allocation instrumentation, or claim that SDK-internal SYCL allocations are absent.
