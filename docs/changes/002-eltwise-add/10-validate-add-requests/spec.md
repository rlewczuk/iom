# Validate ADD requests

**Order:** 10
**Priority:** P0 — establishes the executable common ADD contract and rejection boundary before any scalar or backend arithmetic is added.
**Blocked by:** `09-document-oid-contract`
**Source:** `docs/changes/002-eltwise-add/spec.md`

## Outcome

The common `DeviceOps::add` policy accepts or rejects an ADD request synchronously, before any output, allocation, submission, or sequence effect, and then delegates only a fully validated request to the protected backend hook. It preserves the exact three-view API, returns the required negative `oid` error for every synchronous failure, returns a positive token for an accepted supported numeric request, snapshots all view metadata, and keeps all three caller owners alive through completion with exact-alias deduplication. Deterministic fakes and shared conformance cases make each validation, precedence, lifetime, and error-mapping rule observable without performing scalar arithmetic or real backend execution.

## Scope

- Implement the backend-neutral, non-throwing public facade with exactly `oid add(const TensorView&, const TensorView&, TensorView&) noexcept`; ADD has no options argument, support query, public broadcast view, or caller-visible capability mechanism.
- Validate exact queue `Device` identity, owner identity and view metadata, recognized and well-formed specifications, matching leaf and quantization, checked shapes/offsets/strides/sizes, exact right-aligned broadcast compatibility/result shape, and input/output aliasing before effects or token acceptance.
- Apply the fixed synchronous error precedence: malformed or unknown specs, mismatched specs, device/owner/view/shape/alias errors map to `OidError::InvalidArgument`; checked arithmetic and sequence exhaustion map to `OidError::Overflow`; only after all three recognized specs match, `BOOL`, `F8_E8M0`, or a recognized non-`NONE` quantization maps to `OidError::Unsupported`; pre-acceptance allocation maps to `OidError::ResourceExhausted`; backend runtime failure before acceptance maps to `OidError::DeviceError`; any unclassified failure maps to `OidError::InternalError`.
- For ranks at least two, compute the exact right-aligned broadcast result by prepending conceptual singleton axes, including `[1,1]` as the only scalar convention. Permit equal axes or singleton axes only, and require `out` to have exactly the resulting shape. Preserve independent transformed leading-view offsets and strides and never read padding.
- Permit arbitrary `lhs`/`rhs` overlap. For each input versus `out`, permit same-owner aliasing only when `TensorSpec`, plane offset, plane strides, and logical element mapping are identical and no broadcast is involved; reject every other same-owner relationship, including provably disjoint windows and broadcast inputs.
- Snapshot every view's specification, shape, leaf, quantization, exact device identity, owner identity/handle, plane offset, plane strides, and derived logical mapping rather than retaining caller `TensorView` objects. Register all three owners for the accepted operation, deduplicating exact aliases, and release or quarantine them according to completion and retained-failure rules.
- Keep common code backend-neutral. The protected default ADD hook remains `Unsupported`; validation must not claim support for an excluded or malformed request, while a fully matching required numeric `NONE` request reaches the hook and returns a positive fake token.

## Requirements

- Expose only `oid add(const TensorView& lhs, const TensorView& rhs, TensorView& out) noexcept` publicly. Do not add `add_support`, an equivalent query, `EltwiseOpOptions`, an options parameter, a promotion knob, or a backend-specific fallback API. `add` itself is the sole support signal.
- Use exact `Device` object identity for all three views; backend kind or numeric device ID equality is not an identity substitute. Validate the exact owner identities separately from native handles so handles from different owners cannot be treated as one owner.
- Snapshot all metadata before invoking the protected hook: exact `TensorSpec` fields, rank and dimensions, recognized leaf and quantization enum values, device and owner identity, native handle, plane offset, plane strides, and the resolved logical-to-plane mapping. A temporary or derived `TensorView` may be destroyed immediately after the call without invalidating accepted work.
- Recognize every declared `DataType` and `QuantizationFormat` value explicitly. Unknown enum values, rank below two, zero dimensions, malformed view metadata, impossible owner/handle state, or metadata that cannot be safely checked are `InvalidArgument`, not `Unsupported`.
- Require the three recognized leaf types to match exactly and the three recognized quantization formats to match exactly. Any mismatch is `InvalidArgument`, even when one of the mismatched values is `BOOL`, `F8_E8M0`, or a non-`NONE` quantization. Only after all three recognized values match may the common excluded leaves (`BOOL` and `F8_E8M0`) or a recognized matching non-`NONE` quantization return `Unsupported`.
- For matching `QuantizationFormat::NONE`, accept each of the 21 required numeric leaves (`I2`, `U2`, `I4`, `U4`, `I8`, `U8`, `I16`, `U16`, `I32`, `U32`, `I64`, `U64`, `F4_E2M1`, `F6_E2M3`, `F6_E3M2`, `F8_E4M3FN`, `F8_E5M2`, `F16`, `BF16`, `F32`, and `F64`) through the common fake irrespective of native SDK dtype availability. This task validates and submits the request only; scalar arithmetic, backend emulation, and TTNN storage are separate tasks.
- Right-align operand ranks, conceptually prepend ones, and require every paired axis to be equal or singleton. The result dimension is the maximum paired dimension. Require `out.spec().shape` to equal that result exactly, including ranks 2, 3, and 6, final tiled-axis tails, opposite-direction singleton axes, and `[1,1]`; two `[1,1]` operands produce `[1,1]`. Resolve broadcast coordinates before tile/native-slot mapping and never address padding.
- Validate each transformed leading view independently. Check plane-offset and plane-stride counts and all products, sums, tile counts, logical element counts, byte/bit sizes, and address/slot calculations with checked arithmetic. Any checked arithmetic failure, including sequence exhaustion, returns `Overflow`; no wrapped value may be used for validation or submission.
- Reject public broadcast-view/zero-stride metadata and any other invalid stride or size representation as `InvalidArgument`; do not introduce a public zero-stride representation. Existing leading transformations remain supported when their metadata is valid.
- Permit arbitrary overlap between the two read-only inputs. Compare each input against `out` by exact owner identity and logical mapping: same-owner input/output is allowed only for identical spec, plane offset, plane strides, and logical mapping with no broadcast; all other same-owner relationships are rejected as `InvalidArgument`, including disjoint windows, broadcast windows, and non-identical transformed views. Different owners do not become aliases merely because native handles compare equal.
- Perform all validation before output writes, backend submission, sequence reservation/acceptance, or caller-visible allocation. A rejected request leaves the output bytes/sentinels, submission log, and next sequence unchanged. The facade must not allocate operands or relocate/replace caller-owned output storage or handles.
- On an accepted request, register the three caller owners against the one operation sequence and deduplicate exact owner aliases so an owner is retained and released once. If registration or any pre-acceptance metadata, staging, or registry allocation fails, return `ResourceExhausted` and roll back all partial registration without a token or effects. Retain owners through completion, repeat waits, and retained asynchronous failures; release or quarantine them exactly once after the terminal outcome.
- Invoke the protected backend ADD hook only after validation and lifetime registration are ready. Its pre-acceptance runtime failure maps to `DeviceError`; a synchronous allocation failure maps to `ResourceExhausted`; the documented OID overflow maps to `Overflow`; and any otherwise unclassified exception/failure maps to `InternalError`. No synchronous exception crosses the `noexcept` facade. Never turn an accepted positive token into a synchronous rejection; post-acceptance failures remain in the existing repeatable `wait`/retained-failure mechanism.
- Keep the protected default ADD hook `Unsupported` for a backend that has not implemented ADD. The common fake must override the hook only to record a deterministic accepted submission, configurable pre-acceptance allocation/runtime/internal failures, and completion/retained-failure behavior.
- Add fake-backed observable coverage for every validation and precedence category: unknown/malformed specs; mismatched leaf and quantization; matching excluded leaves and matching recognized non-`NONE`; device and owner identity errors; rank, zero-dimension, broadcast incompatibility, wrong output shape, view, offset/stride/size, and checked-overflow errors; forbidden aliasing; allocation failure; backend runtime failure; internal failure; and sequence exhaustion.
- Add accepted-request coverage for all 21 numeric leaves, positive tokens, equal and broadcast shapes, `[1,1]`, transformed leading views, read/read overlap, exact lhs-only/rhs-only/all-three in-place aliasing, output/source preservation, and no access to padding. Shared cases must verify asynchronous ordering, repeated waits, and retained failures without depending on arithmetic results.
- Add lifetime tests that destroy temporary/derived view objects immediately after `add`, verify all three caller owners and stable handles remain alive through completion, and verify exact alias deduplication with one owner appearing in multiple operands. Rejection tests must prove no output, submission, sequence, or lifetime-registration effect.

## Non-goals

- Do not implement scalar integer or floating arithmetic, an independent scalar oracle, numeric codecs, backend kernels, real device execution, or backend-native/emulated dtype paths.
- Do not implement TTNN storage expansion, backend capability systems, generic fallback infrastructure, a CPU `Device`, a CPU tensor, a CPU queue, or allocation/return of operands or results.
- Do not expose public broadcast views, public zero strides, mixed-type promotion, caller-visible casts, quantization support, options, or support/capability queries.
- Do not change `copy`, `mul`, `silu`, `linear`, `rmsnorm`, `sdpa`, or unrelated OID migration behavior except where the already-completed prerequisite's common boundary is required to keep ADD's facade correct.
- Do not add arithmetic or backend completeness claims to the deterministic fakes or shared validation helpers; positive fake tokens prove only common acceptance and submission policy.

## Acceptance criteria

- [ ] The public API has exactly the three-view `noexcept` ADD signature, no ADD options/support query, and a protected default hook that returns `OidError::Unsupported` without submitting.
- [ ] Fake-backed `iom_tests` observe every specified error category and precedence. Mismatched/malformed/device/shape/view/alias requests return `InvalidArgument`; checked arithmetic and exhausted sequence return `Overflow`; matching excluded/non-`NONE` specs return `Unsupported` only after recognized equality; deterministic pre-acceptance allocation, backend runtime, and unclassified failures return `ResourceExhausted`, `DeviceError`, and `InternalError` respectively.
- [ ] Every rejection leaves output sentinels, submission records, sequence allocation, token acceptance, and owner-registration state unchanged.
- [ ] Each of the 21 numeric `NONE` leaves reaches the fake hook and returns a positive token. `BOOL`, `F8_E8M0`, and matching recognized non-`NONE` requests do not reach it.
- [ ] Broadcast tests prove exact right-aligned results for ranks 2, 3, and 6, `[1,1]`, opposite-direction singleton axes, final tiled-axis tails, and transformed leading views; incompatible inputs and every wrong output shape are rejected before effects.
- [ ] Aliasing tests permit arbitrary lhs/rhs overlap and exact same-owner in-place mappings only, reject every other input/output relation including disjoint same-owner windows and broadcast aliases, and confirm caller-owned storage/handles are never replaced or relocated.
- [ ] Temporary-view lifetime tests prove metadata is snapshotted, all three owners are retained until terminal completion, exact aliases are deduplicated, and repeat waits/retained failures do not double-release an owner.
- [ ] The shared conformance helper exercises the common policy and the CPU conformance driver invokes it without vendor types or arithmetic assumptions. The focused suites are `iom_tests` and `iom_backend_conformance_cpu_tests`.

## Verification

- `iom_tests` — required focused fake-backed validation, precedence, token-effect, alias, snapshot, allocation, and lifetime suite; not run while generating this frozen specification.
- `iom_backend_conformance_cpu_tests` — required CPU shared-conformance execution of the common ADD policy; not run while generating this frozen specification.
