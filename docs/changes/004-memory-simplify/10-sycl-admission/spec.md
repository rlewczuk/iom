# Adopt bounded admission on SYCL

**Order:** 10
**Priority:** P1 — SYCL needs the same FIFO and lifetime guarantees over its distinct queue, metadata, and host-fallback paths.
**Blocked by:** `06-fixed-queue-resources`, `07-binary-workspace-cutover`, `08-common-fifo-admission`
**Source:** `docs/changes/004-memory-simplify/spec.md`

## Outcome

SYCL uses the common bounded-admission protocol for queued copies and binaries. Accepted work is snapshot-safe and FIFO ordered, parked work has no native effect, and only the FIFO head with a proven credit and fixed resources reaches a SYCL queue. Completion retires resources autonomously while preserving each token's result, and device teardown drains or quarantines every accepted request without releasing memory still possibly used by the runtime.

## Scope

- Integrate task-08 admission into `SyclQueue` and the SYCL device queue state. A positive token is returned only after validation, immutable request/view snapshots, owner/tensor/workspace registrations and exclusivity leases, sequence reservation, and FIFO append complete. This is before SYCL queue submission, metadata acquisition or upload, workspace device copies, output mutation, or any other native effect.
- Apply one immutable, backend-neutral `QueueConfig::max_in_flight_per_queue` value (`C`, default 16 and never zero) to every queue on a Device. Limit live queues to four; accepted excess requests park in host state without a credit, metadata slot, completion resource, workspace device effect, or native allocation call.
- Use the fixed task-06 metadata partition and completion/fence resources. Dispatch only the FIFO head when a safe credit, completion resource, and required metadata slot are available. No operation, including no-op or no-metadata work, may bypass a parked head.
- Retire completed SYCL work autonomously without requiring `wait`, dispatching the oldest parked request as credits become safe. Keep token outcomes separate from reusable event/fence generations, metadata slots, credits, workspace leases, and host upload backing so repeated waits observe the original result after resource reuse.
- Preserve task-07 raw workspace behavior for the SYCL binary fallback. The scalar host binary algorithm uses three aligned slices of the borrowed workspace for padded lhs, rhs, and output device staging; host-USM staging remains separate and alive until all asynchronous readers and writers finish.
- Make queue destruction close admission, drain executing and parked requests to terminal outcomes in FIFO order, transfer unresolved leases to Device-scope quarantine, and retain queue partition/count reservations and backing memory as needed.
- Add focused SYCL smoke/conformance and configured-coexistence coverage for admission, fixed-resource reuse, workspace lifetime, failure, teardown, isolation, and unchanged numerical/storage behavior.

## Requirements

- `C` is immutable for the Device, must be at least one, and applies uniformly to every SYCL queue. A fifth live `DeviceOps` queue fails with `std::bad_alloc` before starting another native queue/worker; failed construction rolls back its queue-count and metadata-partition reservation. A safely drained queue returns both reservations, while an unresolved queue retains them until covering proof.
- Admission must complete all host-side snapshot, registration, lifetime, exclusivity, sequence, and FIFO-node transactions before returning a positive token. Any preacceptance allocation or registration failure returns the established synchronous resource/overflow/invalid-input error and rolls back every partial reservation with no native effect or output mutation.
- Parked requests retain immutable snapshots, token outcome state, owner registrations, and workspace leases, but hold no native credit, fixed metadata slot, completion event/fence, host upload allocation, device workspace effect, or SYCL allocation. Host parking is not bounded by an additional configured backlog count.
- Autonomous completion processing must prove completion and all host/device accesses before reusing a credit, event/fence generation, metadata slot, host upload backing, workspace range, or payload reference. It must then dispatch only the oldest parked request; an explicit wait is not required for progress. There is no cross-queue ordering and no global synchronization or mutex on normal paths.
- Retain successful and failed terminal outcomes independently of reusable completion objects. Failures found after acceptance remain repeatable terminal failures observed by `wait`; they are never converted to synchronous negative OIDs. No-op, inline, and no-metadata operations still consume FIFO positions and cannot overtake a parked request, but do not acquire a dummy metadata slot.
- On uncertain SYCL queue/event completion, quarantine at Device scope the credit, fence/event generation, metadata slot or partition, host upload backing, workspace lease, and all payload/owner references that may still be read or written. A failed callback, failed event query, or missing callback is never completion proof. Reclaim quarantined resources only after a successful covering proof; otherwise retain them through teardown rather than freeing or reusing them.
- A queue destructor must first close admission, finish host preparation, and drain every accepted request, including parked requests, to a terminal result in FIFO order. It must not silently cancel, discard, or omit an accepted token. Unresolved native leases move to Device-owned quarantine before queue resources or host descriptors are released; metadata backing and payload/workspace storage outlive every possible native access.
- Use task-06 fixed metadata and fence/event resources prepared at queue/device setup. Submission, parking, dispatch, retirement, and waits must not grow, replace, resize, lazily allocate, or native-free metadata or completion resources. Device-wide metadata partitions are disjoint, and safely proven partitions and slots can be reused without changing earlier token results.
- Preserve task-07 workspace validation and leasing for the four binary facades. A positive requirement with an empty `RawWorkspaceView{}` is invalid; invalid capacity, alignment, range, owner/device identity, liveness, operand/output overlap, and missing workspace fail before acceptance. A leased workspace range remains exclusive while parked and through completion; overlap with another accepted lease is synchronous resource exhaustion. Zero-byte requirements accept the empty view and report alignment 1.
- For SYCL binary fallback, retain the existing host scalar implementation and `binary_view_staging_bytes` padded-plane semantics. Replace the three per-operation `sycl::malloc_device`/`sycl::free` pairs with non-overlapping 32-byte-aligned workspace slices at offsets `0`, `align_up(lhs_bytes, 32)`, and `align_up(lhs_bytes, 32) + align_up(rhs_bytes, 32)`, requiring the checked capacity through `out_bytes`. Never treat a device-arena slice as a host span or use shared USM for the arena.
- Keep `lhs_stage`, `rhs_stage`, and `out_stage` host-USM allocations separate from device workspace and retain them through all asynchronous reads and writes. Host-transfer workspace, staging-pool removal, and the dedicated serialized transfer queue are owned by task 11 and are not changed here.
- Do not add a direct SYCL binary device kernel, a shared-USM arena, cross-queue ordering, global synchronization/mutex, hidden allocator lock, or any resource/arena growth. SDK-internal SYCL event allocations are outside the IOM-native-memory guarantee; if observed, instrumentation must report them separately and must not claim that they are absent.
- Preserve owner identity, temporary transformed-view snapshots, different broadcast mappings, exact alias rules, numeric results, untouched planes, and tile padding. Device isolation is required: credits, queue caps, metadata partitions, workspaces, outcomes, and quarantine on one Device must not affect another Device.

## Non-goals

- Implementing a direct SYCL binary kernel or changing the host scalar algorithm, dtype support, broadcast rules, tile representation, numerical semantics, or padding policy.
- Introducing a SYCL-specific public operation/direction enum, duplicate workspace query APIs, a second allocator implementation, shared-USM storage, or a compatibility factory overload.
- Bounding accepted host backlog beyond native resources, adding cross-queue ordering, global locks/synchronization, paging/compaction/eviction, or allowing resource growth after setup.
- Eliminating host allocations or claiming to eliminate SDK-internal SYCL event/runtime allocations; only IOM-native device allocations and their accounting are covered.
- Changing CPU, CUDA, ROCm, or TTNN behavior except for the shared API/caller migration required to keep the configured coexistence build source-compatible.
- Migrating synchronous host-transfer APIs, deleting `src/sycl/staging_pool.*`, or asserting host-transfer no-churn; those belong to task 11.

## Acceptance criteria

- [ ] With `C=1` and `C=17`, hold the configured in-flight completions, submit at least two additional valid SYCL operations, and observe prompt positive tokens with no parked SYCL queue submission, metadata acquisition/upload, workspace device copy, output mutation, or IOM-native allocation call. Release credits one at a time and observe autonomous FIFO dispatch without `wait` or a new submission.
- [ ] Verify no-op and no-metadata SYCL requests follow the same FIFO, do not acquire dummy metadata, and cannot pass an earlier parked request; repeated waits on successful, failed, and parked tokens return each token's original result after fixed resources are reused.
- [ ] Verify fixed task-06 metadata slots and completion/fence generations are reused without growth or replacement, including success/failure cycles and metadata/resource saturation. Confirm descriptor snapshots for temporary transformed views and different binary broadcast mappings are not overwritten by later submissions.
- [ ] Verify a raw workspace remains retained and exclusively leased while its request is parked; validate missing, undersized, misaligned, foreign, overlapping, and operand/output-overlapping views, plus zero-byte empty-workspace paths. Confirm SYCL binary slices preserve padded storage, untouched planes, and unchanged scalar numerical results.
- [ ] Force or inject post-acceptance SYCL submission, event, callback, and completion uncertainty. Confirm terminal failures remain repeatable, all uncertain credit/fence/metadata/host-upload/workspace/payload leases are quarantined at Device scope, and only a later successful covering proof permits safe reclamation.
- [ ] Destroy a SYCL queue with executing and parked requests and verify every accepted token drains in FIFO order to a terminal result, with no silent cancellation or discarded token. Verify unresolved leases survive queue destruction and prevent premature partition, workspace, payload, or metadata reuse.
- [ ] Create four live queues with disjoint metadata partitions, reject the fifth, roll back failed queue construction, and safely reuse a partition only after proof. Repeat the scenarios with two independent Devices and confirm quotas, results, and quarantine are isolated.
- [ ] Run SYCL queued-copy and binary conformance against the CPU reference and confirm unchanged logical values, bit patterns, untouched planes, and tile padding, including temporary views and different broadcasts. Enabled SYCL tests fail rather than skip when no eligible accelerator is available.
- [ ] Confirm native allocation instrumentation distinguishes the two setup arena reservations from zero post-setup IOM-native allocation/free calls across queued SYCL operations; host-transfer allocation accounting remains a task-11 gate. Report SDK-internal SYCL event allocations separately rather than counting them as absent.
