Implement skill `spec-run-all` and command `spec-run-all <task-name>` that will execute all subtasks of a given task in `docs/changes/<task-name>`:
* it should scan all subdirectories containing `spec.md` (`<subtask-name>/spec.md` in `docs/changes/<task-name>`) and look `task.md` in the same directory;
* it `task.md` file exists and contains `**Status:** done` line, then this task is alread executed and should be omitted
* tasks should be performed in alphabetical order (as directory names), but be sure to maintain dependencies; each `spec.md` contains `**Blocked by:**` line, it has `None` or list of dependencies; be sure to take dependencies into account when maintaining task queue
* tasks should be run in subagents, using `@implementer` model alias, up to 5 subagents may run in parallel at any given time; each subagent should use `spec-run-task` skill to implement given task (see `spec-run-task` command for reference on how to use skill)
* if given task is blocked by something (other than missing dependency), please report it at the end of run along with explanation why it was blocked
* mechanical parts of above logic should be implemented as python3 scripts, not as LLM instructions; this applies to: scanning and listing subtasks and their current statuses, sorting tasks; (note: dependencies may be a bit harder to parse using script -- see examples -- but you can extract this single `**Blocked by:**` using script and then parse it in LLM)
* see `docs/changes/01-review` for an example of task directory to be executed; in this example first task is finished and remaining ones are not implemented at all; note that this is a big set of tasks, you probably don't need to read them all, all needed information will be in first 10 lines of `spec.md` and first 5 lines of `task.md`;
