# Pin the destroy-while-queued storage-lifetime guarantee with always-run CPU and protocol regressions

**Order:** 69
**Priority:** P0 — always-run regression enforcement of the P0 storage-lifetime guarantee (49-ST-003's own CPU acceptance criterion was never implemented); the guarantee protects the most lifetime-critical machinery the 55/61/62 wave just restructured, and without these tests a regression to unconditional early free passes the entire CPU-only suite.
**Blocked by:** `62-AR-002-share-release-quarantine-protocol`
**Source:** `docs/changes/0001-tensor-view/review.md` — `NT-003`
**Review severity:** medium
**Review verification:** verified, confidence 90

## Outcome

The invariant 49-ST-003 built into every backend — a tensor destroyed while queued work references its storage is fenced or quarantined before free, and queue teardown defers a failed free to device destruction — is enforced by regressions that run on every CPU-only `ctest` invocation, not only on machines with accelerators attached. The always-run `iom_cpu_tests` suite gains the poisoning/recycling destruction cases 49-ST-003 specified but never received: submit a copy, destroy the source and/or destination before `wait`, prove the freed address is recycled only through the destructor's release path and that recycling cannot corrupt the completed copy. The always-run `iom_tests` suite gains direct unit coverage of the shared lifetime machinery: the `detail::release_or_quarantine` branch matrix (release only when every snapshot fence succeeds; quarantine — drained exactly once at teardown — on invalidated, failed, or throwing fences), the `register_registry_entries` two-phase rollback on second-entry failure, and the documented `try_release_entry`-vs-completion race tolerance. The SYCL destroy-before-wait mirror is the blocker-delivered 55-ST-001 regression set and is verified on SYCL hardware through `.agents/skills/remote-development`, not re-specified here.

This task is test-only. It redesigns nothing in the registry, the shared protocol helper, or any destructor.

## Current failure

`docs/changes/0001-tensor-view/49-ST-003-fence-tensor-destruction/spec.md` acceptance criterion 1 — "A CPU poisoning/recycling allocator test submits a copy, destroys the source or destination tensor without waiting, and proves no freed address is reused until the queued operation is complete; a failed fence quarantines instead of freeing" — was never implemented, and no test anywhere in `test/` destroys an owner before waiting (the shared conformance harness waits every token first). Consequences at the reviewed commit, all still true after the 55/57/58/61/62 remediation wave except where noted:

- The always-run CPU suite cannot detect a regression to unconditional early free: `~CpuTensor`'s snapshot/fence/quarantine flow (`src/cpu/device.cpp:493-553` pre-62; the `detail::release_or_quarantine` call post-62) executes only its trivial paths under test, and the queue-teardown → invalidated-entry → quarantine flow is covered only incidentally on accelerator hardware (the CUDA/ROCm transactional-failure canary, TTNN deferred-lifetime cases).
- The unit gaps in the lifetime machinery named by the review remain open after 57-ST-003 and 61-AR-003 land their own narrower cases: `register_registry_entries`' two-phase rollback on second-entry failure (57-ST-003's non-goals explicitly assign this case to NT-003 — 57 covers only `register_entry`'s internal single-entry rollback), and the `try_release_entry`-vs-completion race documented at `include/iom/outstanding_work_registry.hpp:281-282` ("Missing IDs are expected when a tensor destructor wins the race with normal queue completion") has no direct test.
- On SYCL the destroy-before-wait scenario could not pass before 55-ST-001; post-55 the mirror exists (`ReusingSyclAllocator` "SYCL tensor destruction fences queued work", "SYCL submission remains transactional across post-enqueue failures", "SYCL queue destruction fences pending copies") and must keep passing through the post-62 shared helper.

Post-blocker refinement (why the CPU case shape changes): 61-AR-003 opts CPU out of registration — `CpuQueue::execute` runs the copy to completion on the submitting thread before publication, so there is never in-flight CPU work and the pre-61 queue-teardown invalidation path disappears from CPU. On post-61 CPU the observable destroy-while-queued contract is: destroying an operand between `copy()` returning and `wait(token)` is legal, frees each address exactly once and promptly (no deferral), and a recycled address cannot corrupt the completed copy. The invalidation → quarantine → deferred-free-until-device-destruction half of 49-ST-003's criterion 1 and criterion 5 is pinned (a) at the protocol level by the `release_or_quarantine` unit matrix driven through `invalidate_entries_for_queue`, and (b) end-to-end on the registering backends by the existing CUDA/ROCm canary block (`test/cuda/test_cuda_conformance.cpp:429-516`: failed addresses never reused, `free_count() == 0` before teardown, `== 2` only after `device.reset()`), the ROCm twins, TTNN's deferred-lifetime cases, and 55-ST-001's SYCL cases.

## Requirements

1. **Recycling allocator fixture.** Add `RecyclingAllocator` to `test/cpu/test_cpu.cpp` modeled on `ReusingCudaAllocator`: `alloc(size)` returns an exact-size slot from a free list when one exists, otherwise allocates a 32-byte-aligned host block; `free(buffer)` rejects unknown addresses (doctest `REQUIRE_MESSAGE`, matching `RecordingAllocator`), pushes `{buffer, size}` onto the free list, and appends a `free` event to a public `std::vector<Event>` log shaped like `RecordingAllocator::Event`; `free_count()` reports the free-list length; `release_free()` releases recycled blocks to the OS and clears the list. Every `alloc`/`free` appends an event so tests can assert exactly-once frees and their ordering.
2. **Destroy-before-wait recycling case** ("CPU tensor destruction before wait fences queued work under address recycling", exact name free but the `-tc` glob `*destruction before wait*` must match it):
   - Fixture: `RecyclingAllocator`-backed CPU device, spec `make_spec({2, 3, 16, 16}, iom::DataType::U8)`, one queue.
   - Source-role variant: seed the source with `encoded_host(view, salt)`, take `token = queue->copy(source->view(), destination->view())`, record `source->view().native_handle()`, destroy the source via `source.reset()` **before** `wait`, create a fresh same-spec tensor, and require the fresh handle to equal the destroyed handle (deterministic recycle — proves the destructor released promptly and exactly once, i.e. took the release branch rather than deferring). Fill the fresh tensor with a poison byte distinct from the copy data (`fill_storage(*fresh, std::byte{0xC5})`), then `wait(token)`: it succeeds and is idempotent on a second call; `destination`'s `copy_to_host` equals the source's seed pattern exactly; the fresh tensor reads back pure poison.
   - Destination-role variant: same flow destroying `destination` before `wait`; the recycled tensor holds pure poison and the source still reads its seed.
   - Both-operands variant: destroy both, create two fresh tensors (two distinct recycled addresses), poison both, wait, verify both patterns.
   - Free accounting in every variant: the event log shows exactly one `free` per destroyed tensor, recorded at destruction (before `wait`); no further `free` for those addresses occurs at `wait`, at queue destruction, or at device teardown; the device destructor leaves no recycled blocks (`release_free()` then `free_count() == 0`).
3. **Queue-teardown case** ("CPU queue destruction with unwaited tokens keeps frees exactly once", glob `*queue destruction with unwaited tokens*`): on a `RecyclingAllocator` device, submit two queued copies and capture both tokens, then `queue.reset()` without waiting. Destroy both tensors afterward: exactly-once frees, no double free, and the event count is stable through device destruction (post-61 CPU registers nothing, so no quarantine entry may appear and the `~CpuDevice` drain — `src/cpu/device.cpp:445-447` — frees nothing). A new queue from the same device then completes one more copy+wait with correct contents, proving the drained device remains usable.
4. **`release_or_quarantine` branch matrix** ("release_or_quarantine releases storage only when every snapshot fence succeeds"): test-local `OutstandingWorkRegistry`, a test address, a `detail::Quarantine`, a counting test-local `CleanupAction` subclass (or `AllocatorCleanupAction` over a counting allocator), and recording `make_cleanup`/`release` lambdas. Cover, each with explicit assertions:
   - no entries at the address → `release` called once, `make_cleanup` never (the post-61 always-empty-CPU-registry shape);
   - one `Live` entry whose fence returns `FenceResult::success()` → entries removed (`snapshot_for` empty afterwards), `release` called once, quarantine empty;
   - two `Live` entries at one address, both succeed → both removed, one release;
   - an entry invalidated through `invalidate_entries_for_queue(queue_id)` (real invalidation: `EntryState::Invalidated`, failed fence) → `release` **not** called, `make_cleanup` exactly once, all snapshot IDs removed, and `drain()` runs the cleanup action exactly once with a second `drain()` a no-op;
   - a fence returning `FenceResult::failed(...)` and a fence throwing — each quarantines identically;
   - mixed: one succeeding `Live` entry plus one `Invalidated` entry → the unsafe classification wins: no release, one cleanup, all entries removed, remaining `Live` fences still invoked (success does not short-circuit the scan).
5. **`register_registry_entries` two-phase rollback** ("register_registry_entries rolls back the source entry when the destination registration throws"): with a local `EntryId next_entry_id = 5`, a captureless counting fence, and a pre-registered destination id (`registry.register_entry(6, destination_address, 1, 1, fence)`), `register_registry_entries(registry, next_entry_id, 1, 1, source_address, destination_address, fence)` throws `std::invalid_argument` (duplicate destination id); assert the source entry was rolled back: `snapshot_for(source_address)` empty, `try_release_entry(5)` false, fence invocation count unchanged, and the destination entry untouched. Then `remove_entry_if_present(6, destination_address)`, reset `next_entry_id = 5`, re-run the identical call: it succeeds, `snapshot_for` shows exactly one entry per address, and both ids release. Also pin the pre-mutation guard: `next_entry_id = std::numeric_limits<EntryId>::max()` makes the same call throw `std::overflow_error` with the registry unchanged.
6. **`try_release_entry`-vs-completion race** ("registry release tolerates the destructor-versus-completion race"): both directions of the documented tolerance, on separate addresses:
   - completion wins: register id X at A → `snapshot_for(A)` (one entry, fence copy held) → `try_release_entry(X)` returns true → the held snapshot's fence is still invocable exactly once (the destructor's snapshot copy stays valid) → `remove_entry_if_present(X, A)` is a no-throw no-op → `try_release_entry(X)` false → `snapshot_for(A)` empty;
   - destructor wins: register id Y at B → snapshot → invoke the snapshot fence once → `remove_entry_if_present(Y, B)` → `try_release_entry(Y)` false (the completer tolerates the missing id) → `snapshot_for(B)` empty.
   The total fence invocation count is exactly one per entry; no call throws.
7. **Unit-gap triage (do not re-add cases owned by blockers):** the `invalidate_entries_for_queue` registry-level unit case (queue-scoped scan isolation, invalidated state, failed fence, retained address index) is 61-AR-003 requirement 10's delivered case; this task consumes invalidation as setup inside requirement 4 instead of duplicating it. The `register_entry` internal-rollback fault sweep is 57-ST-003's delivered case; requirement 5 covers the different, higher-level `register_registry_entries` rollback 57 explicitly deferred to NT-003. The SYCL destroy-before-wait, transactional-submission, and queue-destruction cases are 55-ST-001 acceptance criteria 1, 2, and 4's delivered cases; this task runs them (Verification) and adds none.
8. **Test-only change:** no edits to `include/iom/**`, `src/**`, or `CMakeLists.txt`; no new test target; both new-case groups run in the unconditionally registered `iom_tests`/`iom_cpu_tests` targets so a CPU-only `ctest` enforces the invariant. No production fault-injection seam is added (57-ST-003's rejected alternative stays rejected — requirement 5's deterministic duplicate-id trigger needs no allocation faulting).

- [ ] The CPU queue-teardown case destroys a queue holding unwaited tokens and proves exactly-once frees, no leak, no quarantine effect, and a still-usable device.
- [ ] `iom_tests` contains the `release_or_quarantine` matrix: the empty-snapshot, all-success, invalidated-via-`invalidate_entries_for_queue`, fence-failed, fence-threw, and mixed cases each assert the release-vs-quarantine decision, removal of all snapshot IDs on both branches, and exactly-once `drain()` on the quarantine branch.
- [ ] `iom_tests` contains the `register_registry_entries` two-phase rollback case (deterministic duplicate-destination-id trigger) asserting pre-call state (`snapshot_for` empty, `try_release_entry` false, fence count unchanged), successful identical re-registration, and the `std::overflow_error` pre-mutation rejection.
- [ ] `iom_tests` contains the race-tolerance case in both directions with exactly-once fence invocation and no throw from the losing side's operations.
- [ ] Discriminator — protocol: disabling the unsafe classification in `release_or_quarantine` (treating `Invalidated`/failed fences as safe) makes the invalidated, fence-failed, fence-threw, and mixed cases fail (release called, quarantine empty); restoring it makes them pass — the always-run form of the review's "fails when the snapshot/quarantine branch is disabled".

- [ ] Discriminator — CPU end-to-end: making `~CpuTensor` skip its release (or defer every free) breaks the recycled-handle equality and free-event assertions; a double free trips the fixture's unknown-address/duplicate-free accounting.
- [ ] On SYCL hardware, 55-ST-001's three lifetime regressions pass unchanged through the post-62 shared helper, with no new SYCL case added by this task.
