# Converge SYCL copy and staging architecture onto the shared backend machinery

**Order:** 60
**Priority:** P1 — high-confidence architecture convergence (review severity high, verified, confidence 92) that lands only after the SYCL correctness/lifetime prerequisites; it deletes the last pre-remediation-generation backend so every future queue/copy fix stays a single edit
**Blocked by:** `55-ST-001-harden-sycl-queue-lifetimes`, `59-ST-005-stage-sycl-host-transfers`
**Source:** `docs/changes/0001-tensor-view/review.md` — `AR-001`
**Review severity:** high
**Review verification:** verified, confidence 92

## Outcome

The SYCL backend consumes the same cross-backend mechanisms the other four backends use. Its copy kernels call the shared word-oriented device functions from `src/shared/standard_tiled_copy.inl` through the existing `IOM_GPU_*` macro seam (the per-bit `sycl::atomic_ref` helpers are deleted); a queued device-to-device copy is one metadata-driven kernel launch over destination storage words instead of one launch per plane pair fed by per-submission host vectors; synchronous host transfers run on pooled `sycl::malloc_device` staging with a pinned `sycl::malloc_host` mirror and one device-owned in-order transfer queue instead of per-call `malloc_shared`/`sycl::free` and a per-call queue. SYCL-specific behavior that is legitimately its own — GPU/accelerator device enumeration, the USM pointer-type compatibility check, in-order queue construction, `parallel_for` lambda launch syntax, and the 55-ST-001 registry/lifetime mechanics built on `SyclFenceState` plus the Task's shared_ptr alias — is preserved unchanged.

## Current failure

Invariant (review AR-001): one semantic operation has one implementation — queue staging/completion/drain mechanics, single-launch word-oriented copy, pooled staging and transfer queues, and fenced destruction are backend-neutral contracts behind AGENTS.md's clean common/backend boundary.

The SYCL backend re-implements the pre-remediation generation of every data-movement pattern. `src/sycl/copy.cpp` duplicates machinery that exists exactly once elsewhere:

1. `device_write_bits`/`device_read_bits` (`src/sycl/copy.cpp:88-129`) are the per-bit `sycl::atomic_ref` fetch_or/fetch_and writers that 46-PF-006 banned from CUDA/ROCm; multiple work items update one destination word, so every sub-byte copy serializes per bit on hardware.
2. `view_planes`/`plane_pairs`/`PlanePair` (`src/sycl/copy.cpp:29-71`) materialize an O(plane-count) host vector per submission, and both data-movement paths launch once per plane: `SyclQueue::copy`'s submission lambda (`src/sycl/copy.cpp:301-331`) submits one kernel per plane pair, exactly the shape 42-PF-002 deleted from CUDA/ROCm.
3. `synchronous_transfer` (`src/sycl/copy.cpp:197-245`) constructs a `sycl::queue` and calls `sycl::malloc_shared`/`sycl::free` on every call, re-implements the staging-size arithmetic that `iom::gpu_algorithm::compute_staging_size` already owns (with a divergent message), and memsets the full staging allocation on downloads where 43-PF-003 converged CUDA/ROCm to tail-word-only zeroing. 59-ST-005 fixes only its non-USM `queue::memcpy` operands; the per-call lifecycle remains.
4. The SYCL backend participates in none of the shared copy architecture: `grep` for `StagedWorker`, `OutstandingWorkRegistry`, `Quarantine` under `src/sycl` returned zero matches before 55-ST-001; 55-ST-001 brings the queue mechanics and tensor-destruction fencing to the shared generation, but the data-movement and host-transfer layers remain a sixth divergent copy of every cross-backend pattern.

Impact: five backends implement one contract at three architecture generations; every future copy-path fix must be reapplied in a sixth place or silently skipped, and SYCL hardware behavior (throughput, teardown cleanliness) diverges observably.

### `SyclFenceState` extension and pinned slot-release mechanism

The metadata slot is released by exactly one mechanism: `SyclFenceState::release_metadata_slot() noexcept`. The method is idempotent and follows the exact pinned implementation. The body is, line for line:

```cpp
void SyclFenceState::release_metadata_slot() noexcept {
    SyclMetadataSlotPool* pool = nullptr;
    std::size_t slot = 0;
    {
        std::lock_guard<std::mutex> lock(mu_);
        pool = pool_;
        slot = slot_;
        pool_ = nullptr;
        slot_ = 0;
    }
    if (pool != nullptr) {
        pool->release(slot);
    }
}
```

Under `mu_` the method captures the current `pool_` and `slot_` into local stack variables, clears both members to the empty state (`nullptr` and `0`), and unlocks. It then calls `pool->release(slot)` outside the lock if and only if the captured `pool` is non-null. The two members are never read after they are cleared; every observable consumer (registry snapshot, `complete_task`, the destructor, the worker thread) goes through `release_metadata_slot()` for any slot-release effect.

This pins the slot release to a single, named operation. The post-condition is invariant: after `release_metadata_slot()` returns, both `pool_` and `slot_` are the empty state. Concurrent calls are safe by construction: the under-lock snapshot-and-clear is atomic with respect to any other thread that also enters the method, and the second caller observes `pool_ == nullptr` and `slot_ == 0` and exits without invoking `pool->release` a second time. Pool release is the only external operation `SyclFenceState` performs; `release_metadata_slot()` does not mutate any begin-publish, end-publish, drain, queue, or other backend lifecycle observable.

`src/sycl` audits must find exactly one text occurrence of `->release(slot)` across the entire file, and that one occurrence is the line `pool->release(slot);` inside `release_metadata_slot()`. The implementation never spells `pool_->release(slot_)`, because the `pool` local is the cleared copy — the members have already been emptied under the lock.

The fence-cleanup path is pinned and runs in three steps, in order, by `fence_destroy(void*)`:

1. Call `state->result()` to force-finalize the cached `FenceResult`. This is the 55-ST-001 idempotent path; the cached value (combined wait result + retained failure) is observed by `complete_task` and by every snapshot that races ahead of entry removal.
2. Under `mu_`, reset `event_ = std::nullopt` so that no future observer ever sees the released slot's metadata or a stale event after release.
3. Call `state->release_metadata_slot()`. This is the only path that produces a slot release on the success/drain path.

The destructor `~SyclFenceState()` calls `release_metadata_slot()` only as a fallback for pre-publication rollback — the case where `execute` rolled back before publishing the task (the 55-ST-001 `submitted_any == false` rollback branch where the shared_ptr is the last reference). The destructor never observes a published task: if the task was published, `fence_destroy` already ran, which already called `release_metadata_slot()`, and the method's idempotence makes the destructor's call a no-op. The single cleanup mechanism is therefore `release_metadata_slot()`; the destructor is just an idempotent second-entry point for the abortive path.

`complete_task` continues to read `state->result()` through the `SequenceOutcome`'s shared_ptr to drive `complete(sequence, exception_ptr)`. Because `fence_destroy` already ran (it runs before `complete` per `StagedWorker::process` order: `fence_complete` → `fence_destroy` → `complete`), the cached result is the post-release observation point; the snapshot-safe invariant from 55-ST-001 (snapshot invokes cached result after event reset) is preserved. The state-owned slot release in `release_metadata_slot()` is observable to neither snapshots nor `complete_task`: it runs on the worker thread after the cached result has been consumed, and the only data the registry/snapshot/complete path ever needed — the `FenceResult` and the `retained_failure` — live inside the state, not in the metadata slot. Pool pointer and slot index are private state-of-the-state, never observed by registry, by `complete_task`, or by a destructor snapshot.

### Pre-publication rollback safety

When `execute` rolls back a pre-enqueue failure in the 55-ST-001 `submitted_any == false` branch and the metadata `queue_.memcpy` has already enqueued into `queue_`, the rollback path drains `queue_` before resetting `task.fence = nullptr` and `task.state.reset()`. The drain is `queue_.wait_and_throw()` with the wait-and-throw failure swallowed: this guarantees the metadata `queue_.memcpy` has retired before the last shared_ptr is released, so the `~SyclFenceState()` fallback release observes no in-flight metadata copy. Once `queue_` is drained, the shared_ptr reset releases the state; the destructor's fallback `release_metadata_slot()` returns the slot to the pool. The fallback release therefore never races a live `queue_.memcpy`. Without the drain, the in-flight metadata copy could read or write the slot's device mirror after the pool had reused the slot for a later task — exactly the slot-reuse-safety invariant 42-PF-002's design gives us via fence-released slots. The drain keeps that invariant intact on the pre-publication rollback path.

### State owners

`SyclFenceState` is reference-counted by exactly four `std::shared_ptr<SyclFenceState>` copies at the moment between `execute` step (e) (the `SequenceOutcome` insertion) and `complete_task`:

1. The Task's `state` member (carried into the worker's `tasks_` list node by `PublishPolicy::Splice`).
2. The first registry `Fence` (source entry's closure), which captures exactly one shared_ptr — the retained failure is stored inside the state, never as a separate Fence capture.
3. The second registry `Fence` (destination entry's closure), which also captures exactly one shared_ptr.
4. The `SequenceOutcome`'s `state` member.

There is no fifth copy. The Task's shared_ptr is dropped when the staged node is consumed by `PublishPolicy::Splice` (the Task is move-constructed into `tasks_`; the `tasks_` list node keeps the new shared_ptr as the worker's reference). The two registry `Fence` copies are dropped in `complete_task` after `try_release_entry` succeeds, or by the registry's normal invalidation path. The `SequenceOutcome`'s shared_ptr is dropped when `complete_task` erases the entry from `outcomes_`. The Task's shared_ptr in `tasks_` is dropped after the worker's `fence_complete`/`fence_destroy`/`complete` sequence returns. The `~SyclFenceState()` fallback runs when the last of these four is dropped, and at that point `release_metadata_slot()` is a no-op (already cleared) or runs once (pre-publication path). The metadata slot is released exactly once per task, by the single named mechanism, regardless of which shared_ptr is the last to drop.

### Pooled host-transfer path

- `StagingSlotPool` semantics mirror `iom::cuda_detail::StagingSlotPool`: `kMaxStagingBytes = 8 GiB` (larger requests throw `std::invalid_argument` before touching state), `kMaxSlotCount = 16`, blocking `acquire(required_bytes)`, geometric growth, replacement allocation before freeing the old slot, first-allocation and grow failures restoring counts exactly, `Lease::poison()` destroying rather than recycling a slot, `destroy() noexcept` freeing all idle slots, and the test seams `idle_count_for_testing()`, `allocation_count_for_testing()`, `fail_next_allocation_for_testing()`. Each slot holds a `sycl::malloc_device` staging buffer and a `sycl::malloc_host` mirror of equal capacity.
- `synchronous_transfer` (reached through `region_from_host`/`region_to_host`) computes `staging_nbytes = gpu_algorithm::compute_staging_size(view.spec().logical_nbytes())` (the shared diagnostic replaces the SYCL-local message), acquires one lease on the device-owned in-order `transfer_queue_`, and follows these exact orderings, which differ by direction:

  **from_host:**
  1. `std::memcpy(lease.host_mirror(), source.data(), logical_nbytes)`.
  2. `transfer_queue.memcpy(lease.device_staging(), lease.host_mirror(), logical_nbytes)` (in-order, USM→USM).
  3. Per-plane scatter wrappers (one `parallel_for` per plane, in-order).
  4. `transfer_queue.wait_and_throw()` — the single wait that synchronizes all of the in-order work above.
  5. Return.

  **to_host:**
  1. Compute `tail_word_start = (logical_bits / 32) * sizeof(std::uint32_t)` and `tail_bytes = staging_nbytes - tail_word_start`; if `tail_bytes != 0`, `transfer_queue.memset(static_cast<std::byte*>(lease.device_staging()) + tail_word_start, 0, tail_bytes)` (USM).
  2. Per-plane gather wrappers (one `parallel_for` per plane, in-order).
  3. `transfer_queue.memcpy(lease.host_mirror(), lease.device_staging(), staging_nbytes)` (in-order, USM→USM).
  4. **One** `transfer_queue.wait_and_throw()` covering all the in-order work above — the single wait.
  5. `std::memcpy(destination.data(), lease.host_mirror(), logical_nbytes)`.
  6. Return.

  Every `queue.memcpy`/`memset`/kernel operand is a USM allocation; raw host spans enter and leave only through `std::memcpy` with the `malloc_host` mirror, preserving 59-ST-005's strict-USM contract. The call stays synchronous at return; any failure (in the `std::memcpy` steps, the `transfer_queue.memcpy`/`memset` enqueue, the `parallel_for` enqueue, or the single `wait_and_throw`) is caught by a single outer try/catch around the entire flow: the catch poisons the lease (which destroys and discards the slot, restoring pool accounting) and rethrows the original exception without further state mutation.
- The scatter/gather launch wrappers keep the shared word-range formulas: `from_host` covers all `words_per_plane` destination words per plane; `to_host` covers the logical span `first_word`/`last_word` exactly as `standard_tiled_copy.inl:343-351` computes it. The per-plane walk uses scalar stack locals (no `std::vector`, no `PlanePair`).

The pinned three-step `fence_destroy` sequence is `state->result()` → `event_ = std::nullopt` under `mu_` → `state->release_metadata_slot()`. The destructor `~SyclFenceState()` calls `release_metadata_slot()` only as a fallback for pre-publication rollback; the success/drain path never reaches the destructor fallback because `fence_destroy` already cleared both members. Source audit: `grep -rn "\->release(slot\b" src/sycl` returns exactly one match (the line `pool->release(slot);` inside `release_metadata_slot()`); the implementation must never spell `pool_->release(slot_)` because the `pool` local is the cleared copy.
5. The 55-ST-001 four-shared_ptr owner invariant holds: `SyclFenceState` is owned concurrently by the Task (in the `tasks_` list node after `PublishPolicy::Splice`), the two registry `Fence` copies (one per entry, each capturing exactly one shared_ptr — the retained failure lives inside the state, not as a separate capture), and the `SequenceOutcome`'s `state` member. `~SyclFenceState()` runs when the last of these four is dropped; `release_metadata_slot()` has already cleared the slot by then on the success/drain path and runs once on the abortive path. No fifth shared_ptr exists.
6. The fault-injection seam remains observable with the same two contracts (pre-enqueue fault: throw, no sequence, sequence reuse next submission; post-enqueue fault: valid token, repeated `wait` rethrows the retained failure); the per-plane fault point fires once at the single post-launch boundary. The pre-enqueue rollback path drains `queue_` via `wait_and_throw()` (swallowed) before resetting `task.state` so the destructor's fallback `release_metadata_slot()` is safe with respect to any in-flight metadata `queue_.memcpy`. Existing 55-ST-001 regression cases are updated only where the fault point or its enumerator name moved.
7. Registry snapshots held across `~SyclTensor` invocation keep their `SyclFenceState` alive through the captured shared_ptr copy; the cached `FenceResult` (combined wait result + retained failure) is the only data the snapshot reads. The metadata slot's `pool_`/`slot_` members are private state-of-the-state and are never observed by the registry, by `complete_task`, or by a destructor snapshot — they are observable only by `release_metadata_slot()` itself. A snapshot therefore never delays or repeats a slot release.
8. Host transfers use the device-owned `StagingSlotPool` and the device-owned in-order `transfer_queue_`; `synchronous_transfer` performs no `sycl::queue` construction, no `sycl::malloc_shared`, and no `sycl::free`, and consumes `iom::gpu_algorithm::compute_staging_size` with its exact overflow diagnostic. Downloads zero only the partial staging tail word.
9. Every `sycl::queue::memcpy`/`memset`/kernel operand is a USM allocation; caller host spans are moved through the `malloc_host` mirror with `std::memcpy`. `copy_from_host`/`copy_to_host` remain synchronous at return with exact logical bytes, LSB-first sub-byte packing, and unchanged exception categories for caller errors. The `to_host` flow enqueues tail-memset → gather → device-to-mirror `queue.memcpy` and then performs exactly one `transfer_queue.wait_and_throw()` that covers the entire in-order sequence before any host-side read of the mirror; the `from_host` flow enqueues host-memcpy → queue-memcpy → scatter kernels and then performs exactly one `transfer_queue.wait_and_throw()` that covers the entire in-order sequence. Any failure inside the per-direction flow poisons the staging lease and rethrows the original exception; no fallback path re-issues the work or retries.
10. `SyclDevice` owns the staging pool and transfer queue; `~SyclDevice` drains the quarantine (55-ST-001), then calls `staging_pool_.destroy()` and releases the transfer queue while `*context_` is alive, then resets the context and invokes the `context_destroyed` seam. Pool destruction frees every idle slot at most once.
11. The only shared-file change is the defaulted `IOM_GPU_GLOBAL_STRIDE` macro whose default reproduces the current CUDA/HIP expansion; `src/cuda/**`, `src/rocm/**`, `src/cpu/**`, `src/ttnn/**`, and everything under `include/iom/` are unmodified.
12. Preserved SYCL-specific behavior: `eligible_devices()` GPU/accelerator filtering and deterministic ordinal validation, `SyclTensor`'s USM pointer-type compatibility rejection, in-order construction of both `SyclQueue::queue_` and the transfer queue, `parallel_for` lambda launch syntax, validation/`unsupported` messages, and token/`wait` semantics.
