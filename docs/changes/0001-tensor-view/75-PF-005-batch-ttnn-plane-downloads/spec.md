# Batch TTNN plane downloads behind one barrier with per-call staging

**Order:** 75
**Priority:** P1 — required normal-path performance remediation: removes the deterministic O(plane-count) download serialization and per-plane host-allocation churn on the TTNN backend; gates no other task.
**Blocked by:** `72-PF-002-avoid-full-download-prezero` — both rewrite `src/ttnn/copy.cpp:region_to_host`. Task 72 removes the `std::fill` destination pre-zero and tightens tail-bit behavior; task 75 must consume that post-72 state and must not reintroduce or preserve the pre-zero fill, since every supported TTNN leaf is whole-byte-aligned (`copy.cpp:53-60` `element_bytes` rejects non-byte widths), the per-plane assembly writes exactly `rows × columns × element_size` bytes per plane, and a whole-call pre-zero would gratuitously reintroduce the very pass the new pipeline collapses.
**Source:** `docs/changes/0001-tensor-view/review.md` — `PF-005`
**Review severity:** low
**Review verification:** strongly-supported, confidence 70

## Outcome

`iom::ttnn_detail::region_to_host` (`src/ttnn/copy.cpp:209-229`) stops downloading one plane at a time with a blocking device round trip per plane. One call allocates a single uninitialized host staging buffer sized to hold every plane's padded tile-major bytes, enqueues all plane reads onto `device.mesh_command_queue(0)` through the supported non-blocking `ttnn::copy_to_host` overload (`bool blocking = false`), executes exactly one `device.mesh_command_queue(0).finish()` as the SDK-documented completion checkpoint, and then assembles each plane's tile-major bytes into the row-major destination with the existing per-face segment walk in native view-plane order. Per-call host-buffer allocation count drops from O(plane count) — one `ttnn::allocate_tensor_on_host` plus one host `ttnn::Tensor` wrapper per plane — to exactly one staging allocation, and blocking device waits per call drop from one per plane to exactly one `finish()`.

The finding's SDK-capability caveat ("a non-blocking `copy_to_host` may not exist") is resolved by the supported surface, not left open: `ttnn/tensor/tensor_ops.hpp:43-48` declares `void copy_to_host(tt::tt_metal::distributed::MeshCommandQueue& queue, const Tensor& device_tensor, std::byte* dst, const std::optional<BufferRegion>& region = std::nullopt, bool blocking = true)`; with `blocking = false` it enqueues an asynchronous read of the full padded tile-major device buffer into caller-provided host memory (`tt_metal/impl/tensor/byte_based_data_transfer_apis.cpp:11-23`, raw non-pinned `host_data` is a supported input), and `MeshCommandQueue::finish()` (`tt_metal/api/tt-metalium/mesh_command_queue.hpp:182`, with the completion-checkpoint contract documented at `:99-112`) waits for all outstanding reads. The iom TTNN device is always a single-device mesh (`ttnn::open_mesh_device(device_id)` at `src/ttnn/device.cpp:621-623`), so the byte-based read path's single-device requirement holds. The submit-all-then-finish design is therefore the normative fix; no "unavoidable blocking serialization" fallback is selected. The speedup magnitude is unmeasured by the review and is established only by the before/after hardware timing this task requires.

## Current failure

Invariant (review §5 PF-005): bulk host transfers pipeline device reads, and host-buffer churn is O(1) per call.

Today `region_to_host` (`src/ttnn/copy.cpp:209-229`) loops over view planes and calls `download_plane` (`src/ttnn/copy.cpp:142-176`) per plane. Each `download_plane` call:

1. allocates a fresh full-padded-shape host tensor through `ttnn::allocate_tensor_on_host(plane.tensor_spec(), &device)` (`:147-148`) — one host allocation plus one host `ttnn::Tensor` object per plane, every call;
2. performs a blocking device read, `ttnn::copy_to_host(plane, host_tiled, /*blocking=*/true)` (`:149`) — the call waits for the plane's device-to-host transfer before returning;
3. extracts the tile-major bytes and runs the per-face segment walk into the destination.

For an N-plane view this is N serialized device round trips (each wait covers only its own plane) and N fresh host allocations, so multi-plane download time scales with `N × round-trip latency` instead of transfer bandwidth. The upload direction already batches: `region_from_host` (`src/ttnn/copy.cpp:190-207`) enqueues all per-plane device writes without waiting and issues exactly one `device.mesh_command_queue(0).finish()` at `:206`, which makes the download path's per-plane blocking the residual asymmetry the review flags. The review's verification is strongly-supported only — the mechanism is code-deterministic, but no TT hardware was available to measure the magnitude, so no unmeasured latency number may be stated as established; the timing evidence is produced by this task's verification.

Behavior that must survive unchanged: the per-face tile-major segment walk the previous remediation (order 45) installed inside `download_plane`; the caller-visible error and synchronization contracts of `region_to_host` (`src/ttnn/copy.hpp:33-36`) — no padding reaches the host buffer, synchronous at return, caller holds `api_mutex_` — and the explicit guarantee that the assembly overwrites every destination byte for the supported whole-byte leaf types (so a destination pre-zero is neither needed nor permitted; that explicit no-fill stance is task 72's contract, and task 75 consumes it).

## Scope

- Rewrite `region_to_host` (`src/ttnn/copy.cpp:209-229` post-72 — note: post-72 the destination pre-zero is gone, so the rewrite must not reintroduce it) to: allocate one uninitialized staging buffer of `plane_count × padded_plane_bytes`; submit all plane reads non-blocking in view-plane order; run one `finish()`; then assemble every plane from its staging window in the same order. The destination receives no pre-fill and no padding: every supported TTNN leaf is whole-byte-aligned and the per-plane write covers exactly `rows × columns × element_size` destination bytes, so the post-fix caller observes the full logical region and nothing else.
- Replace `download_plane` (`src/ttnn/copy.cpp:142-176`) with two anonymous-namespace helpers: a submit half (non-blocking read of one plane into a staging window) and an assemble half (the existing tile-major-to-row-major segment walk reading one staging window). The old per-plane blocking function is deleted; no caller outside `region_to_host` references it.
- Preserve the caller-visible error and synchronization behavior: `TtnnTensor::region_to_host` (`src/ttnn/device.cpp:333-339`) keeps holding the device-wide `api_mutex_` across the whole call, the call remains synchronous at return under all outcomes, and exceptions propagate with their existing categories.
- Affected backend: `ttnn` only. `region_from_host`, `upload_plane`, `copy_planes`, `TtnnQueue`, the registry/quarantine machinery, and every other backend are untouched.

## Implementation references

  1. Keeps the `rows` / `columns` / `element_size` / `plane_bytes` / `count` computation (`:216-221`, minus whatever task 72 has adjusted) verbatim. Does NOT prepend any `std::fill` over the destination: post-72 the destination arrives uninitialized and stays so until the assembly writes the logical region.
  2. Reads the padded plane geometry once from the first owner plane — `planes[owner_plane_at(source, 0)].padded_shape()[-2]` and `[-1]` — and computes `padded_plane_bytes = padded_rows × padded_columns × element_size`. All planes of an owner share one `tt::tt_metal::TensorSpec` (`src/ttnn/device.cpp:220-239`), so one read covers the call; `count ≥ 1` always (every logical dimension is nonzero).
  3. Allocates the staging buffer with checked arithmetic and no zero pass, e.g. `std::unique_ptr<std::byte[]> staging = std::make_unique_for_overwrite<std::byte[]>(total_bytes);` where `total_bytes = count × padded_plane_bytes` is built with the hand-rolled overflow-check pattern of `checked_plane_count` (`src/ttnn/device.cpp:140-153`), throwing `std::overflow_error` on wrap. `make_unique_for_overwrite` (C++20) avoids a full-size value-initialization pass over a buffer every byte of which a device read overwrites; allocation failure propagates `std::bad_alloc` synchronously exactly as `allocate_tensor_on_host` does today.
  4. Submit loop, view order `index = 0 .. count-1`:
     `ttnn::copy_to_host(device.mesh_command_queue(0), planes[owner_plane_at(source, index)], staging.get() + index * padded_plane_bytes, std::nullopt, /*blocking=*/false);`
     The call needs `<optional>` in this TU for the `region` argument; `ttnn/tensor/tensor_ops.hpp` is already included (`src/ttnn/copy.cpp:9`).
  5. Exactly one `device.mesh_command_queue(0).finish();` after the submit loop — the first blocking wait of the call, mirroring the existing upload-side barrier at `:206`.
  6. Assembly loop, same order and same `owner_plane_at` mapping: for each `index`, run the existing per-row/per-segment walk (identical arithmetic to `:156-175`: `seg_columns = min(16 - (col % 16), columns - col)`; `tile_index = (row / 32) * num_tile_cols + (col / 32)`; `face_index = ((row % 32) / 16) * 2 + ((col % 32) / 16)`; `first_element_index = tile_index * 1024 + face_index * 256 + (row % 16) * 16 + (col % 16)`) with `num_tile_cols = padded_columns / 32`, source bytes `staging.get() + index * padded_plane_bytes`, destination offset `index * plane_bytes + (row * columns + col) * element_size`.
  7. Owns the staging allocation with a single outer `try` / `catch` covering both entry points (a submit-loop throw and the success-path `finish()` throw) and the unified drain-then-rethrow policy. The lifetime invariant: once the submit loop publishes its first `ttnn::copy_to_host(..., blocking=false)` call, the address range `staging.get()` to `staging.get() + count*padded_plane_bytes` must stay allocated and unmutated until either the success-path `finish()` returns and the staging buffer goes out of scope at function end, or a compensating drain returns, or until the leaked-path code has deliberately released ownership. One `std::exception_ptr original_failure` captures the first throw in the protected scope via `catch (...) { if (!original_failure) original_failure = std::current_exception(); }` — once captured, `original_failure` is never reset. The catch body, exactly in order:
     1. Attempt a best-effort drain via `try { device.mesh_command_queue(0).finish(); } catch (...) { /* drain failure swallowed — we still rethrow the original below */ }` — this is the second source-visible `finish()` call site in this translation unit (the first is the success-path barrier after the submit loop). If the drain returns normally, the staging buffer is safe to free; the `std::unique_ptr<std::byte[]>` destructor does the free on natural unwinding as the `std::rethrow_exception(original_failure)` below propagates.
     2. If the drain throws, the device is still in flight; freeing the staging buffer now would race the reader thread writing into freed memory — exactly the bug this rewrite prevents. Deliberately **leak** the staging allocation for the remainder of the process's lifetime: `std::byte* leaked = staging.release(); (void)leaked;` and do NOT call `delete[]` on it. This is a permanent leak. A `std::unique_ptr<std::byte[]>::release()` allocation is NOT registered with the TTNN device or with the iom allocator and is therefore NOT reclaimed by `~TtnnDevice`, by `~TtnnTensor`, or by any other teardown path — the bytes survive until the OS reclaims the process. The leak is intentional, deliberate, and the only state observation that distinguishes the leak path from a normal failure that drains successfully. Its sole purpose is to prevent an in-flight device read from writing into freed host memory, which would be undefined behavior at the engine boundary; correctness dominates over process-lifetime footprint and is the accepted trade.
     3. `std::rethrow_exception(original_failure);` is the final statement, executed whether the drain succeeded, whether the drain threw, and whether the staging leaked as a result. The caller observes the original exception (a `ttnn::...` runtime type on the failure path) and never a different exception type. The rethrow spelling is `std::rethrow_exception` of the captured `std::exception_ptr`; a bare `throw original_failure;` (or `throw *original_failure;`) is a different operation (it throws a copy, bypasses the captured object, and is NOT the correct spelling here) and is explicitly forbidden.
     Cumulative leak consequence: each call to `region_to_host` whose submit or success-path `finish()` throws AND whose compensating drain `finish()` also throws permanently leaks exactly one host allocation of size `count * padded_plane_bytes`. A pathological workload can therefore leak unboundedly across many failed calls; the per-call allocation is bounded, the cumulative total is not. The leak is accepted only because the alternative — freeing the staging buffer while a non-blocking device read is in flight — corrupts host memory and is undefined behavior. The function returns the original exception in every case so the caller can stop issuing work; a future remediation may pool the staging buffer or own it through a long-lived registry to eliminate the cumulative leak, but that work is out of scope here.
     This unified handling collapses path A (submit-loop throw) and path B (success-path `finish()` throw) into one policy: attempt `finish()` to drain, free on success or leak on failure, always `std::rethrow_exception(original_failure)` and never substitute a different exception type. The upload-side `region_from_host` keeps its `device.mesh_command_queue(0).finish()` at `:206` and its own exception behavior untouched.

(The contract's pre-zeroed-destination comment is removed by task 72; task 75 inherits the post-72 contract.) No signature changes.
- **Read (SDK evidence, resolved):** remote `TT_METAL_HOME` source — `ttnn/api/ttnn/tensor/tensor_ops.hpp:43-48` (byte-pointer `copy_to_host` with `bool blocking`), `tt_metal/api/tt-metalium/mesh_command_queue.hpp:99-112,166-169,182` (`finish()` listed as a completion checkpoint for non-blocking transfers), `tt_metal/impl/tensor/byte_based_data_transfer_apis.cpp:11-23` (raw destination, single-device mesh). ## Requirements

1. **Submit all planes, finish once.** `region_to_host` enqueues every plane read with `blocking = false` onto `device.mesh_command_queue(0)` and performs exactly one `device.mesh_command_queue(0).finish()` after the submit loop. The download path contains zero blocking `ttnn::copy_to_host` calls (no `/*blocking=*/true` anywhere in `src/ttnn/copy.cpp`) and no `finish()` inside either loop. The upload-side `finish()` at `:206` is untouched.
2. **O(1) host-buffer allocation per call.** The call performs exactly one staging allocation (`count × padded_plane_bytes`, computed with the overflow-check pattern of `src/ttnn/device.cpp:140-153`, `std::overflow_error` on wrap) and zero `ttnn::allocate_tensor_on_host` calls. Staging footprint (not allocation count) is the sum of padded plane bytes — one window per in-flight read — the same fire-and-forget batching trade the upload path already makes; this consequence is accepted, and no chunked-submission variant is introduced.
3. **No staging initialization pass.** The staging buffer is created uninitialized (`std::make_unique_for_overwrite<std::byte[]>`); every byte of every window is overwritten by its plane's read, so the buffer is never zero-filled or pre-touched.
4. **Native plane order preserved end to end.** The submit loop and the assembly loop use the identical `owner_plane_at(source, index)` mapping and the identical window pairing (`window = staging.get() + index * padded_plane_bytes` ↔ `destination + index * plane_bytes`), in view order `0 .. count-1`. No window is read before the `finish()` returns.
5. **Byte-identical assembly; destination never pre-zeroed.** The per-face segment walk keeps its exact arithmetic (`seg_columns = min(16 - (col % 16), columns - col)`; `first_element_index = tile_index * 1024 + face_index * 256 + (row % 16) * 16 + (col % 16)` with `tile_index`/`face_index` from `padded_columns / 32`), now sourcing from the staging window instead of `host_buffer::get_host_buffer`. Destination offsets stay `(row * columns + col) * element_size`. The `region_to_host` body contains no `std::fill` over the destination; padding never reaches the destination because the assembly writes only the logical `(row, col)` lattice bytes, and every supported TTNN leaf is whole-byte-aligned so every destination byte is written exactly once. The pre-zero semantics that used to live here are owned by task 72; after that ship, `region_to_host` is a pure read-then-write path.
6. **Synchronous-at-return errors preserved across both failure paths; permanent per-failed-call host leak only when the compensating `finish()` itself throws.** `element_bytes` keeps throwing `std::logic_error("TTNN supported type is not byte-aligned")`; TTNN runtime exceptions from submit or `finish()` propagate synchronously with their existing types. The implementation owns the staging buffer across both failure entry points (submit-loop throw and success-path `finish()` throw) with the unified outer-try / drain-finish / rethrow policy described in Implementation references step 7. On the failure path, the policy is, in order:
- Capture the first throw into a `std::exception_ptr original_failure`; never substitute a different exception.
- Attempt a best-effort `finish()` drain. If it returns normally, the `std::unique_ptr<std::byte[]>` destructor frees the staging buffer on natural unwinding as `std::rethrow_exception(original_failure)` propagates.
- If the drain itself throws, deliberately `staging.release()` the unique_ptr without `delete[]`. The host allocation is leaked for the rest of the process's lifetime; it is not registered with the TTNN device, the iom allocator, `~TtnnDevice`, `~TtnnTensor`, or any teardown path — the bytes survive until the OS reclaims the process. This is a deliberate, permanent leak; the only alternative would free the staging buffer while a non-blocking device read is still in flight, which is undefined behavior at the engine boundary.
- Final statement is `std::rethrow_exception(original_failure);` — always `std::rethrow_exception` of the captured `std::exception_ptr`. A bare `throw original_failure;` (which throws a copy and bypasses the captured exception_ptr) or `throw *original_failure;` is NOT the correct spelling here and is forbidden. The function never substitutes a different exception type (no `std::logic_error("TTNN...pool exhausted")`, no rewrap, no throw of an implicitly-constructed `std::runtime_error`).
- The destination is never pre-zeroed (post-72), so on any exception the destination holds whatever bytes the assembly wrote before the failure plus whatever was there beforehand in the un-written regions — partial-assembled bytes only where the assembly reached, never zeros imposed by this function.
- Each failed call whose drain also failed leaks exactly one allocation of size `count * padded_plane_bytes` for process lifetime. The per-call leak size is bounded; the cumulative leak across many failed calls is unbounded. The leak is intentional and is the only state observation that prevents an in-flight read from corrupting freed host memory.
7. **Locking discipline unchanged.** `TtnnTensor::region_to_host` keeps one `api_mutex_` critical section around submit, the success-path `finish()`, assembly, and the unified exception-handling scope (outer `try` / `catch` and the drain `finish()` all run under the same lock); the rewrite shortens the effective device-busy window but never drops, narrows, or reorders the mutex protocol.
8. **Clean cutover, no surface change.** `download_plane` is deleted and replaced by the two helpers; `upload_plane`, `region_from_host`, `copy_planes`, `element_bytes`, `view_plane_count`, `owner_plane_at`, `view_rows`, `view_columns`, `typed_buffer` stay as they are; no public header, CMake target, or exported symbol changes; no permanent benchmark or test-infrastructure additions.

## Non-goals

- The upload path's per-plane typed scratch vector (`std::vector<T> typed(padded_elements, T{0})` at `src/ttnn/copy.cpp:86`) and any other `upload_plane`/`region_from_host` churn. The finding cites it, but this task's assignment is TTNN plane-download serialization/churn only.
- The destination pre-zero semantics that task 72 ships (it removes the `std::fill` and replaces the tail-bit contract). This spec consumes task 72's post-state; it neither preserves nor replaces the pre-zero itself.
- `copy_planes` (`src/ttnn/copy.cpp:231-240`), `TtnnQueue`, `fence_through_sequence`/`last_finished_seq_` watermark finishing (`src/ttnn/device.cpp:570-587`), the outstanding-work registry, and quarantine behavior.
- Multi-device meshes, new SDK APIs beyond the `copy_to_host` overload already declared in `ttnn/tensor/tensor_ops.hpp`, pinned-memory optimization, SDK upgrades, or CMake/build changes.
- A chunked submit/finish pipeline (barrier every K planes): a different design than the selected submit-all-then-finish; only reconsider if hardware evidence shows the SDK cannot hold a full call's reads outstanding.
- Any tracked test or benchmark target. The timing evidence is produced by the `_local/` throwaway helper, per `.agents/skills/remote-development`.

- `/tmp/pf005.prefix.txt` and `/tmp/pf005.postfix.txt` each contain, per bench shape, the download median, the upload control median, and a sampled-value correctness line. The post-fix download medians are at or below the control medians, with the largest relative improvement on the 1024-plane latency-class shape; the upload control medians are approximately unchanged. The recorded numbers (baseline, post-fix, delta) are reported in the implementation's completion notes as the measurement the review could not make.
- The source audit returns exactly the expected counts: zero `allocate_tensor_on_host`, zero blocking `copy_to_host`, exactly three `finish()` call sites (upload barrier in `region_from_host`; success-path download barrier; exception-path drain inside the unified catch — none inside a plane loop), no `std::fill` over the destination in `region_to_host`. The `release()` that would hand ownership of the staging buffer to a process-lifetime leak does NOT appear on the success path and is reached only inside the catch and only after the drain `finish()` itself throws — the unique_ptr destructor frees normally in every other path, and the exception is always rethrown via `std::rethrow_exception(original_failure);` rather than `throw original_failure;` or any other spelling.
- No formatters, linters, project-wide builds, or sibling-backend suites are run here; per-backend validation belongs to the sibling tasks on their own orders.
