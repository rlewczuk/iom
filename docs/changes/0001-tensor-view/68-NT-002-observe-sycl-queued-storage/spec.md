# Observe Full Native SYCL Storage After Queued Copies

**Order:** 68
**Priority:** P1 — required normal-path remediation that closes the only accelerator's out-of-window/padding corruption blind spot; a one-argument cutover per call site with no design work, and nothing else is gated on it
**Blocked by:** None
**Source:** `docs/changes/0001-tensor-view/review.md` — `NT-002`
**Review severity:** medium
**Review verification:** verified, confidence 95

## Outcome

The SYCL driver observes complete native owner storage around every queued copy, exactly like CUDA, ROCm, and TTNN already do. In `test/sycl/test_sycl_conformance.cpp`, the `TEST_CASE("SYCL conformance: asynchronous copies against the CPU reference")` and `TEST_CASE("SYCL conformance: full shared suite")` cases each construct the existing `SyclStorageOracle` bound to `devices.candidate_allocator` and pass `&oracle` as the fourth argument to `iom_conformance::run_async_copy_conformance` / `iom_conformance::run_backend_conformance`. After every queued `DeviceOps::copy` completes, the harness then proves that the complete destination owner allocation equals its seeded storage with only the destination view window replaced by the source's logical bytes (padding, untouched planes, and sub-byte tails included) and that the complete source owner allocation is byte-for-byte unchanged — instead of only checking destination-window logical bytes.

## Current failure

`run_async_copy_conformance` (`test/backend/backend_conformance_copy_storage.hpp:457-631`) takes an optional `AcceleratorStorageOracle*` fourth argument. When it is `nullptr` (the SYCL state today), the harness checks only `require_logical_bytes` on the destination view after the queued copy — in-window logical bytes — and never re-verifies the source owner or any byte outside the destination window. When an oracle is supplied, the harness independently encodes full standard-tiled owner storage for both candidates (`encode_standard_tiled_storage`), seeds both allocations through the backend-native oracle path, waits the copy token, and compares the full destination observation against seed-plus-window-update and the full source observation against its seed (`:549-577` seeding, `:596-620` post-copy observation).

The CUDA, ROCm, and TTNN drivers pass their native oracles at both call sites: `test/cuda/test_cuda_conformance.cpp:319-322` and `:365-369` (`CudaStorageOracle oracle;` … `&devices.gate, &oracle`), `test/rocm/test_rocm_conformance.cpp:428-430` and `:519-522`, `test/ttnn/test_ttnn_conformance.cpp:474-477` and `:513-515`. The SYCL driver is the only accelerator left uncovered: `test/sycl/test_sycl_conformance.cpp:317-319` calls `run_async_copy_conformance` and `:357-360` calls `run_backend_conformance` (which forwards the oracle only into `run_async_copy_conformance`, `test/backend/backend_conformance_other.hpp:507-519`) with no fourth argument — even though `SyclStorageOracle` is fully implemented in the same file (`:208-240`, seeding/observing through an in-order `sycl::queue` on the allocator's captured context/device) and is already exercised by the host-transfer oracle fixture two cases above (`:306-313`).

Consequently a SYCL copy kernel that writes padded tiles, clobbers a neighboring slot via a wrong mask, or touches planes outside the destination window passes the entire SYCL suite. The exposure is acute for SYCL specifically: its queued copy kernel is the only one in the repository still using per-bit `sycl::atomic_ref` writes (`device_read_bits`/`device_write_bits`, `src/sycl/copy.cpp:88-129`, launched per plane pair over `sycl::range<1>(rows * columns)` at `:301-331`), so a slot-arithmetic or mask regression ships silently and would first surface as distant model corruption once compute operations arrive. CPU is the only backend with full-allocation oracle coverage, and only via the synchronous `run_storage_oracle_conformance` fixture — not around queued copies.

## Scope

- Modify only `test/sycl/test_sycl_conformance.cpp`: wire the existing `SyclStorageOracle` into the two existing conformance cases that drive queued copies. No new test case, no harness change, no oracle change, no production change.
- Affected call sites:
  - `TEST_CASE("SYCL conformance: asynchronous copies against the CPU reference")` (currently `:315-321`): add `SyclStorageOracle oracle(devices.candidate_allocator);` after `SyclDevices devices;` and change the call to `run_async_copy_conformance(devices.conformance(), devices.candidate->supported_data_types(), &devices.gate, &oracle);` — the fourth argument after the observer, mirroring `test/cuda/test_cuda_conformance.cpp:318-322`.
  - `TEST_CASE("SYCL conformance: full shared suite")` (currently `:355-362`): the same construction and `run_backend_conformance(devices.conformance(), devices.candidate->supported_data_types().subspan(0, 1), &devices.gate, &oracle);`, mirroring `test/cuda/test_cuda_conformance.cpp:364-369`.
- The oracle argument activates the harness's full protocol for every supported leaf type (23 types via `devices.candidate->supported_data_types()` in the dedicated async case; the full suite's async segment via its single-type span, whose first entry is `DataType::BOOL`), every `copy_owner_shapes()` entry, and every `copy_cases_for()` case (`test/backend/backend_conformance_copy_storage.hpp:255-263`, `:193-253`): independent source/destination seed, seed read-back verification, `wait` before any observation, full destination-owner comparison against seed plus `apply_standard_tiled_view` window update, and full source-owner comparison against its seed.
- Binding rule: the oracle is constructed with `devices.candidate_allocator` only. Its context/device are captured by `capture_context` during `SyclDevices`' construction of the candidate (`test_sycl_conformance.cpp:75-80,192-201`), which is what makes `seed`/`observe` address the same USM allocations the candidate device wrote. Never bind it to `foreign_allocator` or `reference_allocator`.
- Verification-side negative demonstration (no committed code): with the wiring in place, a deliberately widened temporary variant of the SYCL copy kernel that writes the padded tile extent must be detected at the first out-of-window destination byte, as `docs/changes/0001-tensor-view/38-NT-001-observe-queued-copy-storage/spec.md` prescribes for accelerator verification (detailed under Verification).

## Non-goals

- Copy-matrix or shape expansion: CC-002 (`52-CC-002-cover-aligned-multitile-storage`) owns the aligned multi-tile oracle shapes and NT-004 (order 70) owns asymmetric-stride, minimal-extent, and row-tail-only coverage. This task adds no `CopyCase`, no owner shape, and no harness parameter; shapes those tasks add flow through the SYCL oracle path automatically because the case consumes the shared matrices.
- SYCL kernel convergence and performance: 60-AR-001 owns replacing the per-bit atomic kernel, per-plane launches, and staging; this task changes no kernel and no production code.
- SYCL queue/lifetime mechanics: 55-ST-001 owns the `StagedWorker`/registry/quarantine migration; 69-NT-003 owns the destroy-before-wait lifetime regressions. The oracle argument is orthogonal to and unaffected by both.
- Oracle machinery: no new `AcceleratorStorageOracle` subclass, no redesign of `SyclStorageOracle`'s per-call queue, no pooled observation path, no new harness infrastructure or fault-injection seam.
- CUDA, ROCm, TTNN, and CPU drivers: their oracle wiring already exists and is the model, not a target.
- Extending oracle observation to host transfers, error paths, or compute operations: `run_storage_oracle_conformance` and the error scenarios keep their current scope.
