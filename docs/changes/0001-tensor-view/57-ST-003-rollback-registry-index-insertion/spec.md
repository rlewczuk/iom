# Roll back the full registry entry on every secondary index insertion failure in register_entry

**Order:** 57
**Priority:** P1 — bounded OOM-path state leak in the lifetime machinery introduced by 49-ST-003; the fix restores strong exception safety for `OutstandingWorkRegistry::register_entry` but gates no other task (AR-003's later redesign must preserve the restored invariant)
**Blocked by:** None
**Source:** `docs/changes/0001-tensor-view/review.md` — `ST-003`
**Review severity:** low
**Review verification:** verified, confidence 85

## Outcome

`OutstandingWorkRegistry::register_entry` is strongly exception-safe for every allocation failure during the secondary index insertions, eliminating both defects the nested try/catch left on the OOM path. After the `by_id_` insertion succeeds, any exception thrown by the `by_address_`, `by_sequence_`, or `by_queue_` insertion (in practice `std::bad_alloc` from a multimap node allocation) is caught exactly once; the complete entry is erased from all four indexes through the registry's established `erase_entry_locked` rollback, and the original exception propagates to the caller. The registry is observably back at its pre-call state: `snapshot_for(address)` returns empty, `try_release_entry(id)` returns `false`, and an identical re-registration is accepted. No `Live` entry with a dangling fence closure survives the failed call, and no invalidated iterator is ever passed to a second erase. A deterministic allocation-fault sweep in the always-run `iom_tests` suite proves the invariant for every allocation ordinal of a registration; the same sweep run under libstdc++ debug-mode iterator validation confirms zero iterator-misuse aborts with the fix in place.

## Current failure

The invariant from 49-ST-003: registry mutators are strongly exception-safe — an exception during index insertion leaves the registry unchanged.

`register_entry` in `include/iom/outstanding_work_registry.hpp` inserts into `by_id_` first (`:225-232`) and then rolls the new entry forward through three nested `try` blocks (`:233-255`): `by_address_` (`:234`), `by_sequence_` (`:236`), `by_queue_` (`:238`). The nesting has two distinct defects, both reachable on allocation failure.

Defect A — address-index leak (the one the review names). The outermost `catch (...) { throw; }` (`:253-255`) wraps only the `by_address_.emplace` statement and is a pure pass-through. When the `by_address_` multimap node allocation throws `std::bad_alloc`, control reaches that outer handler, which rethrows without erasing the already-inserted `by_id_` entry.

Defect B — invalid-iterator UB on the sequence/queue path (the one the review missed by rebutting only the "uninitialized iterator" theory). The inner handler (`:242-247`) erases `sequence_it`, `address_it`, and `entry_it` and then `throw;`. That rethrow propagates out of the middle try, which catches at `:248-252`, where the middle handler calls `by_address_.erase(address_it)` and `by_id_.erase(entry_it)` on iterators that the inner handler has just invalidated. Erasing an already-erased iterator is undefined behavior: under libstdc++/libc++ it typically corrupts the multimap's size and may dereference freed node memory, surfacing as a deterministic crash inside `erase`, as a heap-use-after-free under AddressSanitizer, or as a silent map invariant violation that later manifests elsewhere. This path is reachable whenever `by_sequence_.emplace` (defect B at ordinal 3 of the source-ordered insertions) or `by_queue_.emplace` (defect B at ordinal 4) throws after the inner handler has already erased the upstream iterators.

Both defects share the same root cause: the nested handlers roll back by erasing the *stored iterators* they obtained from the prior emplace calls, but a rethrow from the innermost handler lands in an enclosing handler that still references those now-invalid iterators. The single-handler rewrite that erases by value from the held `Entry` — exactly the "initialize the rollback path from the `Entry` already held" option — eliminates both at once. The review's rejection of uninitialized-iterator UB is correct for that reading; the iterators are initialized but invalidated by the inner catch before the outer catches see them.

Consequences of the leak path (defect A): the retained entry is `Live` and holds a fence closure capturing the submitting task's fence resource (the CUDA/ROCm event-plus-slot resource or TTNN synchronization object). The production callers cannot reach it: `register_registry_entries` (`:488-512`) rolls back only the first-registered source id (`:506-510`) — the failed destination id was never returned — and the failed submission produces no `SequenceOutcome` record, so no later `try_release_entry` or `invalidate_entries` call ever names the id. The entry is unreachable from `by_address_`, so no tensor destructor's `snapshot_for(address)` sees it either. The result is a permanent `by_id_` map-node leak holding a closure whose captured fence resource the caller's catch path destroys — a dangling `std::function` that is never invoked. Reachability of defect A is `by_address_.emplace` node-allocation failure only.

Consequences of defect B: undefined behavior whenever `by_sequence_.emplace` or `by_queue_.emplace` node allocation fails, even though the leak and double-erase-intent would otherwise leave the registry observably clean in a well-defined world. Both defects are bounded by allocation failure only, which is why review severity is low — but together they are exactly the OOM-path exception-safety guarantee 49-ST-003's spec promises and the nested rollback fails to deliver.

The defect ships in the common header consumed by all four registry backends (`src/cpu/registry_state.hpp`, `src/cuda/registry_state.hpp`, `src/rocm/registry_state.hpp`, `src/ttnn/registry_state.hpp`); 55-ST-001 wires SYCL onto the same header. Every backend inherits the fix without per-backend work.

## Scope

- Restructure the rollback in `OutstandingWorkRegistry::register_entry` so one exception handler covers all three secondary index insertions and erases the `by_id_` entry through the existing private `erase_entry_locked` helper. Delete the nested try/catch ladder and its pass-through outer handler.
- Preserve the pre-insertion behavior exactly: argument validation (`:200-218`) and the duplicate-id checks (`:221-232`) throw before any index mutation; `by_id_.emplace`'s own standard strong guarantee (an `Entry`/fence copy failure inserts nothing) is relied upon, not re-implemented.
- Affected backends: none individually — the change is in the shared header; CPU, CUDA, ROCm, and TTNN behavior is unchanged on every non-faulting path and on every faulting path. On the `by_address_` ordinal the fix replaces a leak with a clean rollback; on the `by_sequence_` and `by_queue_` ordinals the fix replaces invalid-iterator UB with a clean rollback. None of the faulting paths remain unsafe after the change.
- Observable failure contract after the change: `register_entry` throws the original exception (e.g. `std::bad_alloc`) and leaves `snapshot_for(address)` empty, `try_release_entry(id)` returning `false`, and the registry accepting an identical re-registration.
- `register_registry_entries` and the four per-backend `register_copy_entries` bridges are unchanged; their existing rollback guards keep working because `register_entry` now throws only after full internal rollback.
- Tests: one deterministic allocation-fault regression added to `test/test_iom.cpp` beside the existing registry cases, using a process-global counting/failing `operator new` replacement scoped to the test binary. The test is exercised under two configurations in CI verification: the default configuration proves the post-fix invariant and the defect-A behavioral discriminator at the address-index ordinal; a companion `_GLIBCXX_DEBUG` build proves the defect-B iterator-misuse discriminator at the `by_sequence_`/`by_queue_` ordinals (with the fix reverted, the debug-mode iterator check aborts on the second erase; with the fix applied, the sweep completes). AddressSanitizer and UndefinedBehaviorSanitizer are not an acceptance channel — sanitizer shadow memory does not cover `std::map` invalid-iterator misuse and the global `operator new` replacement interferes with sanitizer allocation interception.

## Implementation references

- **Modify:** `include/iom/outstanding_work_registry.hpp` — `OutstandingWorkRegistry::register_entry`, the nested try/catch at `:233-255`. Replace the ladder with a single `try` enclosing the three index insertions; in the single `catch (...)` call `erase_entry_locked(entry_it)` and rethrow the original exception. `entry_it` is the `by_id_` iterator returned by `:225-232`.
- **Read:** `include/iom/outstanding_work_registry.hpp:426-453` — `erase_entry_locked(const_iterator)` is the established rollback mechanism already used by `try_release_entry`, `remove_entry_if_present`, and `remove_entries`. It reads the held `Entry`'s address, sequence, and queue id, erases the matching pair from each of `by_address_`, `by_sequence_`, and `by_queue_` (finding nothing where an insertion never happened), then erases the `by_id_` node. It is `noexcept`, so the rollback itself cannot throw — required for strong exception safety. This is the review's "initialize the rollback path from the `Entry` already held" option; a single handler eliminates the triple-nested handlers whose cumulative iterator erases forced the pass-through outer catch.
- **Read:** `include/iom/outstanding_work_registry.hpp:488-512` — `register_registry_entries`: its catch removes the source entry via `remove_entries` when the destination registration throws. This contract is preserved verbatim; do not touch the helper.
- **Read:** `src/cpu/device.cpp:831-863` (and the CUDA/ROCm/TTNN `execute` analogues at `src/cuda/copy.cu:816-821`, `src/rocm/copy.hip:817-822`, `src/ttnn/device.cpp:488-494`) — the Execute-callback callers that rely on a throwing `register_entry` to trigger their pre-publication rollback. No caller changes.
- **Tests:** `test/test_iom.cpp:2097-2162` — the existing `OutstandingWorkRegistry releases exact same-address entries` and `Quarantine runs allocator cleanup at most once` doctest cases are the pattern and neighbor for the new case; the suite asserts allocation failures with `CHECK_THROWS_AS(..., std::bad_alloc)` (see `test/test_cpu.cpp:447`).

## Requirements

- The rollback structure in `register_entry` becomes: after the `inserted` check, one `try` block containing the `by_address_.emplace`, `by_sequence_.emplace`, and `by_queue_.emplace` statements, and one `catch (...)` whose body is exactly `erase_entry_locked(entry_it);` followed by `throw;`. No other statements join the handler. The rollback runs under the existing `std::lock_guard` and performs no allocation.
- `erase_entry_locked` must remain the only rollback path; the per-index `erase` calls by stored iterator disappear with the nested handlers. Its scan-based erase is safe on every partial-insertion state: zero, one, or two of the three secondary indexes may hold the id when the handler runs.
- Validation throws (`std::invalid_argument` for zero id/address/sequence/queue and empty fence, duplicate id) and the `by_id_.emplace` strong guarantee keep their current pre-mutation behavior.
- After a failed `register_entry`, the caller-observable registry state equals pre-call state: `snapshot_for(address)` is empty (the address bucket holds nothing), `try_release_entry(id)` is `false` (the id is absent from `by_id_`), the test fence invocation counter is unchanged (no dangling closure is ever invoked), and an identical re-registration with the same id/address/sequence/queue id succeeds and behaves normally through release or invalidation queries.
- The sweep covers the source-ordered insertion ordinals in their source-order positions. From the current `register_entry` source, the insertions occur in this order: `by_id_` (ordinal 1), `by_address_` (ordinal 2), `by_sequence_` (ordinal 3), `by_queue_` (ordinal 4). With the captureless test fence, `N` from the probe equals `4` and the source-ordered ordinals map directly to the sweep ordinals. The sweep drives both discriminator channels: (i) the address-index ordinal — the unique ordinal whose failed allocation leaves the address bucket empty while `by_id_` still holds a `Live` entry — yields the defect-A behavioral discriminator under the default configuration (`try_release_entry(id)` returns `true` by erasing the leaked entry; duplicate-id re-registration throws `std::invalid_argument`). On the current source that ordinal is `k=2`; if a future std::function or library implementation shifts the allocation count, the case identifies the address-index ordinal by repeating the probe under the same fence and locating the largest `k` for which the failed-at-`k` call has the address bucket empty post-failure while `by_id_` still holds the entry — that is the by-address-insertion ordinal. (ii) the source-ordered `by_sequence_` and `by_queue_` ordinals yield the defect-B iterator-misuse discriminator under `_GLIBCXX_DEBUG`; with the fix reverted, those ordinals abort inside the debug-mode iterator check on the second `erase`; with the fix applied, they pass the same pre-call-state assertions as every other ordinal. The sweep asserts the observable pre-call-state list (empty `snapshot_for(address)`, `CHECK_FALSE(try_release_entry(id))`, unchanged fence counter, immediate identical re-registration success) at every ordinal `1..N` in the default configuration; the `_GLIBCXX_DEBUG` build runs the same sweep against the same ordinals to surface defect B.
- The test fence must be a captureless lambda incrementing a static counter (a captureless `std::function` copy allocates nothing), so one successful registration consumes exactly the four index node allocations. The case then: (1) probes the allocation count `N` of one successful registration in count-only mode and releases it; (2) sweeps every ordinal `k = 1..N` with a fresh address and id: arms fail-at-`k`, calls `register_entry` inside a plain try/catch (not a doctest macro, so no harness allocations fall inside the armed window), requires the `std::bad_alloc`, and asserts every element of the observable pre-call-state list above, then re-registers the identical tuple, requires the snapshot to contain exactly one entry, exercises `invalidate_entries_for_sequence` on it (exactly one `Invalidated` entry), removes it with `remove_entry_if_present(id, address)` (an invalidated entry is not releasable through `try_release_entry`), and requires the snapshot empty again.
- Keep the change limited to the rollback restructure and the test; no public header, `Entry`/`EntrySnapshot`, `Fence`, mutator-signature, or error-category changes.

## Non-goals

- Registry shape changes: index removal, `EntrySnapshot` aliasing, quarantine-list rework, or header relocation are AR-003's redesign. AR-003 must preserve this task's invariant (a failed insertion leaves the registry unchanged) and may update the sweep test to the reduced index set.
- Quarantine allocation-failure policy (`Quarantine::add`/`emplace` behavior on `std::bad_alloc`) — owned by the ST-004/CC-004 quarantine-failure work, not touched here.
- The end-to-end destroy-while-queued CPU regression and the `register_registry_entries` two-phase rollback unit case belong to NT-003's testing remediation; this task adds only the `register_entry` fault-injection regression its review section prescribes.
- SYCL adoption of the registry — 55-ST-001 owns that migration; this fix benefits it automatically through the shared header.

## Verification

CPU-only local build and test (common header; no accelerator hardware involved). Two configurations prove the two defects and the fix.

Default (defect A evidence through behavioral assertions, plus the post-fix invariant at every ordinal):

```bash
cmake -S . -B build/st003-rollback -DBUILD_TESTING=ON -DCUDA_ENABLED=OFF -DROCM_ENABLED=OFF -DTTNN_ENABLED=OFF -DSYCL_ENABLED=OFF
cmake --build build/st003-rollback --target iom_tests -j
ctest --test-dir build/st003-rollback --output-on-failure -R "^iom_tests$"
```

libstdc++ debug mode (defect B evidence — deterministic iterator validation, the required discriminator):

```bash
cmake -S . -B build/st003-rollback-debug -DBUILD_TESTING=ON -DCMAKE_CXX_FLAGS='-D_GLIBCXX_DEBUG' -DCUDA_ENABLED=OFF -DROCM_ENABLED=OFF -DTTNN_ENABLED=OFF -DSYCL_ENABLED=OFF
cmake --build build/st003-rollback-debug --target iom_tests -j
```
