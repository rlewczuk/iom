# Eliminate the avoidable full-destination pre-zero pass on CPU and TTNN `copy_to_host`

**Order:** 72
**Priority:** P1 — deterministic avoidable full-destination write on every output readback; one wasted host pass per download on a path the engine runs on every host read. The review's measured 24.3 vs 14.3 GB/s asymmetry motivates the removal; the removed pass's contribution to that asymmetry is not isolated as a measured 40 % causal loss.
**Blocked by:** `51-CC-001-enforce-cpu-tiled-row-walk` — the corrected per-tile-column walk is the substrate the prezero removal must agree with byte-for-byte; removing the prezero before the layout is canonical would lock in zeroed-but-wrong positions.
**Source:** `docs/changes/0001-tensor-view/review.md` — `PF-002`
**Review severity:** medium
**Review verification:** strongly-supported (extra pass deterministic; asymmetry attribution consistent), confidence 80

## Outcome

`CpuTensor::region_to_host` (`src/cpu/device.cpp:645-728`) and `iom::ttnn_detail::region_to_host` (`src/ttnn/copy.cpp:209-229`) stop zeroing the entire destination host buffer on every `copy_to_host`. For byte-aligned leaf widths (`leaf_bits % 8 == 0`) the implementation skips the fill entirely — every byte the tile walk writes is the canonical host-encoding byte, and padding bytes that the §5.4 contract keeps out of the host buffer are never touched. For sub-byte leaf widths (`leaf_bits % 8 != 0`) the implementation keeps a single trailing-byte zero of the final byte of the destination buffer, written *before* the sub-byte walk runs, so the walk then writes the logical bits back into the zeroed destination and the unused trailing bits of the final byte read as zero. The minimum is derived from total logical bits of the view (`source.spec().shape.element_count() * bits`), validated through the existing checked arithmetic that `logical_nbytes()` already exercises; the byte count is `logical_nbytes()` and the trailing-byte-zero condition is `total_logical_bits % 8 != 0`. The upload paths and the shared GPU synchronous-transfer path are untouched. The host encoding, padding exclusion, error categories, and zero-size impossibility are preserved verbatim. The CPU throughput floor re-baselined by order 67 (NT-001) updates accordingly.

## Current failure

Invariant: download cost scales with logical bytes moved; only the trailing unused bits of the final byte of a sub-byte logical buffer can contain garbage that needs canonical zeroing (the §5.4 "unused tail bits in a logical host buffer … are written as zero on output" contract — `docs/changes/0001-tensor-view/spec.md:185`). The shared GPU path already encodes this minimum: `synchronous_transfer_impl` (`src/shared/standard_tiled_copy.inl:381-438`) computes `tail_word_start = (logical_bits / 32) * sizeof(std::uint32_t)` (line 410) and `Policy::memset`'s only the bytes from `tail_word_start` to `staging_nbytes` (lines 413-417) — never the whole buffer.

The CPU and TTNN download paths instead pre-zero the full destination on every call:

- `src/cpu/device.cpp:650` — `std::fill(destination.begin(), destination.end(), std::byte{0})` over the entire `std::span<std::byte>` that the §5.4 contract sizes as `view.spec().logical_nbytes()`. The bytes the per-tile walk writes are then overwritten by `copy_tile_row_byte_aligned` (the byte-aligned path at `:697-715`) or assembled by `copy_tile_row_subbyte` (the sub-byte path at `:722-725`) — both paths overwrite every destination byte the pre-fill wrote. For byte-aligned leaves the pre-fill is pure overhead; for sub-byte leaves the pre-fill is broader than needed, because the walk leaves every byte except possibly the final partial byte fully written.
- `src/ttnn/copy.cpp:215` — the same `std::fill` over the entire row-major destination before the per-plane `download_plane` loop. `download_plane` (`:142-176`) writes `seg_columns * element_size` bytes per face-major segment — one `std::memcpy` per 16-element segment — for every `(row, col)` inside the logical extent. Every supported TTNN leaf (`iom::ttnn_supported_data_types()` enumerates `BFLOAT16`, `FLOAT32`, `UINT32`, `INT32`, `UINT16`, `UINT8` at `src/ttnn/device.cpp:37-72`) has a whole-byte `element_size`, so the TTNN pre-fill is pure overhead on every supported leaf width today.

The review's measured CPU asymmetry (24.3 GB/s `copy_from_host` vs 14.3 GB/s `copy_to_host` on the development host for an identical F32 traversal) motivates the removal of this deterministic redundant pass; the magnitude of the removed pass's contribution to that asymmetry is not isolated as a measured causal loss in the review. TTNN's per-download cost drops by one host pass per `copy_to_host`; the magnitude is unmeasured on Tenstorrent hardware and the finding retains its strongly-supported, unmeasured-magnitude status.

The TTNN upload path (`upload_plane` at `src/ttnn/copy.cpp:74-138`) and the CPU upload path (`region_from_host` at `src/cpu/device.cpp:560-643`) do not perform a pre-fill on the destination storage; the per-plane upload writes typed bytes or per-tile-row copy segments directly into the destination without zeroing first. The pre-fill asymmetry exists only on the download direction.

## Scope

- `src/cpu/device.cpp:645-728` (`CpuTensor::region_to_host`) — branch on `bits % 8`. For `bits % 8 == 0` (the byte-aligned case: `bits ∈ {8, 16, 32, 64}` covering `BOOL`, `I8/U8`, `F8_E4M3FN/F8_E5M2/F8_E8M0`, `I16/U16`, `F16/BF16`, `I32/U32`, `F32`, `I64/U64`, `F64`) delete the `std::fill` and the explanatory comment block; let the per-tile walk overwrite every destination byte as the canonical byte-aligned host encoding. For `bits % 8 != 0` (the sub-byte case: `bits ∈ {2, 4, 6}` covering exactly `I2/U2`, `I4/U4/F4_E2M1`, `F6_E2M3/F6_E3M2`) keep exactly one `std::fill_n` of the final byte of the destination buffer, written *before* `for_each_tile` runs so the sub-byte walk then overwrites the destination's logical-bit positions and the trailing unused bits of the final byte read as zero. The guard is overflow-free modular arithmetic that detects whether the total logical bit count leaves a partial trailing byte: `const std::size_t tail_bits = (source.spec().shape.element_count() % 8) * (bits % 8) % 8; if (tail_bits != 0) { std::fill_n(destination.data() + (destination.size() - 1), 1, std::byte{0}); }` — both `% 8` operands and the multiplication are bounded, so the predicate cannot overflow regardless of `element_count`. The fill targets the final destination byte at index `destination.size() - 1` (the destination buffer is sized to `spec.logical_nbytes()` per the §5.4 contract).
- `src/ttnn/copy.cpp:209-229` (`iom::ttnn_detail::region_to_host`) — delete the `std::fill` at `:215` and its explanatory comment block at `:213-214`; let the per-plane `download_plane` writes populate every destination byte. Every supported TTNN leaf has a whole-byte `element_size` (1, 2, or 4 bytes for `UINT8`, `UINT16`/`BFLOAT16`, `UINT32`/`INT32`/`FLOAT32`), so the byte-aligned path suffices on every supported leaf width today and no partial-byte or tail-bit work is required.
- `src/cpu/device.cpp:560-643` (`CpuTensor::region_from_host`) and `src/ttnn/copy.cpp:190-207` (`iom::ttnn_detail::region_from_host`) — no change. These are upload paths; the destination is the owning storage, which the §7 contract allocates uninitialized.
- The shared GPU `synchronous_transfer_impl` (`src/shared/standard_tiled_copy.inl:381-438`) — no change. The shared path already implements the partial-tail-word memset and is the reference behavior.
- `src/cuda/copy.cu`, `src/rocm/copy.hip`, `src/sycl/copy.cpp` — no change. CUDA, ROCm, and SYCL already delegate to the shared `.inl` path; the pre-zero asymmetry is CPU/TTNN-only.
- `test/cpu/test_cpu.cpp:507-568` (`"CPU host writes land in exact tiled slots and reads hide padding"`) — no change required. The case's `readback` vector is pre-filled with `0xAA` (`:561`); the post-fix `region_to_host` overwrites every byte that holds a logical element with its canonical host-encoding byte and leaves the trailing unused bits of the final byte as zero. `read_logical` and `require_logical_bytes` (`test/backend/backend_conformance_common.hpp:137-166`) prefilled the buffer with `kReadbackSentinel{0xAA}` (`:138`) precisely to catch tail-bit regressions — the existing pass on CPU implies the post-fix code still zeros the trailing bits of the final byte in every sub-byte case; that guarantee is preserved by the trailing-byte `std::fill_n` written before the walk.
- `test/cpu/test_cpu_bench.cpp:67` (`copy_to_host` measurement) — no change required. The measurement times `source->view().copy_to_host(host_destination)` over `spec.logical_nbytes()` bytes; the post-fill `host_destination` content is identical to the pre-fill content for every shape and leaf width the bench exercises. The post-fix throughput `to_gigabytes_per_second` will reflect the eliminated pre-fill cost. NT-001 (order 67) owns the throughput floor recalibration; if the floor moves after this task, that recalibration follows NT-001's documented protocol (median of 20 runs, halved, rounded down to 0.1 GB/s, written into the `CHECK_GE` at `test/cpu/test_cpu_bench.cpp:112` with the host/date/medians comment block).
- `test/ttnn/test_ttnn_conformance.cpp` — no change required. The conformance round-trip at `:421-462` already verifies bit-for-bit equality between uploaded and downloaded row-major host buffers via the typed `plane.to_vector<T>()` path; the post-fix download still populates every byte the typed upload wrote. The TTNN download's "zero first" comment at `src/ttnn/copy.cpp:213-214` is deleted alongside the `std::fill` call; the conformance oracle's coverage of the byte-level download contract remains intact.

## Non-goals

- Touching the upload paths (`CpuTensor::region_from_host`, `iom::ttnn_detail::region_from_host`). The asymmetry exists only on the download direction; uploads have no destination-side pre-fill to remove.
- Modifying the shared GPU `synchronous_transfer_impl` partial-tail-word memset (`src/shared/standard_tiled_copy.inl:408-418`). The shared path is the reference behavior CPU and TTNN converge to; the partial-tail-word `Policy::memset` is already minimal.
- Modifying the per-tile walk (`for_each_tile`, `for_each_tile_lockstep`, `copy_tile_row_byte_aligned`, `copy_tile_row_subbyte`). The walk is correct after order 51; this task removes the pre-fill, not the walk.
- Changing the §5.4 host-transfer contract. The post-fix code preserves the host encoding, the span size, the padding exclusion, the error categories, and the synchronous-at-return behavior verbatim. A future "skip the pre-fill on byte-aligned leaves" spec amendment is not proposed here; the contract's "the host encoding is exactly the view's `DataType`" requirement is satisfied by the per-tile walk alone for byte-aligned leaves.
- Introducing a tail-bit-zero branch on TTNN. Every supported TTNN leaf has a whole-byte `element_size`; the partial-byte-zero branch this task adds to CPU is unnecessary on TTNN. A future sub-byte TTNN leaf would belong to a future change that introduces the typed `std::vector<T>` arithmetic for sub-byte sizes.
- Re-baselining `test_cpu_bench.cpp:112` (`copy_to_host` throughput floor) in this task. If the post-fix median moves the floor, the recalibration follows NT-001's documented protocol (median of 20 runs, halved, rounded down to 0.1 GB/s, written into the `CHECK_GE` with the host/date/medians comment block) and is owned by a follow-up change that runs the recalibration procedure.
- Touching CUDA, ROCm, SYCL copy paths. The shared GPU path already implements the partial-tail-word memset and is not affected by this task. The PF-001 SYCL convergence (order 60) consumes the shared `.inl` path; SYCL's download eventually converges to the same behavior.
- Modifying the conformance harness's `kReadbackSentinel{0xAA}` pre-fill or the `read_logical` / `require_logical_bytes` semantics. The pre-fill is the sentinel that catches padding-leak, byte-skip, and tail-bit-set regressions on every backend; this task's prezero removal must satisfy the existing sentinel semantics, not change them.
- Touching the `TTNN conformance: storage oracle identifies perturbed transfer map` case (`test/ttnn/test_ttnn_conformance.cpp:425-447`) or any other conformance oracle. The post-fix TTNN download still populates every byte the typed upload wrote; the existing oracle continues to observe equality.
- Introducing a benchmark, microbenchmark infrastructure, timing hook, or TU-private accessor on the TTNN path. The verification runs only the existing public conformance round-trip on Tenstorrent hardware through `.agents/skills/remote-development`.
- Adding new tests beyond the existing conformance matrix. The existing CPU conformance cases (`test/cpu/test_cpu.cpp:507-568`, `run_storage_and_transfer_conformance`, `run_storage_oracle_conformance`, `run_async_copy_conformance`) and the TTNN conformance round-trip (`test/ttnn/test_ttnn_conformance.cpp:421-462`) are the verification surface; the post-fix code must pass them unchanged.
