# Enforce the standard 16x16 tiled walk on every CPU host transfer and copy

**Order:** 51
**Priority:** P0 — critical standard-layout correctness on the reference backend. The CPU fast path physically violates the engine-defined layout for every tensor whose last dimension is an exact multiple of 16 greater than 16, breaking byte-interoperability with CUDA/ROCm/SYCL storage and silently corrupting model geometry on the very shape class the reference backend is the conformance oracle for.
**Blocked by:** None
**Source:** `docs/changes/0001-tensor-view/review.md` — `CC-001`
**Review severity:** critical
**Review verification:** verified, confidence 95

## Outcome

CPU host transfers (`region_from_host`, `region_to_host`) and the CPU asynchronous copy (`CpuQueue::copy_elements`) write every logical element into its exact standard-layout slot, as defined by `iom::detail::standard_plane_slot` (`src/iom.cpp:147`) and pinned in `docs/changes/0001-tensor-view/spec.md:216-245`. The canonical location of element `[..., row, column]` is the bit offset `detail::standard_plane_slot(spec, plane, row, column) * leaf_bits(type)`. For `DataType` values whose leaf width is a multiple of 8 — every byte-aligned leaf in section 3 (`I8/U8`, `I16/U16`, `I32/U32`, `I64/U64`, `F16`, `BF16`, `F32`, `F64`, plus 8-bit `BOOL` and the 8-bit floating types) — that bit offset is also a byte offset, namely `detail::standard_plane_slot(spec, plane, row, column) * leaf_bits(type) / 8`. For sub-byte widths (`I2/U2`, `I4/U4`, `F4_E2M1`, `F6_E2M3`, `F6_E3M2`, `F8_E4M3FN`, `F8_E5M2`, `F8_E8M0`), the bit offset is exact and any byte-indexed reference below uses the host bit-order defined in spec §3 (least-significant bits first). The walk visits one 16-element tile row at a time; no contiguous run ever spans more than a single 16x16 tile. Round-trip `copy_from_host` → `copy_to_host` remains byte-identical only because both directions share the corrected walk, and CPU storage for every shape in the conformance matrix is bit-identical to the canonical `encode_standard_tiled_storage` reference.

## Current failure

`src/cpu/device.cpp:239-242` (`for_each_tile`) and `:351-357` (`for_each_tile_lockstep`) take the divergent branch when `columns % TensorSpec::TILE == 0` and `columns > 0`. The visitor emits a single row-wide run anchored at `row_byte` — the byte address of row `first_row + row_in_tile`, column 0, inside tile column 0 — and passes `elements = columns` to the consumer. `copy_tile_row_byte_aligned<kElementBytes>` (`src/cpu/device.cpp:97-117`) then issues a contiguous `std::memcpy` of `elements * kElementBytes` bytes from the source row to the destination row. `copy_tile_row_subbyte` (`src/cpu/device.cpp:119-186`) does the same in its `elements > TensorSpec::TILE && total_bits % 8 == 0` branch.

That encoding is correct only when `columns <= TensorSpec::TILE`. For `columns > TILE`, the data the helpers move is one row's worth of logical elements but the destination interval they fill is row bytes `[0..columns*bits/8)` of the row inside tile column 0. Tile column `k+1` begins `TILE * TILE * bits / 8` bytes after tile column `k`, so writing one logical row across multiple tile columns in a single memcpy overwrites the storage that belongs to rows `row + 1` through `row + tile_rows - 1` of tile column 0 while the true tile-1 region is never touched.

The four affected consumers — `region_from_host` (`src/cpu/device.cpp:594-642`), `region_to_host` (`src/cpu/device.cpp:682-727`), and `CpuQueue::copy_elements` (`src/cpu/device.cpp:910-952`) — all route through the same broken visitor, so every CPU host transfer and every CPU queue copy exhibits the defect. The bug is invisible to round-trip tests because both the source and destination use the same wrong walk: the bytes that land in the wrong slot on the way in are read back from the same wrong slot on the way out, so the host buffer round-trips while the on-device storage is corrupt.

Direct storage inspection reproduces the bug for both byte-aligned and sub-byte element widths:

- `[1, 32]` `F32` (leaf_bits = 32, byte-aligned): element pattern `1000 + i` writes element 16 with the expected bit pattern whose little-endian 4-byte representation equals `1016` (`0x000003F8`). The broken contiguous path encodes element 16 at the bit offset `16 * 32 = 512` (byte offset 64, the start of slot 16 inside tile column 0); the canonical path encodes it at bit offset `256 * 32 = 8192` (byte offset 1024, the start of slot 256 inside tile column 1). Direct storage inspection reads `storage[64..67]` (the broken-path 4-byte window) and `storage[1024..1027]` (the canonical 4-byte window), decodes both as little-endian `F32` via `std::memcpy` into a `float` and `std::bit_cast`/comparison against the expected bit pattern `0x000003F8`, and confirms only the canonical window decodes to `1016`. Pre-fix, the broken-window decode yields `1016` and the canonical-window decode yields `0`; post-fix, the broken-window decode yields `0` (or its pre-write sentinel) and the canonical-window decode yields `1016`.
- `[1, 32]` `I4` (leaf_bits = 4, sub-byte): element 16 is the 17th nibble of the row-major host bit stream. The broken contiguous path places its 4 bits at bit offset `16 * 4 = 64` (byte 8, low nibble, since section 3 writes each element least-significant bits first); the canonical path places them at bit offset `256 * 4 = 1024` (byte 128, low nibble, byte-aligned because 1024 is a multiple of 8). Direct inspection reads the low nibble of `storage[8]` and `storage[128]` and confirms only the canonical nibble equals the expected pattern; pre-fix the broken nibble equals it and the canonical nibble is the pre-write sentinel (or zero), post-fix vice versa.

- The defect is CPU-only. `src/shared/standard_tiled_copy.inl:71-96,140-186` (CUDA/ROCm word kernels) and `src/sycl/copy.cpp:74-86` map every element/word through the canonical slot and are bit-identical to the spec. The CPU storage is therefore byte-incompatible with every accelerator backend for the same spec, breaking future direct-storage paths (mapped weight upload into tiled storage, cross-backend staging, compute kernels on CPU tensors). The 41-PF-001 bench throughputs (24.3 / 85.6 GB/s `F32`, 19.5 GB/s `I4`) measure the invalid contiguous path and will drop after the fix; their re-baseline is owned by `docs/changes/0001-tensor-view/67-NT-001-stabilize-cpu-benchmark-gates` (41-PF-001 is the historical source of the broken code path only and does not own the gates).

## Scope

- Remove the `columns % TensorSpec::TILE == 0` whole-row run from `for_each_tile` (`src/cpu/device.cpp:239-242`) and `for_each_tile_lockstep` (`src/cpu/device.cpp:351-357`). The remaining per-tile-column loop already handles `columns` that are exact multiples of `TensorSpec::TILE`: `tile_columns = columns / TensorSpec::TILE`, every inner iteration consumes a full `TensorSpec::TILE` elements, and the offset `row_byte + tile_column * tile_bytes` (and `destination_tile_row_byte + tile_column * destination_tile_bytes`) is the canonical slot for that tile column's row start.
- Add an exact `assert(elements <= TensorSpec::TILE)` as the first statement of `copy_tile_row_byte_aligned<kElementBytes>` (`src/cpu/device.cpp:97-117`) and as the first statement of `copy_tile_row_subbyte` (`src/cpu/device.cpp:119-186`), so the cross-tile contiguous `memcpy` branches cannot fire again. The byte-aligned helper's existing fast path (`elements >= TILE`) is the original bug source; the production `assert` makes the invariant an immediate runtime contract and the helpers' per-element loop becomes the only remaining path.
- Keep the `tile_columns` and `tile_rows` calculations (`src/cpu/device.cpp:197-202` and `:275-280`) intact — they are already correct and the per-tile-column loop depends on them.
- Update the `row_runs_per_plane` and `callbacks_per_plane` accounting in `region_from_host` (`src/cpu/device.cpp:574-580`) and `region_to_host` (`src/cpu/device.cpp:662-668`) so the host-bit index uses the same number of callbacks per plane that the corrected visitor emits. Today both sites precompute `row_runs_per_plane = columns % TILE == 0 ? 1 : tile_columns`, which assumes the broken visitor emits one callback per row. With the broken branch removed, every callback visit corresponds to one 16-element tile-row slice, so `row_runs_per_plane = tile_columns` unconditionally and `callbacks_per_plane = rows * tile_columns`.
- No change to `for_each_tile_lockstep`'s `identical_layout` short-circuit (`src/cpu/device.cpp:289-296`) — it is a separate early-out unrelated to the row-run predicate.
- No change to the public `Device`, `Tensor`, `TensorView`, `Allocator`, `DeviceOps`, `TensorSpec`, `TensorShape`, or `iom::detail::standard_plane_slot` API.

## Requirements

1. `for_each_tile` and `for_each_tile_lockstep` must not emit any row callback whose `elements` argument exceeds `TensorSpec::TILE`. The `columns % TensorSpec::TILE == 0` early-return branch is deleted in both visitors; every row inside the per-row loop enters the existing per-tile-column loop unconditionally.
2. `copy_tile_row_byte_aligned<kElementBytes>` must begin with an exact `assert(elements <= TensorSpec::TILE)` (using the C standard-library `<cassert>` macro; no `REQUIRE`, `CHECK`, custom debug macro, or conditional wrapper) before either the byte-aligned fast path or the per-element loop runs. The byte-aligned `elements >= TILE` fast path becomes unreachable; the per-element loop is the only remaining execution path.
3. `copy_tile_row_subbyte` must begin with an exact `assert(elements <= TensorSpec::TILE)` (same `<cassert>` form). The `elements > TensorSpec::TILE && total_bits % 8 == 0` contiguous branch is deleted; only the word-aligned whole-word path and the bit-by-bit fallback remain, and both are valid for `elements <= TILE`.
4. `region_from_host` and `region_to_host` must compute `row_runs_per_plane = tile_columns` and `callbacks_per_plane = rows * tile_columns`; the `columns % TILE == 0 ? 1 : tile_columns` ternary is deleted. Every per-plane callback index increments monotonically from zero and `host_bit = (plane_index * elements_per_plane + row * columns + column) * bits` resolves to the canonical slot for the current `(plane, row, column)` triple.
5. The corrected walk, byte for byte, must match `iom::detail::standard_plane_slot` for every shape in the conformance matrix. The minimal regression in `test/cpu/test_cpu.cpp` asserts this on `[1, 32]` `F32`, `[1, 32]` `I4`, and `[2, 3, 16, 48]` `U8` after both a host write followed by direct byte inspection and a queued copy followed by direct byte inspection.
6. `CpuQueue::copy_elements` continues to consume the corrected `for_each_tile_lockstep` visitor; it does not gain a separate walk and does not re-introduce a row-wide `memcpy`. The per-tile-row writes it performs are byte-equivalent to the corresponding `region_to_host` → `region_from_host` round trip on the same shape.
7. The removal does not alter `for_each_coordinate` (`src/cpu/device.cpp:387-415`) or `plane_at` (`:417-436`); those are the view-coordinate enumerators used by validation and are not on the broken path.
8. CUDA, ROCm, SYCL, and TTNN storage and copy paths are not modified. CPU storage for the corrected shapes must be byte-identical to CUDA/ROCm/SYCL storage for the same spec, as the existing CUDA conformance driver (`test/cuda/test_cuda_conformance.cpp`) checks via `AcceleratorStorageOracle`.
9. The corrected CPU walk preserves the existing exception categories: an unknown byte-aligned width still throws `std::invalid_argument` from the same call sites; no new exceptions or categories are introduced.
10. The `assert(elements <= TensorSpec::TILE)` in `copy_tile_row_byte_aligned` and `copy_tile_row_subbyte` is the production runtime contract: in non-`NDEBUG` builds it fires immediately on any cross-tile call; in `NDEBUG` builds it compiles out, but the helpers' only remaining copy path is the per-element loop, so correctness is preserved by construction rather than by a single test-time guard.

## Non-goals

- Modifying `test/backend/backend_conformance_copy_storage.hpp` or any other shared conformance harness file. Adding `{16, 32}` and `{2, 3, 16, 48}` to `transfer_owner_shapes`, `copy_owner_shapes`, and `storage_oracle_owner_shapes` is owned by CC-002.
- Re-baselining `test_cpu_bench.cpp:115` throughput or absolute-latency thresholds, or touching the historical 41-PF-001 throughput floors. Bench gate ownership (the `iom_cpu_bench` target's pass/fail contract on the reference host, including the post-CC-001 honest re-measurement) belongs to `docs/changes/0001-tensor-view/67-NT-001-stabilize-cpu-benchmark-gates`. 41-PF-001 is the historical source of the broken code path this task fixes and is not a current owner of any artifact in this spec. This task restores layout correctness; the bench gate may go from deterministic-red to re-baselined in 67-NT-001 once this task lands.
- Touching `iom::detail::standard_plane_slot`, `iom::detail::standard_layout_slot`, or `encode_standard_tiled_storage` in `src/shared/`. The layout helpers are the reference; only the walk that consults them is fixed.
- Touching CUDA, ROCm, SYCL, or TTNN backends. The review confirms those paths already encode the correct layout.
- Introducing a contiguous-run optimization for any future "wide-row" case. The smallest structural correction deletes the divergent encoding entirely; re-introducing any equivalent fast path would re-introduce the same risk and is out of scope.
- Changing public APIs, header paths, allocator interfaces, or the `Tensor`, `TensorView`, `Device`, or `DeviceOps` declarations.
- Modifying `test_iom.cpp`, `test_cpu_conformance.cpp`, or any other test file outside the minimal `test/cpu/test_cpu.cpp` regression declared in this spec. CC-002 expands the matrix; this task adds only the local regression that proves the corrected walk.
- Performance work unrelated to the bug. The corrected walk visits more callbacks than the broken walk (one per tile column rather than one per row); that is the cost of correctness.

## Acceptance criteria

- [ ] `for_each_tile` no longer contains a `columns % TensorSpec::TILE == 0` early-return; the only execution path through the per-row loop is the existing per-tile-column loop, and every callback passes `elements <= TensorSpec::TILE`.
- [ ] `for_each_tile_lockstep` no longer contains the corresponding `columns % TensorSpec::TILE == 0` early-return; the only execution path is the existing per-tile-column loop, and every callback passes `elements <= TensorSpec::TILE` with `source_byte` and `destination_byte` differing by `destination_tile_bytes` from tile column to tile column.
- [ ] `copy_tile_row_byte_aligned` and `copy_tile_row_subbyte` both begin with the exact production `assert(elements <= TensorSpec::TILE)` from `<cassert>`. The byte-aligned `elements >= TILE` contiguous branch and the sub-byte `elements > TensorSpec::TILE && total_bits % 8 == 0` contiguous branch are deleted and unreachable from the corrected callers.
- [ ] `region_from_host` and `region_to_host` use `row_runs_per_plane = tile_columns` and `callbacks_per_plane = rows * tile_columns`; the ternary form is deleted.
- [ ] Direct storage inspection on `[1, 32]` `F32` after `view.copy_from_host` reads `storage[1024..1027]` (the canonical 4-byte window of slot 256, the canonical slot of element `(0, 16)`) and `storage[64..67]` (the broken-path window at slot 16 inside tile column 0); `std::memcpy` of the canonical window into a `float` decodes to the element value `1016`, and `std::memcpy` of the broken-path window decodes to the pre-write sentinel (or zero). The same inspection on `[1, 32]` `I4` reads the low nibble of `storage[128]` (canonical bit offset 1024 for element 16) and confirms it equals the expected pattern, and reads the low nibble of `storage[8]` (broken-path bit offset 64 for element 16) and confirms it equals the pre-write sentinel (or zero).

- [ ] `CpuQueue::copy` round trip on `[1, 32]` `F32` from a source tensor through a destination tensor produces destination storage whose every byte equals the corresponding source byte at the canonical slot. The previously byte-identical-but-locally-wrong round trip remains byte-identical because the corrected walk agrees with itself in both directions; the difference is that the bytes are now at the canonical slots rather than at the cross-tile contiguous positions.
- [ ] All `test/cpu/test_cpu.cpp` cases in the layout, host-transfer, and asynchronous-copy sections still pass, including the existing `[3, 20, 18]` `I16` case and the padded `{17, 33}` and `{2, 3, 17, 33}` cases.
