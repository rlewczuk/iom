# Slim the outstanding-work registry to its two production queries and opt synchronous CPU out of registration

**Order:** 61
**Priority:** P1 — required simplification and per-copy host-overhead reduction on the shared lifetime machinery; gates no correctness work but must land before AR-002 shares the destructor glue so the helper is written against the final registry shape
**Blocked by:** `55-ST-001-harden-sycl-queue-lifetimes`, `57-ST-003-rollback-registry-index-insertion`
**Source:** `docs/changes/0001-tensor-view/review.md` — `AR-003`
**Review severity:** medium
**Review verification:** verified, confidence 88

## Outcome

`iom::detail::OutstandingWorkRegistry` holds exactly two indexes — `std::map<EntryId, Entry> by_id_` and `std::multimap<void*, EntryId> by_address_` — serving the only two production queries: "entries at address" (tensor destructors) and "entries of a queue" (queue teardown, now a single bounded scan of `by_id_`). The production-dead sequence index, its `invalidate_entries_for_sequence` API, and the test that exercised that dead function are gone; `sequence` survives as an unindexed diagnostic field. `EntrySnapshot` is an alias of `Entry`. The hand-rolled intrusive quarantine list is a `std::vector<std::unique_ptr<CleanupAction>>` whose `add` pins the by-value `unique_ptr` so any `std::bad_alloc` from vector growth (or a future throwing step on the protected section) is converted into a deliberate process-lifetime leak of the action node and its owned resources — never into a stack-unwinding `unique_ptr` destruction that would invoke `~CleanupAction` and bypass the deferred-release protocol for TTNN's native plane vector or any in-flight CUDA/ROCm/USM handle inside `AllocatorCleanupAction`. The header lives at `include/iom/detail/outstanding_work_registry.hpp`, out of `IOM_HEADERS`. CPU registers nothing: `CpuQueue::execute` runs the copy synchronously on the submitting thread, so per-copy registration was provably pure overhead — a queued CPU copy no longer allocates registry nodes, fence copies, or an outcome record, while every observable token, failure, teardown, and destructor behavior is unchanged. ST-003's strong exception-safety invariant survives on the reduced index set, and the CUDA/ROCm/TTNN/SYCL 49-ST-003/55-ST-001 teardown and destroy-before-wait regressions pass unchanged.

## Current failure

The registry introduced by 49-ST-003 (`include/iom/outstanding_work_registry.hpp`, 514 lines) maintains four multimaps (`by_id_`, `by_address_`, `by_sequence_`, `by_queue_` at `:455-459`) for a structure with two real production queries. The consumer grep found only `snapshot_for`, `try_release_entry`, `invalidate_entries_for_queue`, `invalidate_entries`, `remove_entries`, and `remove_entry_if_present` in production; `invalidate_entries_for_sequence` (`:297-312`) and its `by_sequence_` index plus `erase_sequence_index_locked` (`:389-398`) have no production caller — the only caller is `test/test_iom.cpp:2123`, so the dead sequence path can rot invisibly behind a test of a function nothing ships. `EntrySnapshot` (`:180-187`) repeats `Entry` (`:171-178`) field-for-field. `Quarantine` (`:115-167`) is a 53-line hand-rolled intrusive list (`CleanupAction::next_` + a `size()` observer with zero callers).

Every queued copy pays for the over-build: two entries × four multimap nodes plus the per-queue `outcomes_` map node plus two `std::function` fence copies ≈ 9–14 small allocations and ~10 lock operations per submission (PF-003 owns the full accounting; this task owns the structure). On CPU the registration is pure waste: `detail::StagedWorker::submit_copy` (`include/iom/iom.hpp`) invokes `execute` on the submitting thread and only publishes after it returns, and `CpuQueue::execute` (`src/cpu/device.cpp:834-862`) runs `copy_elements` to completion *before* registering two entries with a no-op success fence (`cpu_detail::completed_fence()`), staging a `SequenceOutcome`, and later releasing both IDs from `complete_task` (`:869-889`). There is never in-flight CPU work for an entry to guard — the destructor snapshots entries whose fences trivially succeed and frees exactly as it would with an empty registry.

Placement compounds this: the header is listed in `IOM_HEADERS` (`CMakeLists.txt:85`) although everything in it lives in `iom::detail`, 49-ST-003 created it as private shared machinery (requirement 13: no public header gains registry accessors), and no public header includes it — while the established internal-header convention (`include/iom/detail/aligned_storage.hpp`) already exists one directory away. Maintainers hold four insert/erase consistency invariants for indexes that serve nothing. The quarantine container also creates a lifetime-correctness contract violation risk for any future throwing operation on its protected section: the intrusive list's `add` is `noexcept`, but the proposed `std::vector<std::unique_ptr<CleanupAction>>` growth path is not, and stack-unwinding destruction of the by-value `unique_ptr` parameter would invoke `~CleanupAction` on `TtnnNativeCleanupAction` (freeing native plane tensors without the deferred-release protocol) or on `AllocatorCleanupAction` (calling `allocator_.free` while quarantine is the gatekeeper). 58-ST-004 locks down the construction-failure case via `noexcept` `add`; this task must pin the recording-failure case the same way or accept silent UB on the resource the post-58 quarantine protocol exists to protect.

## Scope

- **Registry shape:** reduce `OutstandingWorkRegistry` to `by_id_` + `by_address_` under the existing single mutex. Delete `by_sequence_`, `by_queue_`, `erase_sequence_index_locked`, and `invalidate_entries_for_sequence`. `Entry` keeps `sequence` (unindexed diagnostic field); `register_entry`'s validation — including the non-zero-sequence check — is unchanged.
- **Queue teardown:** `invalidate_entries_for_queue(QueueId)` keeps its signature, `noexcept`, and zero-id no-op behavior; its body becomes one locked scan of `by_id_` invalidating entries whose `queue_id` matches. `invalidate_entry_locked` keeps marking `EntryState::Invalidated` and swapping the fence for `&failed_invalidated_fence`, and stops erasing any sequence index. `erase_entry_locked` erases the matching `(address, id)` pair from `by_address_`, then the `by_id_` node, and stays `noexcept`.
- **ST-003 invariant:** after the `by_id_` emplace, one `try` encloses the `by_address_.emplace`; its handler erases the `by_id_` node through the emplace iterator and rethrows. A failed `register_entry` still leaves the registry observably unchanged (empty `snapshot_for`, `try_release_entry(id) == false`, identical re-registration accepted).
- **Snapshot type:** `using EntrySnapshot = Entry;` replaces the duplicate struct; `snapshot_for` copies `Entry` values directly. All four existing tensor-destructor bodies (`src/cpu/device.cpp:511-553`, `src/cuda/device.cpp:176-220`, `src/rocm/device.cpp:156-200`, `src/ttnn/device.cpp:273-318`) and 55-ST-001's SYCL destructor compile unchanged against the alias.
- **Quarantine:** replace the intrusive list with `std::vector<std::unique_ptr<CleanupAction>>` behind the existing mutex. `CleanupAction` loses `next_` and the `friend class Quarantine` declaration. `add(std::unique_ptr<CleanupAction>)` takes the action by value, locks the mutex, and performs `push_back` inside one `try` block whose `catch (...)` does exactly `(void)action.release();` and then rethrows — converting any growth allocation failure (or any future throwing step on the protected section, including a throwing `CleanupAction` move) into a deliberate process-lifetime leak of the action node and its owned resources, never into stack-unwinding `unique_ptr` destruction that would invoke `~CleanupAction` and bypass the quarantine's deferred-release protocol. `emplace<Action>(Args&&...)` forwards through `add`. The unused `size()` observer is deleted. `drain() noexcept` keeps running each action outside the lock, keeps draining actions added while a drain is in progress, and preserves today's LIFO run order (reverse iteration over each swapped batch). The post-58 swallow-and-leak invariant is the umbrella over both "could not construct the action" (TTNN path 58 unifies) and "could not record the action in the quarantine" (the vector-growth path this task pins); both cases must appear in the umbrella-spec exception wording alongside the success case (parent-spec handoff for `62-AR-002` to record the umbrella-spec edit through the AR-002 contract).
- **Header placement:** move `include/iom/outstanding_work_registry.hpp` to `include/iom/detail/outstanding_work_registry.hpp` (the `aligned_storage.hpp` convention); its `#include "alloc.hpp"` becomes `#include "iom/alloc.hpp"` matching that sibling. Remove the `include/iom/outstanding_work_registry.hpp` line from `IOM_HEADERS` (`CMakeLists.txt:85`); do not add the detail path to `IOM_HEADERS`. Update every includer: `src/cpu/registry_state.hpp`, `src/cuda/registry_state.hpp`, `src/rocm/registry_state.hpp`, `src/ttnn/registry_state.hpp`, the `src/sycl/registry_state.hpp` created by 55-ST-001, and `test/test_iom.cpp:28`.
- **CPU opt-out:** `CpuQueue::execute` reduces to `if (!task.no_op) copy_elements(task.source, task.destination);`. Delete the registration/rollback block, the `SequenceOutcome` struct, `outcome_mutex_`, `outcomes_`, `complete_task` (the worker's complete callback calls `complete(sequence, std::move(failure))` directly), `Task::source_entry_id`/`Task::destination_entry_id`, the `state_` and `registry_queue_id_` members, the `allocate_queue_id` lease in the constructor, and `~CpuQueue`'s `invalidate_entries_for_queue` call (nothing can be registered). `CpuRegistryState` reduces to `{ detail::OutstandingWorkRegistry registry; detail::Quarantine quarantine; }`; delete its `next_entry_id`, `next_queue_id`, `allocate_queue_id`, `register_copy_entries`, and `completed_fence`. `CpuDevice` keeps `registry_state_`, the accessor, `~CpuTensor` (snapshot on an always-empty registry → direct free, quarantine path intact as the no-throw defense), and `~CpuDevice`'s drain.
- **Accelerators:** CUDA, ROCm, TTNN, and SYCL keep registration, completion, and teardown call sites unchanged — they compile against the reduced API (`snapshot_for`, `try_release_entry`, `invalidate_entries`, `invalidate_entries_for_queue`, `remove_entry_if_present`, `remove_entries`, `register_registry_entries` all survive).

## Requirements

1. `OutstandingWorkRegistry` stores exactly `mutable std::mutex mutex_; std::map<EntryId, Entry> by_id_; std::multimap<void*, EntryId> by_address_;`. No other index exists. `register_registry_entries` (`:488-512`), `allocate_registry_queue_id`, `EntryRegistration`, `Fence`/`FenceResult`, and `AllocatorCleanupAction` are unchanged.
2. `register_entry` keeps all argument validation and the duplicate-id check before mutation; after `by_id_.emplace` succeeds, a single `try` wraps the `by_address_.emplace` and its `catch (...)` does exactly `by_id_.erase(entry_it); throw;`. With one secondary index there is no nested ladder. `erase_entry_locked` remains the only other erase path and stays `noexcept`.
3. `invalidate_entries_for_queue` performs one locked pass over `by_id_` and calls `invalidate_entry_locked` on every entry with a matching `queue_id`. Cost is bounded by genuinely outstanding entries and paid once per queue lifetime. Zero `queue_id` remains a no-op; `Invalidated` entries keep their `by_address_` pairs so later tensor destructors still quarantine (49-ST-003 requirement 5).
4. `snapshot_for` returns `std::vector<Entry>` (via the `EntrySnapshot` alias) by copying the `Entry` values; the address-index consistency `std::logic_error` guard is kept.
5. `Quarantine::add(std::unique_ptr<CleanupAction>)` ignores null inputs, otherwise locks the mutex, then enters a single `try` block:
   ```
   try {
       actions_.push_back(std::move(action));
   } catch (...) {
       (void)action.release();
       throw;
   }
   ```
   After the `push_back` succeeds the function returns; on any exception (vector growth allocation failure today, or a throwing move/assignment tomorrow) the by-value `unique_ptr` parameter has its stored pointer released back to it without destruction — the action node becomes a deliberate process-lifetime leak, preserving every resource it owns (native plane vectors, USM handles, allocator free paths, etc.) outside the quarantine's gatekeeper. The `try` encloses exactly the `push_back`; the release is the only statement in the `catch` besides `throw`. The function is not `noexcept`.
6. `Quarantine::emplace<Action>(Args&&...)` forwards its arguments to `std::make_unique<Action>(std::forward<Args>(args)...)` and passes the result to `add`, inheriting the same pinning and rethrow semantics for the action-node construction failure case that 58-ST-004 already covers for the caller.
7. `Quarantine::drain() noexcept` loops: swap the vector out under the lock (return when empty), run each action in reverse insertion order outside the lock, repeat — so actions added while an action runs are still drained exactly once. `size()` is deleted.
8. The moved header uses `#pragma once`, includes `"iom/alloc.hpp"`, and is included everywhere as `"iom/detail/outstanding_work_registry.hpp"`. `IOM_HEADERS` no longer names it, no public `include/iom/*.hpp` includes it, and the public `Device`/`Tensor`/`DeviceOps`/`Allocator` surfaces are untouched.
9. CPU: a queued copy consumes no registry allocation, no `std::function` copy, and no outcome record; tokens, retained failures, no-op identical-window handling, unsupported rejections, sequence leasing, and `shutdown_and_drain` completion are observably identical. `Task::fence` stays (always null) because `StagedWorker::process` reads it.
10. CPU: `~CpuTensor` and `~CpuDevice` are not edited; the destructor still snapshots the now-always-empty registry and falls back to quarantine on snapshot failure, and the drain still runs — AR-002 consolidates these bodies into the shared helper afterward, and the empty-entry case is exactly what that helper must handle.
11. CUDA/ROCm/TTNN/SYCL behavior is byte-for-byte unchanged on every non-faulting and faulting path except allocation count: same registration, completion, invalidation, quarantine, and teardown ordering. 57-ST-003's rollback semantics hold on the two-index shape.

## Non-goals

- The shared `detail::release_or_quarantine` destructor helper and collapsing `src/{cpu,cuda,rocm}/registry_state.hpp` — AR-002 (`62-AR-002`, order 62) owns that against this task's final shape; the four destructor bodies stay untouched here.
- Remaining submission-overhead measurement, `std::function` fence copies, per-queue `outcomes_` maps on accelerators, and latency gates — PF-003 owns the cost accounting; this task contributes only the structure removal and a before/after CPU bench comparison.
- Quarantine allocation-failure policy (TTNN's terminate-vs-leak alignment) — 58-ST-004 owns it; this task preserves every caller's existing swallow-and-leak catch and only changes the container, and 58's umbrella-spec wording statement about "could not construct the action" is updated by AR-002 (order 62) to also cover "could not record the action in the quarantine" per the parent-spec handoff above.
- `fence_destroy` synchronization (ST-002/56), CUDA/ROCm pool/metadata extraction (AR-004/63), SYCL kernel/staging convergence (AR-001/60), and the remaining dead accelerator queue/pool fields (`SequenceOutcome::fence_succeeded` on CUDA/ROCm/TTNN, `Task::{source,destination}` views, staging-pool members — AR-006/65).
- Re-adding a gated or opt-in CPU registration hook "until async CPU work exists": the plain opt-out is the smaller design; re-registration is a future change when CPU gains genuinely asynchronous work.
- Deleting `allocate_registry_id` (zero callers, but not part of this finding's remediation list) or changing any registry error categories, validation, or `Entry` field semantics beyond de-indexing `sequence`.
