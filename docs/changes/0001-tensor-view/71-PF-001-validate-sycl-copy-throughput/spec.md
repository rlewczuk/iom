# Validate SYCL plane-count-independent submission with a durable smoke regression and record before/after transfer throughput via a throwaway driver

**Order:** 71
**Priority:** P2 — required measurement/falsification closure for the architecture remediation: task 60 removes four code-deterministic SYCL data-movement overheads, but no launch-observation point existed to prove the single-submit invariant and no SYCL runtime was available to the review; this task closes the code-deterministic side durably and records the timing side as evidence.
**Blocked by:** `60-AR-001-converge-sycl-copy-architecture`
**Source:** `docs/changes/0001-tensor-view/review.md` — `PF-001`
**Review severity:** medium
**Review verification:** strongly-supported (mechanisms code-deterministic; magnitudes unmeasured — no SYCL runtime on this host), confidence 85

## Outcome

The code-deterministic half of PF-001's verification method is closed durably: a test-only kernel-launch observation seam in the SYCL backend backs a focused regression asserting that one non-identical queued copy enqueues exactly one kernel regardless of leading-plane count and zero kernels for an identical window, joined to the existing `iom_sycl_smoke_tests` target. No CMake file, no `test/sycl/test_sycl_bench.cpp`, no `iom_sycl_bench` ctest target is added — a permanent always-green throughput ctest would be tautological given the finding's unmeasured status and the project's no-absolute-thresholds policy. The magnitude half is captured as evidence via a throwaway throughput driver authored under `_local/`, synchronized to the remote SYCL host with the `sycl` profile, run on the pre-convergence revision and on the post-convergence tree under identical conditions, and recorded in the completion evidence (the deliverable's only throughput record). The throwaway driver and its binary are removed at cleanup; the durable deliverables are the seam, the smoke case, and the recorded numbers.

## Current failure

Invariant (review PF-001): SYCL data movement must approach the design's near-DMA weight-upload goal (`docs/design/README.md:39`) with word-granular kernels, pooled staging, and plane-count-independent submission — the standard CUDA/ROCm already meet via `src/shared/standard_tiled_copy.inl` and the slot/stream pools.

Task 60's outcome removes the four deterministic overheads the review cites at the pre-convergence lines — per-call `sycl::queue` construction plus per-call `malloc_shared`/`sycl::free` (`src/sycl/copy.cpp:197-245`, specifically `:202-204`, `:213`, `:244`), the full-size shared-staging memset on every download (`:225`), per-bit element access including per-bit `sycl::atomic_ref` serialization for sub-byte types (`:88-99`, `:101-129`), and per-plane submits fed by O(plane-count) host vectors on queued copies (`:275-278`, `:301-331`). Task 60 deliberately excludes the measurement side (its non-goals: "PF-001 measurement: no CPU (or GPU) benchmark harness, throughput thresholds, or launch-count timing claims; byte-exact conformance and static audits are the gates"). Consequently, after 60 lands:

- nothing observes kernel-launch counts: `SyclQueue`'s kernel submissions are invisible outside the backend, so the "one submit per queued copy regardless of plane count" claim of 60 requirement 2 has no executable check;
- a regression that quietly reintroduces per-plane submits or per-call staging would pass every byte-exact conformance case and every static grep until someone re-reads the source;
- no SYCL throughput number exists anywhere in the repository, so the magnitude half of the review's verification method ("transfer GB/s for F32 4096×4096 and I4 2048×2048 before/after") cannot be addressed without measurement.

The review recorded no magnitudes because no SYCL runtime was available on the review host. The honest way to retain that status is to record what is measured without inventing a threshold — and the only ctest-grade durable artifact is the launch-count assertion, which is code-deterministic. Throughput is recorded once as evidence (no threshold, no committed ctest target, no permanent TU).

## Scope

- **Launch-observation seam (test-only):** `src/sycl/runtime.hpp` gains a `LaunchCalls { void (*kernel_launched)() = nullptr; }` struct beside `ContextCalls`, with `extern LaunchCalls launch_calls;` defined once in `src/sycl/device.cpp` next to `context_calls`. `src/sycl/copy.cpp` includes `"runtime.hpp"` and invokes the null-checked hook exactly at every `parallel_for` submit site — the queued-copy single launch inside `execute` and each host-transfer scatter/gather launch wrapper. The hook is inert by default (one predictable null test per launch, no call, no state), mirrors the existing unconditional SYCL seam convention (not CUDA's `IOM_ENABLE_TESTING` gate), and changes no kernel structure, launch syntax, or submission behavior. This is the only backend edit, and it is diagnostic, not architectural.
- **Launch-count regression (durable):** one new `TEST_CASE("SYCL queued copy submits one kernel regardless of plane count")` in `test/sycl/test_sycl_smoke.cpp`, using a probe counter and RAII restore mirroring the file's `ContextProbe`/`ContextCallsRestore` pattern. Assertions, each scoped by resetting the counter around one `copy` → `wait` window:
  - a rank-2 F32 `{16, 16}` non-identical queued copy (1 leading plane) counts exactly 1 kernel launch;
  - a rank-4 F32 `{2, 32, 32, 64}` non-identical queued copy (64 leading planes — the review's `[1,4096,32,128]`-class geometry reduced to a fast deterministic footprint) counts exactly 1 kernel launch;
  - the two counts are equal, proving plane-count independence directly;
  - an identical-window copy (`queue->copy(view, view)`) counts exactly 0 launches;
  - every copied window is verified byte-exact after its count is read, so the count assertion cannot coexist with wrong data.
  On the pre-convergence architecture this case fails with a count equal to the plane count (64 for the rank-4 shape), established by the per-plane submit loop the review cites at `src/sycl/copy.cpp:301-331`; the seam does not exist on that revision, so the pre-fix failure mode is fixed by source inspection of that loop, not by running the case there.
- **Throwaway throughput driver (evidence, not durable):** a `_local/sycl_throughput.cpp` program written for this task, synchronized to the remote SYCL host via `remote-sync` (which propagates `_local/` as the sole non-versioned path), compiled there with the DPC++ driver directly against the built `libiom_sycl.a` and `libiom.a` static archives (no CMake touch), and run under exclusive device access to capture the same six throughput metrics on the pre-convergence and post-convergence revisions. The driver is honest about its plumbing: it uses public `iom::Tensor`/`TensorView`/`Device`/`DeviceOps` operations for every measured op (`copy_from_host`, `copy_to_host`, `queue->copy`, `queue->wait`), and reaches only the test-fixture seam `iom::sycl_detail::context_calls.context_ready` (declared in `src/sycl/runtime.hpp`, the same seam the in-tree conformance and smoke drivers use to bind a `SyclAllocator` to a freshly-created context) to wire the USM allocator. The driver is removed by the cleanup step of the verification protocol; nothing is committed.
- **Conformance unchanged:** `iom_sycl_smoke_tests`, `iom_sycl_conformance_tests`, and `iom_tests` pass on hardware with their existing case coverage; this task adds one smoke case and the throwaway driver, and edits no `test/CMakeLists.txt`, no shared harness file under `test/backend/`, no root `CMakeLists.txt`, and no `src/<backend>/CMakeLists.txt`. SYCL library/target wiring remains exactly where task 60 leaves it (in root `CMakeLists.txt` and `test/CMakeLists.txt`, with the global DPC++ compiler gate at `CMakeLists.txt:39-52` — explicitly deferred by task 60's non-goals and therefore not relocated here).
- **Honesty constraint:** the strongly-supported/unmeasured review status is preserved. No throughput promise is invented; the expected observation and the failure action below define what confirmation and falsification mean for this task.

The header contains exactly one `#ifdef IOM_PF001_BASELINE` branch with this content and nothing else:

  ```cpp
  #pragma once
  // PF-001 baseline-only compile fallback. Defined only on the pre-convergence
  // revision (passed via -DIOM_PF001_BASELINE on the compile command). The
  // post-fix tree does NOT define this macro and the header expands to nothing,
  // so the driver compiles unchanged against the converged LaunchCalls seam.
  #ifdef IOM_PF001_BASELINE
  #include "../src/sycl/runtime.hpp"   // exposes context_calls (55-ST-001 seam).
  // The pre-convergence SYCL backend has no LaunchCalls seam (it is added by
  // this task, order 71; task 60 converges the kernel/staging architecture
  // and leaves the launch sites this task instruments). Provide a no-op local adapter the driver can call identically
  // on both trees; the adapter is _local/-scoped (declared static inline at
  // namespace scope here) and never reaches the in-tree backend. The adapter
  // name must match the driver's `#ifdef IOM_PF001_BASELINE` call site.
  namespace pf001_baseline_compat {
      inline void notify_launch_observed() noexcept { /* no-op on pre-60 */ }
  }
  #endif // IOM_PF001_BASELINE
  ```

  The header does **no symbol verification**, **no `static_assert` on public ops**, and **no machine-checked equivalence claim** — a preprocessor shim cannot verify symbols at compile time, and the same-source claim is explicitly NOT made (see "What the adaptation does NOT claim" below). Its single purpose is to give the driver a documented, named fallback symbol so the baseline compile does not need to reach the in-tree backend's launch infrastructure that does not yet exist there.

  **What the adaptation does NOT claim:** the driver source is **not** identical on both trees. The driver uses `#ifdef IOM_PF001_BASELINE` to choose between two code paths that both go through public operations on both trees. On the post-fix tree, `IOM_PF001_BASELINE` is undefined and the driver calls the in-tree `launch_calls.kernel_launched()` seam added by this task (for instrumented timing, identical to what the smoke case does). On the baseline tree, `IOM_PF001_BASELINE` is defined and the driver calls `pf001_baseline_compat::notify_launch_observed()` instead, which is a no-op — the baseline therefore does not measure launch counts (it cannot, the seam does not exist), it measures wall-clock throughput only. Every measured transfer operation (`make_sycl_device`, `create_tensor`, `copy_from_host`, `copy_to_host`, `create_ops`, `queue->copy`, `queue->wait`, `context_calls.context_ready`) is unchanged across both trees because task 60's non-goals explicitly leave the public header surface and the 55-ST-001 seam family alone — only the launch-observation hook is gated by `#ifdef IOM_PF001_BASELINE`.

  The two compilations therefore differ **only** by the documented baseline fallback: the post-fix compile uses `-DIOM_PF001_BASELINE=0` (or omits the macro, the header is then empty), the baseline compile uses `-DIOM_PF001_BASELINE=1`. No public op is bypassed on either tree.
