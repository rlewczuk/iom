# Migrate the SYCL queue onto the shared staged worker and fence tensor storage through a device-owned registry

**Order:** 55
**Priority:** P0 — high-severity asynchronous storage lifetime and transactional submission safety on the SYCL backend
**Blocked by:** None
**Source:** `docs/changes/0001-tensor-view/review.md` — `ST-001`
**Review severity:** high
**Review verification:** verified, confidence 90

## Outcome

SYCL reaches the same storage-lifetime and submission-transaction generation as CPU, CUDA, ROCm, and TTNN. A `SyclTensor` destroyed while queued work still references its storage first fences that work: its destructor snapshots the device-owned outstanding-work registry, waits each live entry's `SyclFenceState::result()` outside registry locks, releases storage only when every entry succeeds, and otherwise moves the USM allocation into a device-owned quarantine that frees it exactly once at device teardown. `SyclQueue` is built on `iom::detail::StagedWorker<Task>` with the standard four callbacks; teardown drains and completes every staged and published task instead of abandoning them, and a later `queue_.submit` throw on a task whose first submit has already stored an event into the pre-submit state yields a committed waitable token whose repeated `wait` rethrows the same stored failure.

## Current failure

Three verified defects, all in the newest backend:

1. `~SyclTensor` at `src/sycl/device.cpp:154-156` is a bare `iom::detail::release_aligned_storage(allocator_, address_)`. `copy(src, dst); destroy dst;` — the exact caller error 49-ST-003 hardened on CPU/CUDA/ROCm/TTNN — frees the USM allocation while the in-flight kernel still reads and writes it: silent corruption or device fault. Compare the snapshot→fence→release-or-quarantine destructors in `src/cpu/device.cpp:493-553`, `src/cuda/device.cpp:153-220`, `src/rocm/device.cpp:133-200`, and `src/ttnn/device.cpp:242-318`.
2. `SyclQueue` (`src/sycl/copy.cpp:247-434`) hand-rolls a worker whose `run()` returns as soon as `shutdown_` is set, abandoning every entry in `tasks_` and `staged_` without waiting their events or calling `complete`; `~SyclQueue` (`src/sycl/copy.cpp:259-268`) only sets the flag and joins. The umbrella spec permits not waiting, but the shared scaffold's drain-and-complete contract (30-AR-002 `shutdown_and_drain`, event wait plus exactly-once completion) is what the other four backends deliver; SYCL is the fifth, weaker variant.
3. The submission lambda (`src/sycl/copy.cpp:289-349`) enqueues per-plane kernels through `queue_.submit` before `staged_.push_back`, which allocates and can throw; the success-path `publish_staged` deque insert can also throw. A throw after the first submit escapes `copy` with no token and no rollback while the enqueued kernels reference both operands — the orphaned-work class 19-ST-002 eliminated on CUDA/ROCm.

`grep` for registry, quarantine, and `StagedWorker` under `src/sycl` finds zero matches. Impact: backend-dependent memory safety for the identical caller error on the newest backend, and unwaitable tokens after queue destruction with pending work.

### Queue migration

`SyclQueue::copy` becomes the CUDA shape: take `std::lock_guard<std::mutex> submission_lock(submission_order_mutex_)` (new member), run `validate_copy`, `identical_window`, and the `plane_pairs`/geometry computation before `DeviceOps::submit` so every pre-enqueue throw consumes no sequence, then `submit` a lambda that calls `worker_.submit_copy(Task{...})`. Construct the worker with `PublishPolicy::Splice` and the four callbacks. The exact host-side ordering inside `execute` matters and is fixed:

1. `execute(Task&)`: every potentially-throwing host allocation and every index insertion that the rest of the helper relies on must happen **before** the first `queue_.submit` so a post-submit throw can never strand partial registry state. The sequence is:
   - (a) if `task.no_op`, set `task.state = nullptr` and `task.fence = nullptr`, register nothing, return — identical windows touch no storage.
   - (b) Otherwise, **inside `execute`, before any `queue_.submit`**, construct `task.state = std::make_shared<SyclFenceState>()` and set `task.fence = task.state.get()` — this is the only place the shared_ptr is created; the construction itself is a single heap allocation, which is a pre-submit allocation. The fence member is a non-owning alias of the state's raw pointer; it exists only because `StagedWorker::process` reads `task.fence` as `void*`. The Task is forbidden from holding any heap resource / raw ownership beyond this alias.
   - (c) Build the registry `Fence` from a `std::function<detail::FenceResult()>` that captures `task.state` (by copying the shared_ptr) and calls `task.state->result()`; the captured shared_ptr keeps the state alive for every registry entry that references this fence. The capture happens **before** registration, so by the time `register_copy_entries` stores the `Fence` into the registry, every registry entry that will see this task already holds a copy of the shared_ptr. The two registry entries each capture their own copy of the shared_ptr — one for the source Fence, one for the destination Fence — so after step (c) three shared_ptr copies are alive.
   - (d) Call `register_copy_entries(*state_, registry_queue_id_, task.sequence, source_handle, destination_handle, fence)`; both registry entries reference the shared_ptr-owned `SyclFenceState`.
   - (e) Acquire `outcome_mutex_` and insert `SequenceOutcome{source_entry_id, destination_entry_id, task.state}` into `outcomes_` — the `SequenceOutcome` holds its **own** shared_ptr copy of the state (a copy, not `std::move(task.state)`, so the Task retains its own owning shared_ptr through step (f)). The Task's copy is the one consumed by `set_event(...)` on the happy path (f) and by `set_failure(...)` on the post-enqueue path (f); the Task's copy is dropped only when the Task is destroyed after the worker has run `process()` for it. The `SequenceOutcome`'s copy exists so `complete_task` can read the cached `result()` after `StagedWorker::process` has run `fence_complete` (which only populates the cache) and `fence_destroy` (which forces a final `result()` and resets the event). After step (e) **four** shared_ptr copies of the state are alive concurrently: the Task's `state`, the source registry Fence's captured shared_ptr, the destination registry Fence's captured shared_ptr, and the `SequenceOutcome`'s `state`.
   - (f) Initialize `bool submitted_any = false;`. **Now** begin the kernel-submit loop on `queue_`.
   - For each plane pair: call `queue_.submit(...)`; on success, move the returned `sycl::event` into `task.state->set_event(...)` (noexcept), set `submitted_any = true`, and continue. A throw from any plane submit branches on `submitted_any`:
     - If `submitted_any == false`: this is the first `queue_.submit` throw before any event — a pre-enqueue failure. The catch path **exactly** unwinds the preinserted state: remove both exact registry entries (`state_->registry.remove_entries({source_entry_id, destination_entry_id}, source_handle_or_destination_handle_per_entry)`), erase the inserted `SequenceOutcome` from `outcomes_` (acquire `outcome_mutex_`, find by sequence, erase), reset `task.fence = nullptr` and `task.state.reset()` (so the last shared_ptr releases the `SyclFenceState`), and rethrow the original exception so `StagedWorker::submit_copy`'s catch erases the staged task and `DeviceOps::submit` rolls back the reservation with no token.
     - If `submitted_any == true`: this is a post-enqueue failure (a later `queue_.submit` throw after ≥1 kernel was already enqueued). The catch path **does not** allocate, **does not** mutate the registry indexes, and **does not** erase the `SequenceOutcome`. It stores `std::current_exception()` into `task.state->set_failure(...)` (a noexcept assignment), and returns normally. The store must be sequenced before `execute` returns and before `StagedWorker` splices the task into `tasks_`, so that any registry fence the worker invokes observes the cached failure through `state->result()`.

2. `fence_complete(void*)` (`StagedWorker::FenceComplete` returns `void`, see `include/iom/iom.hpp:32-33,140-143`): the closure casts `void*` to `SyclFenceState*` and calls `state->result()`. It does **not** return a `FenceResult` — `StagedWorker::process` cannot pass a failure back through the void callback. Calling `result()` here only forces the wait once and caches the result for later consumers (`complete_task` reads the cached value through the `SequenceOutcome`'s shared_ptr, not through the callback). The closure is `noexcept` (the only operation is the state method call, which never throws) and never allocates.

3. `fence_destroy(void*)` (`StagedWorker::FenceDestroy` returns `void`, see `include/iom/iom.hpp:33-34,145-153`): the closure casts `void*` to `SyclFenceState*`, calls `state->result()` (which is idempotent and never throws — it returns the cached value if a fence_complete already ran, or runs the wait-and-cache path otherwise), then under the state's mutex resets the optional event. After this returns, `state` is **not deleted** by `fence_destroy`; the heap-owned `SyclFenceState` is released when the last of the four shared_ptr copies is dropped — that is, when both registry entries are removed in `complete_task` (or invalidated) **and** the `SequenceOutcome`'s shared_ptr is dropped **and** the worker has finished the task **and** the Task itself is destroyed after the worker has run `process()` for it. Null fences (no-op tasks) are a no-op.

4. `complete`: forwards to the queue's `complete_task(sequence, callback_failure)`, which mirrors `CudaQueue::complete_task` with two changes:
   - Pop the `SequenceOutcome` from `outcomes_` by sequence. The outcome carries its own `std::shared_ptr<SyclFenceState> state`, `source_entry_id`, and `destination_entry_id`.
   - Call `state->result()` to read the cached, race-safe `FenceResult` (which combines the wait result with any retained failure stored via `set_failure(...)`).
   - Combine the cached `FenceResult::failure` with the `callback_failure` argument (which carries any exception from `fence_complete`/`fence_destroy`, normally nullptr for SYCL since `result()` is noexcept) into one `exception_ptr` for the task.
   - On any failure, `state_->registry.invalidate_entries({source_entry_id, destination_entry_id})`; on success, `state_->registry.try_release_entry(...)` for both IDs.
   - Call `DeviceOps::complete(sequence, combined_failure)`.

### Holder and fence-resource shape (pinned)

The Task holds `std::shared_ptr<SyclFenceState> state` (the owner) **and** `void* fence = state.get()` (a non-owning alias for `StagedWorker::process`). No heap resource / raw ownership is permitted beyond this alias. The shared_ptr is constructed in `execute` step (b), copied into the two registry Fences in step (c) (one for the source entry, one for the destination entry), and copied into the `SequenceOutcome` in step (e). **Four** shared_ptr copies of the state are alive concurrently between step (e) and the worker's `complete_task`: the Task's `state`, the source registry Fence's captured shared_ptr, the destination registry Fence's captured shared_ptr, and the `SequenceOutcome`'s `state`. The Task's shared_ptr is dropped only when the Task is destroyed after the worker has run `process()` for it (under `PublishPolicy::Splice`, the Task is move-constructed into the worker's `tasks_` list and the staged entry is destroyed; after the worker pops the task and runs `fence_complete`/`fence_destroy`/`complete_task`, the Task's holder is destroyed and its shared_ptr is released — the state itself is then released when the last remaining shared_ptr is dropped, which is the `SequenceOutcome`'s copy when `complete_task` erases it from `outcomes_` and the captured shared_ptrs in the registry entries when those entries are removed or invalidated). The registry Fences' shared_ptrs are dropped when the registry entries are removed or invalidated in `complete_task`; the `SequenceOutcome`'s shared_ptr is dropped when the outcome is erased from `outcomes_` after being popped in `complete_task`. The `SyclFenceState` is released when the last of those four shared_ptrs is dropped — `fence_destroy` does not `delete` it.

The `void* fence` alias is set whenever `state` is set: in step (b) `task.fence = task.state.get()`. In step (a) `task.fence = nullptr`. In the pre-enqueue rollback path of step (f), the alias is reset to `nullptr` before the shared_ptr is reset, so `StagedWorker::process` (which reads `task.fence` to decide whether to call `fence_complete`/`fence_destroy`) treats the rolled-back task as a no-op. `StagedWorker::process` (`include/iom/iom.hpp:136-155`) reads `task.fence`, not `task.state`, so the alias is the field the helper observes.

The registry Fence therefore **cannot observe a non-null state pointer before the shared_ptr copy returns**: the Fence is constructed in step (c) under the registry mutex (during `register_copy_entries`) after the shared_ptr is constructed in step (b); the operand-lifetime/caller-serialization contract from the umbrella spec (`SyclQueue::copy` runs under `submission_order_mutex_`, the task is staged before `execute` runs, no two callers share the same Task) keeps the source/destination view references stable for the lifetime of the entries; the shared_ptr keeps the state stable for the same period.

`SyclFenceState` is a TU-private class declared in `src/sycl/copy.cpp` (or a small TU-private header) with exactly these data members and the documented behaviors:

- `std::mutex mu_` — protects `event_`, `retained_failure_`, and `cached_` after publication. **Not** acquired by the pre-publication setters (see below).
- `std::optional<sycl::event> event_` — the last `sycl::event` returned by a successful `queue_.submit`.
- `std::exception_ptr retained_failure_` — set by the post-enqueue catch in `execute` step (f) before the helper publishes.
- `std::optional<detail::FenceResult> cached_` — populated by the first `result()` that performs a wait; subsequent calls return the cached value.

`SyclFenceState` declares `static_assert(std::is_nothrow_move_constructible_v<sycl::event> && std::is_nothrow_move_assignable_v<sycl::event>)` so the move-asymmetry of `std::optional<sycl::event>::operator=` is enforced at compile time. Its event setter (`set_event(sycl::event)`) and exception setter (`set_failure(std::exception_ptr)`) are both declared `noexcept` and are callable only from `execute` before the task is published; therefore they perform their stores **without acquiring `mu_`** — they write `event_ = std::move(incoming_event)` (the move-assignment is noexcept by the static_assert) and `retained_failure_ = incoming_exception_ptr` (the `std::exception_ptr` copy is noexcept) directly. This keeps the `noexcept` setters credible: a `std::lock_guard<std::mutex>` inside a function declared `noexcept` would be a latent terminate-on-resource-exhaustion trap, and the setters have no need for the mutex because at the only call sites (step (f) of `execute`) no other thread can observe the state — the Task has not yet been published into `tasks_`, the registry Fence closures are not yet running, and the destructor cannot have snapshotted the address yet because no token exists. The mutex `mu_` and the `cached_` slot are owned by `result()`, by the `event_.reset()` inside `fence_destroy`, and by any destructor-side coordination that runs after publication. It exposes one method `result() -> detail::FenceResult` that, under `mu_`, if `cached_` is set returns the cached value, otherwise waits `event_->wait_and_throw()` once in try/catch, combines any thrown exception with `retained_failure_` to produce `detail::FenceResult`, caches it into `cached_`, and returns it. Every subsequent `result()` call returns the cached value, so registry fences invoked from a snapshot copied before entry removal observe the same `FenceResult` they would have observed before removal, even after `event_` has been reset by `fence_destroy`. A snapshot copied before entry removal therefore invokes the cached result after the optional event has been reset by `fence_destroy` and observes the correct `FenceResult` without seeing an empty or dangling event.

### Tensor destructor protocol

`~SyclTensor` becomes `noexcept override` and mirrors `~CudaTensor`: null-address early return; `state_->registry.snapshot_for(address_)` (on snapshot failure, quarantine and return); invoke each live entry's fence after the snapshot released the registry lock — the fence closure casts the void* alias back to `SyclFenceState*` and calls `result()`, which is race-safe and idempotent; invalidated or empty fences mark unsafe without invocation; when every fence succeeds, remove the snapshot IDs and `release_aligned_storage(allocator_, address_)`; otherwise quarantine once via `quarantine.emplace<detail::AllocatorCleanupAction>(allocator_, address_, bytes)` (no `pre_release` hook — SYCL has no context-activation requirement), swallow a quarantine-allocation failure (leaking is safer than freeing referenced storage), remove the snapshot IDs, and never free. The destructor's fence call observes the cached `FenceResult` and never observes an empty or dangling event even if the snapshot was taken before the registry entries were removed.

## Requirements

1. Registry and quarantine are owned by `SyclDevice`, outlive every tensor and queue created by that device, and the quarantine drains in `~SyclDevice` before the context is reset, invoking each cleanup action at most once.
2. Registration happens inside `execute` before the helper publishes the task; a worker completion can never precede the existence of a task's entries. Storage-referencing tasks register exactly two entries keyed by unique `EntryId`s; completion releases exactly those IDs, never an address bucket. The Task holds an owning `std::shared_ptr<SyclFenceState> state` and a non-owning `void* fence = state.get()` (nullptr for no-op tasks); no heap resource / raw ownership is permitted beyond the alias. No-op tasks register nothing and still complete once with a waitable token.
3. Registry fences capture only the per-task `SyclFenceState` (via the shared_ptr reached by `state.get()`) and the retained failure stored in the state. No fence captures a queue pointer, `SyclQueue*`, tensor, view, or stack address.
4. Fences are invoked outside registry locks: the destructor snapshots, then waits, then mutates.
5. A tensor destructor never frees storage after a failed or invalidated fence; failed storage enters quarantine and is not freed or reused before device teardown. The destructor and quarantine drain are no-throw effective.
6. `~SyclQueue` invalidates its registry entries before any native resource teardown; invalidation marks entries failed, keeps them address-indexed, and does not erase them early.
7. `SyclQueue` contains exactly one `detail::StagedWorker<Task>` value member with `PublishPolicy::Splice`; the previous mutex/condvar/deque/thread worker, `publish_staged`, and `run` bodies are deleted. A per-queue `submission_order_mutex_` serializes the whole public `copy` call.
8. Pre-enqueue failures are the throws that occur before any `queue_.submit` has returned an event on this task. They include: `validate_copy`, `identical_window`, the `plane_pairs`/geometry computation, the pre-submit `std::shared_ptr<SyclFenceState>` heap allocation in step (b), the `Fence` construction in step (c) (which captures the shared_ptr), the registry entry insertion in step (d), the `SequenceOutcome` map insertion in step (e), and a `queue_.submit` that throws before it ever produced an event (zero kernels enqueued — `submitted_any == false` branch of step (f)). All of these happen before the kernel-submit loop's first successful event so a failure there is pre-enqueue by construction. The pre-enqueue rollback path of step (f) (and any throw from steps (b)–(e)) **exactly** unwinds the preinserted state: remove both exact registry entries, erase the inserted `SequenceOutcome` from `outcomes_` by sequence, reset `task.fence = nullptr` and `task.state.reset()`, rethrow the original exception so `StagedWorker::submit_copy`'s catch erases the staged task and `DeviceOps::submit` rolls back the reservation with no token.
9. Post-enqueue failures are limited to a `queue_.submit` throwing after at least one earlier `queue_.submit` on this task has already stored an event into `task.state` via `set_event(...)` — i.e. the `submitted_any == true` branch of step (f). The implementation **does not** allocate, **does not** mutate the registry indexes, **does not** erase the `SequenceOutcome`, and **does not** call `commit_failure` from this path: before `execute` returns and before the helper splices the task into `tasks_`, it stores `std::current_exception()` into `task.state->set_failure(...)` (a noexcept assignment), and returns normally. `PublishPolicy::Splice` publishes the task; the worker eventually calls `complete_task`, which calls `state->result()` through the `SequenceOutcome`'s shared_ptr to read the cached, race-safe `FenceResult` (combining the stored retained failure with the event's wait result), invalidates both entries, and the caller's repeated `wait(oid)` observes the same stored failure. The enqueued kernels remain fenced by the last stored event until completion or drain.
10. Shutdown drains every staged and published task exactly once, calling `fence_destroy` for non-null fences (no `fence_complete`) and `complete(sequence, failure)` exactly once, so no token is left uncompleted by queue destruction.
11. `fence_complete(void*)` is a void callback that only forces/populates the cached `state->result()`; it does not return a `FenceResult` and does not propagate a failure back to `StagedWorker::process`. `fence_destroy(void*)` is no-throw, calls `state->result()` (idempotent — repeat invocations return the cached value, never re-wait and never throw), then resets the optional event under the state's mutex. The state itself is not deleted by `fence_destroy`; it is released by the last `std::shared_ptr<SyclFenceState>` when both registry entries are gone, the worker has finished the task, and the Task itself has been destroyed after `process()`.
12. Common registry code stays free of SYCL types; the new state header lives beside `src/cuda/registry_state.hpp` and adds nothing to public headers. Queue-ID leasing and `oid` encoding in the `DeviceOps` base are unchanged.
13. Existing SYCL conformance behavior — validation messages, no-op handling, unsupported-operation rejection, token semantics, in-order execution — is preserved.
14. `commit_failure` is not called from `execute`; the only path that records a post-enqueue retained failure is the worker calling `complete_task`, which uses `state->result()` through the `SequenceOutcome`'s shared_ptr to drive `complete(sequence, exception_ptr)`.
15. Four shared_ptr copies of `SyclFenceState` are alive concurrently between `execute` step (e) and `complete_task`: the Task's `state`, the source registry Fence's captured shared_ptr, the destination registry Fence's captured shared_ptr, and the `SequenceOutcome`'s `state`. The Task's `void* fence` is a non-owning alias of `state.get()`. The Task's shared_ptr is the one consumed by `set_event(...)` on the happy path (f) and by `set_failure(...)` on the post-enqueue path (f); it is dropped only when the Task is destroyed after the worker has run `process()` for it. `fence_destroy` does not `delete` the state; the last shared_ptr reference is dropped when no Task, no source-entry Fence closure, no destination-entry Fence closure, and no `SequenceOutcome` hold a copy.
16. `SyclFenceState::result()` is idempotent and race-safe: under its internal mutex it returns the cached `FenceResult` if set, otherwise waits the held event once in try/catch, combines the outcome with the retained failure, caches the result, and returns it. Every subsequent call returns the same cached value. A snapshot copied before entry removal therefore invokes the cached result after the optional event has been reset by `fence_destroy` and observes the correct `FenceResult` without seeing an empty or dangling event.
17. `SyclFenceState::set_event(sycl::event)` and `SyclFenceState::set_failure(std::exception_ptr)` are `noexcept` and perform their stores **without acquiring `mu_`**. They are only callable from `execute` step (f) before the helper publishes the task — at the only call sites, no other thread can observe the state — and their mutex discipline is owned by `result()`, `event_.reset()` inside `fence_destroy`, and any destructor-side coordination that runs after publication. This makes the `noexcept` setters' guarantee credible: a `std::lock_guard<std::mutex>` inside a `noexcept` setter would be a latent terminate-on-resource-exhaustion trap.

## Non-goals

- Coexistence build wiring: `IOM_COEXIST_SYCL`, the `test/CMakeLists.txt` gate, and `-fsycl` participant setup belong to `53-CC-003-add-sycl-backend-coexistence`.
- Shared word-oriented copy kernels, per-plane launch elimination, pooled staging/transfer queues, and `submission`-path data-movement changes: AR-001/PF-001 convergence owns those; the per-plane kernel body stays as is.
- `synchronous_transfer` host-pointer routing (review ST-005) and the async-copy storage-oracle wiring (review NT-002).
- Changing `DeviceOps`, `Device`, `Tensor`, `TensorView`, or `Allocator` public signatures; changing the registry's internal design (review AR-003) or deduplicating the four existing destructors behind a shared helper (review AR-002); changing `StagedWorker`'s `FenceComplete`/`FenceDestroy` return type from `void` to `FenceResult`.
- CUDA/ROCm/CPU/TTNN queue or destructor changes; 47-ST-001/ST-002 concerns on those backends.
- Cross-queue dependency tracking, cancellation, implicit caller-visible waits, or making a destroyed queue waitable.
- A whole-device synchronization beyond the owning queue's teardown fence.
- Fault-injection inside `OutstandingWorkRegistry::register_entry`'s per-bucket `by_id_/by_address_/by_queue_/by_sequence_` insertions. The exhaustive registry-insertion fault sweep is owned by the next task `57-ST-003-roll-back-outstanding-work-registrations-on-second-entry-failure` (cited for traceability). ST-001 may rely on the helper's intended transaction.

## Acceptance criteria

- [ ] A `ReusingSyclAllocator`-based regression ("SYCL tensor destruction fences queued work") submits a copy on SYCL hardware, destroys an operand before `wait`, allocates a fresh same-size tensor through the reusing allocator, and proves the freed address is not recycled with in-flight writes: the fresh tensor's filled pattern reads back exactly, `wait(token)` succeeds, and free counts balance. On the pre-fix bare release this case corrupts the recycled storage and fails.
- [ ] A pre-enqueue fault case (the fault seam trips before any `queue_.submit` has returned an event for this task, so zero kernels are enqueued — `submitted_any == false`) confirms `copy` throws, no sequence is consumed, and the next successful submission reuses the sequence number. The fault targets for ST-001's deterministic pre-enqueue tests are exactly: (i) the pre-submit `SyclFenceState` heap allocation in step (b), (ii) the registry `Fence` construction in step (c) (the `std::function` copy that captures the shared_ptr), (iii) the post-registration `SequenceOutcome` map insertion in step (e) (whose returned outcome ST-001 removes through the same indexes it just populated), and (iv) a `queue_.submit` that throws before any event (`submitted_any == false` branch of step (f)).
