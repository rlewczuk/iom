# Pool CUDA/ROCm queued-copy events in a shared ring and pass bounded copy metadata as kernel arguments

**Order:** 74
**Priority:** P1 — removes two deterministic per-submission fixed costs (native event create/destroy churn and the metadata H2D memcpy) from the small-op regime; required performance remediation that gates no correctness work.
**Blocked by:** `56-ST-002-restore-gpu-event-fencing`, `63-AR-004-share-cuda-rocm-copy-infrastructure`, `73-PF-003-reduce-staged-submission-overhead`
**Source:** `docs/changes/0001-tensor-view/review.md` — `PF-004`
**Review severity:** low
**Review verification:** strongly-supported (churn code-deterministic; per-call driver cost unmeasured), confidence 65

## Outcome

Every queued non-no-op CUDA/ROCm copy acquires its completion event from one shared, policy-parameterized ring (`iom::detail::EventRingState<Policy>`, allocated once per queue via `std::make_shared<EventRingState<Policy>>(context, metadata_pool)`) instead of using task 73's intrusive-refcounted per-task `CudaFenceResource`/`HipFenceResource` and its one-pointer inline registry leases (where the worker releases the metadata and the `Task` refcount, and the last registry/snapshot lease destroys the per-task event/resource). Events are created lazily up to 16 slots (`kEventRingCount = 16`, aligned with `kMetadataSlotCount`), reused only after the fence boundary synchronized them, and destroyed exactly once at `~EventRingState`, which runs only when the queue owner and every registry/snapshot lease are gone. Each slot carries a per-slot `FenceResult cached_result` recorded by the worker (`on_worker_complete` populates it; `on_worker_destroy` keeps it immutable after release); the registry/snapshot `invoke` trampoline consults the cached result after first observation rather than blindly synchronizing a possibly-reused slot — matching task 73's snapshot-after-worker regression safety exactly. Every copy whose leading rank is at most 8 — every shape in the repository, maximum queued-copy rank is 6 — passes its copy metadata as an inline kernel argument (`InlineCopyMetadata`, 240 bytes) and performs no metadata H2D `cudaMemcpyAsync`/`hipMemcpyAsync` and no metadata-slot acquisition; larger ranks keep the pooled metadata slot plus H2D path byte-for-byte as delivered by 63-AR-004. The per-task intrusive `CudaFenceResource`/`HipFenceResource` is deleted entirely (the previous per-submission heap allocation from the pre-73 tree, preserved by 73 as the intrusive-refcounted mechanism 74 now supersedes). Fencing semantics stay unchanged: 56-ST-002's no-throw synchronize still precedes every slot release on the destroy boundary; completion, retained-failure, teardown, and the `SubmissionFault::event_create` injection behavior are preserved. The ring's native events/context/pointer stay valid as long as the creating Device keeps its native context alive, which the public contract already requires for tensors and every registry/snapshot fence reached from their destruction.

## Current failure

Invariant (review PF-004): per-op driver-object lifecycle is amortized the way metadata slots already are — and now that 73-PF-003 has installed the corrected fixed-capacity inline `detail::Fence` plus intrusive-refcounted per-task `CudaFenceResource`/`HipFenceResource` (where the worker releases metadata + `Task` refcount and the last registry/snapshot lease destroys the per-task event/resource), the next step is to replace the per-task intrusive resource itself with a queue-shared one.

`CudaQueue::execute` (`src/cuda/copy.cu:742-858`) and `RocmQueue::execute` (`src/rocm/copy.hip:746-859`) pay two fixed costs per non-no-op submission, independent of copy size:

1. **Per-task intrusive-refcounted event/resource.** Each submission constructs a fresh `CudaFenceResource` / `HipFenceResource` (post-73 intrusive-refcounted: per-submission `new` plus one refcount bump per registry entry plus one per snapshot — the worker's release drops the worker's refcount, the last outstanding registry/snapshot lease drops the final refcount and destroys the event). One `cudaEventCreateWithFlags` / `hipEventCreateWithFlags` (at `src/cuda/copy.cu:75-83`, `src/rocm/copy.hip:74-81`) per non-no-op copy plus one intrusive-refcounted per-submission heap node — the same per-op resource the metadata slots already amortize, but paid through a per-submission intrusive allocation/refcount dance that this task replaces with a single queue-shared allocation.
2. **Metadata H2D memcpy.** Every submission writes the metadata blob into its pooled slot's host buffer and enqueues `gpu_policy::copy_from_host` (`copy.cu:768-770`, `copy.hip:771-773` — `cudaMemcpyAsync`/`hipMemcpyAsync` H2D), even though the metadata for low leading rank is small enough to pass as a kernel argument.

The metadata blob is 48 bytes of header (five `uint64_t` fields, `bits`, `leading_rank` — `CudaCopyMetadataHeader` `copy.cu:226-234`) plus 24 bytes per leading-rank level (source strides, destination strides, leading dimensions — `write_cuda_metadata` `copy.cu:562-598`). In the small-op regime (16×16 F32, the NT-001 benchmark shape) these driver calls and the per-task intrusive allocation are the same order as the whole submit+wait budget; the review estimates ~1–4 µs driver overhead per submission — an estimate, not a measurement; this task must keep it that way until the before/after runs below land. For large copies the costs are negligible, and nothing in this task changes large-copy throughput.

The integration review surfaced lifetime requirements that PF-004 has to honor against 73's corrected baseline: (a) task 73's intrusive-refcounted per-task resource makes snapshot-after-worker/queue safety correct (the snapshot's lease refcount keeps the resource alive past worker `fence_destroy` and past queue teardown), and PF-004 must replace the per-task resource itself without reintroducing any path where a registry/snapshot fence dereferences a destroyed event or pool pointer; (b) task 73's post-Fence model is a fixed-capacity inline type-erased value with four function pointers (`invoke`, `copy_construct`, `move_construct`, `destroy`), not a `std::function` — there is no small-buffer optimization to fit a `std::shared_ptr<EventRingState<Policy>>` into; the lease capture's zero-allocation claim is scoped to the shared_ptr/exception_ptr control-block refcount operations the lease copies perform (the `shared_ptr` copy/move adjusts the control block's refcount; the `exception_ptr` copy/move adjusts its refcount — neither allocates); (c) registry fences must be invoked before or at most alongside registry entry removal, never after the slot has been released to a later submission — the safety property is "registry/snapshot invoke observes a cached result the worker recorded before releasing the slot", not "registry/snapshot invoke observes a possibly-reused slot's later recording"; (d) acquire must consume the `SubmissionFault::event_create` fault before doing anything that could leave state — including before any free-slot search and before any capacity-block wait, because the fault semantics are "submission fails pre-link with no slot allocated/marked"; (e) the `EventRingState<Policy>::synchronize` method is backend-neutral and cannot call backend-private `fence_event` — the policy exposes a single helper (or each backend's lease invoke calls its own backend helper) so the shared template stays runtime-clean; (f) `~EventRingState` must release the metadata slots attached to any still-in-use slots before destroying the events (the metadata pool is queue-owned, but every attached slot that was never released by the worker still holds a slot in the pool and would leak if `~EventRingState` dropped without releasing them — the public Device contract requires the pool to remain alive when the last lease destroys the state, so the state can safely release its attached metadata slots).

The replacement is one queue-shared `EventRingState` (held by `shared_ptr`, refcount bumped by every registry/snapshot lease) plus a 32-byte `EventLeaseWithFailure` capture that lives inside 73's pinned `detail::Fence` inline buffer (`kFenceStorageBytes = 32`, `kFenceStorageAlign = alignof(std::max_align_t)`); the worker records a per-slot `cached_result` so registry/snapshot invokes never re-synchronize a possibly-reused slot; the `invoke` trampoline is backend-side (a `Policy::synchronize_event_result` helper or a per-backend direct call), keeping the shared template runtime-clean.

The fix lands after its blockers on purpose: 56-ST-002 restores `gpu_policy::synchronize_event_noexcept` — the no-throw synchronize the ring's reuse invariant needs; 63-AR-004 moves the metadata header/writer/kernel and the pools behind `gpu_policy` in `src/shared/`, so the ring and the inline kernel land once, not as a sixth twin pair; 73-PF-003 installs the inline `detail::Fence` and the corrected per-task intrusive `CudaFenceResource`/`HipFenceResource` (worker releases metadata + Task refcount; last registry/snapshot lease destroys event/resource) — PF-004 explicitly replaces that per-task intrusive resource with the queue-shared `EventRingState` and rewrites the CUDA/ROCm `detail::Fence` capture from `CudaFenceCapture`/`HipFenceCapture` (the one-pointer intrusive-resource inline lease) to `EventLeaseWithFailure` (the 32-byte shared_ptr + slot_index + retained_failure with per-slot cached_result consultation). 73's other deliverables (TTNN/SYCL captures, CPU inline completion, registry/outcome/staged-list allocations) are consumed unchanged.

## Scope

- **Shared event-ring state:** add `src/shared/event_ring.hpp` defining `iom::detail::EventRingState<Policy>` — the public class is the state-bearing object held via `std::shared_ptr<EventRingState<Policy>>`; one `std::make_shared<EventRingState<Policy>>(context, metadata_pool)` allocation per queue (single queue-level allocation; this replaces 73's per-submission intrusive `CudaFenceResource`/`HipFenceResource` `new` and refcount bumps). The state holds 16 slots (`kEventRingCount = 16`), a non-owning `MetadataSlotPool<Policy>*` pointer (set at construction; the pool itself remains queue-owned and outlives the state's refcount when the queue holds its own reference), the queue context, a mutex + condition variable, a lazy-event-creation counter, and an activate-swallowing destructor that synchronizes and destroys every created event exactly once and releases the metadata slot attached to any in-use slot.
- **Per-slot cached result recorded by the worker.** Each `Slot` carries `iom::detail::FenceResult cached_result` (default `success`, no fence payload). The worker's `on_worker_complete(Slot&)` synchronizes the event via the policy's throwing `synchronize_event` and stores the result (success or failure) into `slot.cached_result`; `on_worker_destroy(Slot&) noexcept` leaves `cached_result` unchanged after release (the slot may be re-acquired by a later submission, but `cached_result` is overwritten by that later submission's own `on_worker_complete` before any new registry entry could observe a stale value — and the registry/snapshot copy's invoke consults `cached_result` only after first observation through `state->invoke_result(slot)`, which atomically returns the current cached value; if the slot has been re-acquired and a new `cached_result` is now recorded, the registry entry has already been removed/invalidated by `complete_task` before any stale observation is possible — this is the invariant 73's snapshot-after-worker regression depends on, here made per-slot explicit).
- **Inline-fence lease capture replaces the intrusive-resource inline lease.** The CUDA/ROCm backend's `detail::Fence` inline capture type changes from task 73's `CudaFenceCapture {intrusive CudaFenceResource* resource, retained_failure}` (one-pointer intrusive lease) to `EventLeaseWithFailure {std::shared_ptr<EventRingState<Policy>> state; std::size_t slot_index; std::exception_ptr retained_failure;}` (32 bytes on the supported platforms — the `static_assert` enforces task 73's pinned `kFenceStorageBytes` budget exactly). Every fence copy (`copy_construct` and `move_construct`) performs shared_ptr/exception_ptr control-block refcount operations, not heap allocations. `invoke` consults `state->invoke_result(slot_index)` — a backend-neutral helper that returns the slot's cached result; if the slot is still in-use (a registry entry is live), `invoke_result` reads `slot.cached_result` directly. A stale lease that outlived worker complete (a snapshot copy of a registry entry's fence invoked after `on_worker_destroy` released the slot) observes the cached result the worker recorded before releasing; if the slot was re-acquired in the meantime, the cached_result has been overwritten by the new submission's worker, but the registry entry has already been removed/invalidated by `complete_task` (the pinned flow guarantee: registry entries are removed before or alongside the slot's release, never after), so a stale observation is impossible.
- **Acquire fault semantics.** `state_->acquire()` consumes `Policy::check_acquire_event_fault()` first — before any free-slot search, before any lazy-creation, and before any capacity-block wait. If the fault is armed, acquire throws before anything is marked in use, no slot is allocated, and no metadata slot was held at the time of the throw (metadata acquire happens in `execute` after the ring acquire returns, so the pre-link cleanup is exactly `state_->release(slot)` plus the metadata slot release when one was acquired). While capacity-blocked, the fault check is not invoked again — the fault fires once per acquire attempt at the top, before the wait. This preserves the pre-73 conformance test behavior (inject `event_create` → `queue->copy` throws `std::runtime_error` pre-link) and is required for "armed fault fails the current submission pre-link" semantics.
- **Worker-callback opaque.** `StagedWorker<Task>::Callbacks::fence_complete` and `fence_destroy` lambdas capture the queue's `std::shared_ptr<EventRingState<Policy>>` (single refcount bump at queue construction; the captures live in the callback-lambda storage that `StagedWorker` already owns — no new per-submission allocation; the zero-alloc claim is the control-block refcount operation, not any claim that the capture fits a `std::function` small-buffer optimization — the post-73 Fence is a fixed-capacity inline type-erased value with four function pointers, and the worker-callback lambdas are independent `std::function` allocations that `StagedWorker` already owns as part of the queue object). The opaque passed to them via `Task::fence` is the stable `Slot*` address inside the state. `on_worker_complete(Slot&)` activates the context, calls the throwing `Policy::synchronize_event(event)` (or a backend-private helper called from the backend TU), stores the result into `slot.cached_result`. `on_worker_destroy(Slot&) noexcept` activates inside a swallowed try, calls `synchronize_event_noexcept(event)` (56's primitive — used here to keep `cached_result` consistent even if the throwing synchronize was skipped or failed), releases the attached metadata slot via `metadata_pool_->release(attached_metadata_slot)` when not the sentinel, then calls `release(*this)`; it never destroys the native event — that is reserved for `~EventRingState`.
- **Backend-private `invoke` policy hook.** `Policy` exposes `static iom::detail::FenceResult invoke_event_result(event_type event, std::exception_ptr retained_failure) noexcept` (CUDA: wraps `fence_event(context, event, retained_failure)` after activating the context; ROCm: the HIP twin). The shared `EventRingState::invoke_result(slot_index)` calls `Policy::invoke_event_result(slot.event, nullptr)` (the retained_failure is already incorporated into the cached_result the worker recorded, so the invoke path observes a fresh result with no retained_failure — the lease's retained_failure is only meaningful for the per-submission fence, not for a registry/snapshot invoke after the worker has recorded the cached result). Alternative: each backend's `EventLeaseWithFailure` `invoke` calls its own backend `fence_event` helper directly (no policy hook needed in the shared template) — either shape satisfies the constraint; the implementation chooses one.
- **Public lifetime contract precondition.** No Device-level bookkeeping is added in this task. The lease's validity is bounded by the existing public lifetime contract that the creating Device outlives every tensor and every queue on it, and that every registry/snapshot fence is reached from a tensor destructor or from `~DeviceOps` (i.e., the fence is destructor-local or device-local and never outlives the Device). The stored native context / device ordinal therefore remains valid for every reachable lease invocation — the same precondition the pre-73 and post-73 intrusive-refcount designs relied on, here stated explicitly so the lease design's correctness is not left implicit. The metadata pool remains queue-owned (the queue member outlives the ring member because the ring's `shared_ptr` is reset in the queue body before the pool member is destroyed in the queue member-destruction phase); the public Device contract ensures the queue (and therefore the pool) outlives the last lease, so `~EventRingState` can safely release the metadata slots attached to any in-use slots during destruction.
- **Inline metadata.** Add to the shared copy machinery in `src/shared/standard_tiled_copy.inl` an `InlineCopyMetadata` by-value kernel-argument representation (`CopyMetadataHeader` + `std::uint64_t values[3 * kInlineMetadataMaxRank]`, `kInlineMetadataMaxRank = 8`, 240 bytes), a second `grid_stride` kernel consuming it, and a `launch_grid_stride_copy` overload; the queues select inline versus pooled with the single comparison `layout.bytes <= sizeof(InlineCopyMetadata)`.
- **Queue rewiring.** `CudaQueue::execute`/`RocmQueue::execute` acquire a ring slot via `state_->acquire()` (fault check first), attach the metadata slot (or the `kNoAttachedSlot` sentinel on the inline path), launch the selected kernel variant, record the pooled event, publish `task.event`/`task.fence = &slot`, and build the registry `detail::Fence` via the backend `make_fence` builder that fills `EventLeaseWithFailure` (replacing 73's `CudaFenceCapture`/`HipFenceCapture` builder). The fence complete/destroy callbacks read the slot. The `CudaFenceResource`/`HipFenceResource` types and `destroy_cuda_resource_noexcept`/`destroy_hip_resource_noexcept` are deleted; `Task::fence` no longer carries a per-task resource pointer (it carries the stable ring `Slot*`); `Task::event` remains for any debug/observation.
- **Fault seam re-point.** `SubmissionFault::event_create` consumption moves from the per-submission `gpu_policy::create_event` (today called inside `execute`'s 73-corrected intrusive-resource path) to the ring's acquire boundary via a new `Policy::check_acquire_event_fault()` consumed at the top of every acquire attempt — the pooled acquire path, exactly the re-pointing the review's verification method requires. `event_record` and `third_plane_launch` stay per-submission and untouched.
- **Snapshot-after-worker/queue safety via cached result.** A snapshot copy of the registry's fence (taken inside `~Tensor` under `release_or_quarantine` after the worker has already destroyed its per-task resource / released its slot) holds its own `shared_ptr<EventRingState<Policy>>` refcount bump; the snapshot's `invoke` calls `state->invoke_result(slot_index)`, which returns `slot.cached_result` (the value the worker's `on_worker_complete` recorded before releasing). If the slot was re-acquired in the meantime, the registry entry for the original submission has already been removed/invalidated by `complete_task` (pinned flow) — the snapshot is unreachable through the registry for the re-acquired submission. If the slot was NOT re-acquired (still free with `cached_result` intact), the snapshot observes the same value the worker recorded. The fence is correct because `cached_result` is set before release and the registry entry is removed before any later submission's `cached_result` overwrite can be observed.
- **Affected backends.** cuda, rocm. CPU, SYCL (task `60-AR-001-converge-sycl-copy-architecture`'s territory), and TTNN are untouched. No `include/iom/` public header changes.
- **Coverage.** The pooled metadata fallback (leading rank ≥ 9) currently has no conformance shape above rank 6; focused rank-boundary cases keep both paths exercised.

## Requirements

1. **One allocation per queue; shared ownership for leases (replaces 73's per-submission intrusive resource).** `EventRingState<Policy>` is held by the queue via `std::shared_ptr<EventRingState<Policy>> state_;`. The queue constructs it with `std::make_shared<EventRingState<Policy>>(context_, metadata_pool_)` — exactly one heap allocation for the state's storage (the `make_shared` control block + state in one block). After this task, the per-submission intrusive `CudaFenceResource`/`HipFenceResource` `new` + refcount bumps that 73's corrected tree uses are deleted; no per-submission resource is allocated. `state_->release(Slot&)` / `state_->acquire()` allocate nothing; every lease's `copy_construct`/`move_construct` performs shared_ptr/exception_ptr control-block refcount operations, not heap allocations. `Task::fence` is a `Slot*` — no intrusive resource pointer, no Task refcount drop in the worker, no last-lease destroy dance.
2. **State mechanics.** `EventRingState<Policy>` holds a queue-context, a `MetadataSlotPool<Policy>*` (set at construction from the pool reference; the pool itself remains queue-owned and outlives the state's refcount when the queue holds its own reference — leases never hold the pool directly), `std::array<Slot, kEventRingCount>` slots (`kEventRingCount = 16`) with `{event_type event = nullptr; bool in_use = false; std::size_t attached_metadata_slot = kNoAttachedSlot; FenceResult cached_result;}`, a mutex, a condition variable, and a `created_count_`. `acquire()` first consumes `Policy::check_acquire_event_fault()` (throw before anything is marked in use, before any free-slot search, before any lazy-create, before any capacity-block wait — while capacity-blocked the fault check is not invoked again), then takes a free created slot, or — while `created_count_ < kEventRingCount` — creates one via `Policy::create_event` (lazy growth, matching `TransferStreamPool::acquire`'s create-on-empty pattern), or blocks on the condition variable until a release. `release(Slot&)` clears `in_use`, resets `attached_metadata_slot` to `kNoAttachedSlot`, leaves `cached_result` as the worker recorded it (the slot is reusable after this point; a new `acquire` will overwrite `cached_result` only when `on_worker_complete` records the new submission's result), and notifies one waiter; it performs no synchronize — the release-side invariant is the worker recorded `cached_result` before releasing. `#ifdef IOM_ENABLE_TESTING` exposes `created_event_count_for_testing()` and `in_use_count_for_testing()` only.
3. **Reuse legality and cached_result invariant.** A slot returns to the free set only through one of two paths: the worker-side `on_worker_destroy` boundary (Requirement 4), which runs 56-ST-002's no-throw `synchronize_event_noexcept` first and leaves `cached_result` immutable after release on every caller class — normal worker path after `on_worker_complete`; shutdown/staged drain; the `execute` post-link rollback — or a pre-link failure rollback in `execute` where the event was never recorded by that submission (and, being free, has no uncompleted recording and `cached_result` may still carry the previous submission's value, which is safe because no registry entry can observe it: the registry entry was either not created (pre-link) or already removed/invalidated). Therefore an acquired slot's event is always legally re-recordable, and `on_worker_complete`'s recording of `cached_result` on every new submission guarantees the registry/snapshot invoke never observes a stale slot value.
4. **Worker-side callbacks consume the slot opaque and record cached_result.** `StagedWorker<Task>::Callbacks::fence_complete` and `fence_destroy` lambdas capture the queue's `std::shared_ptr<EventRingState<Policy>>` (single refcount bump at queue construction) and receive a stable `Slot*` opaque through `Task::fence`. `on_worker_complete(Slot&)` activates the context, calls the throwing `Policy::synchronize_event(event)` (or the backend's `fence_event(context, event, nullptr)` directly), and stores the result into `slot.cached_result` — this is the value registry/snapshot invokes observe. `on_worker_destroy(Slot&) noexcept` activates inside a swallowed try, calls `synchronize_event_noexcept(event)` (56's primitive; keeps `cached_result` consistent if `on_worker_complete`'s throwing synchronize was skipped or failed), releases the attached metadata slot via `metadata_pool_->release(attached_metadata_slot)` when not the sentinel, then calls `release(*this)`; it never destroys the native event — that is reserved for `~EventRingState`. The queue-shared equivalent of 73's worker-side "release metadata + Task refcount" step: PF-004's worker releases the metadata slot and marks the slot free (with `cached_result` recorded so registry/snapshot invokes see the result).
5. **Inline-fence lease capture consumes 73-PF-003's pinned 32-byte budget and replaces the intrusive-resource inline lease.** The CUDA/ROCm backend's `detail::Fence` capture type is `EventLeaseWithFailure { std::shared_ptr<EventRingState<gpu_policy>> state; std::size_t slot_index; std::exception_ptr retained_failure; };`. The two normative static asserts sit immediately before the first factory call:
   ```cpp
   static_assert(sizeof(EventLeaseWithFailure) <= iom::detail::kFenceStorageBytes);
   static_assert(alignof(EventLeaseWithFailure) <= iom::detail::kFenceStorageAlign);
   ```
   `kFenceStorageBytes = 32` and `kFenceStorageAlign = alignof(std::max_align_t)` are the exact pinned constants from `include/iom/detail/outstanding_work_registry.hpp` (73-PF-003 requirement 1); this task does not redefine them, does not grow them, and does not introduce a separate closure or per-fence heap resource. `EventLeaseWithFailure` replaces 73's `CudaFenceCapture`/`HipFenceCapture` capture (the one-pointer intrusive-resource inline lease); the 32-byte buffer that previously held the intrusive-resource pointer now holds the three-field shared lease. `copy_construct`/`move_construct` placement-new the `shared_ptr` (control-block refcount operation, no heap) and `exception_ptr` (control-block refcount operation, no heap) into uninitialized storage per task 73's placement-new contract; `destroy` releases both. `invoke` calls `state->invoke_result(slot_index)` (which returns `slot.cached_result` — the value the worker recorded) or calls the backend's `fence_event` directly (depending on the chosen shape).
6. **`invoke_result` returns the cached result, not a fresh synchronize.** `EventRingState<Policy>::invoke_result(slot_index)` returns `slot.cached_result`. No synchronize call is performed on this path — the result was recorded by `on_worker_complete` before the slot was released. If the slot was re-acquired and a new submission's `on_worker_complete` recorded a new `cached_result` before the registry/snapshot copy's invoke, the new value is returned (and that is correct: the registry entry for the original submission has already been removed/invalidated by `complete_task` before the new submission's `on_worker_complete` runs, per the pinned flow guarantee — registry entries are removed before or alongside slot release, never after). If the slot is still free with its original `cached_result` intact, the original value is returned. There is no path that synchronizes a possibly-reused slot from a registry/snapshot invoke — that is the safety property (Requirement 4's worker-side `on_worker_complete` is the only synchronize).
7. **Inline representation.** `kInlineMetadataMaxRank = 8`; `InlineCopyMetadata` is exactly `sizeof(CopyMetadataHeader) + 3 * kInlineMetadataMaxRank * sizeof(std::uint64_t)` = 240 bytes, `static_assert`ed trivially copyable, 16-byte-multiple sized, and `<= 1024` bytes. The bound is derived, not tuned: CUDA documents 4,096 kernel-parameter bytes as its floor across `sm_2x`–`sm_6x` (32,764 on `sm_70+`), ROCm/HIP documents no smaller universal limit and the conservative cross-runtime parameter floor (OpenCL `CL_DEVICE_MAX_PARAMETER_SIZE`) is 1,024 bytes — 240 bytes leaves ≥4× headroom under the tightest bound and covers every queued-copy shape in the repository (maximum rank 6, i.e. leading rank 4) with headroom to rank 10. Leading rank ≥ 9 takes the pooled fallback with unchanged `ensure_slot_capacity` growth, H2D copy, and slot release.
8. **Kernel variants.** One shared device-function body; two `IOM_GPU_GLOBAL` kernels (pointer form, inline form) and two `launch_grid_stride_copy<Policy>` overloads computing today's identical geometry (256 threads, `ceil(total_words / 256)` blocks capped at 65535, `IOM_LAUNCH_KERNEL`). No kernel-body arithmetic changes (PF-006 is a separate finding); the inline kernel reads the same fields from the by-value header and the fixed array. The `.inl` stays macro-pure (no CUDA/HIP symbols), keeping it consumable by task 60's SYCL include.
9. **Fault seams.** `SubmissionFault::event_create` is consumed exactly once per ring acquire attempt via `Policy::check_acquire_event_fault()` consumed at the top of `acquire()` — before any free-slot search, before any lazy-create, and before any capacity-block wait. While capacity-blocked the fault check is not invoked again; the fault fires once at the top of the acquire call, before anything is marked in use. If the fault is armed, acquire throws before any slot is allocated/marked, with today's `std::runtime_error` text and pre-link cleanup (no metadata slot was held — metadata acquire happens after the ring acquire returns). This preserves both `event_create` conformance cases (inject → `queue->copy` throws pre-link) without assertion edits. `event_record` and `third_plane_launch` consumption points are byte-identical to the pre-task tree. `inject_submission_fault_for_testing` is unchanged.
10. **Teardown order, metadata release, and lifetime.** `~CudaQueue`/`~RocmQueue` bodies are unchanged (`invalidate_entries_for_queue` → `shutdown_and_drain` → activate → `synchronize_and_destroy_stream`); after the body the `shared_ptr<EventRingState<Policy>>` member is reset, dropping the queue's reference. `~EventRingState` runs only when the last `shared_ptr` drops — typically after every outstanding registry entry holding a lease has been removed (`try_release_entry`/`invalidate_entries`/`erase_entry_locked` invoke the lease's `destroy`, which releases the `shared_ptr`). Before destroying any event, `~EventRingState` releases the metadata slot attached to any still-in-use slot (via `metadata_pool_->release(slot.attached_metadata_slot)` when not the sentinel) so no metadata slot leaks when the state tears down with work still in flight. The metadata pool remains alive at this point — the public Device contract requires the creating Device to outlive every tensor and every queue on it, and the queue's `shared_ptr` member is reset in the queue body before the queue's `metadata_pool_` member is destroyed in the member-destruction phase, so the pool outlives the last lease's drop. `~EventRingState` then swallows activation failure, releases the metadata slot for every in-use slot, and for every created event calls `Policy::synchronize_event_noexcept` followed by `Policy::destroy_event_noexcept` — each native event destroyed exactly once, only there. No Device-level refcount, lease counter, or `~CudaDevice`/`~RocmDevice` assertion is added in this task (such a mechanism would introduce new registry/ownership state outside PF-004's scope).
11. **Execute rewiring (both backends identically).** After the no-op early return and `gpu_policy::activate`, compute `copy_metadata_layout`; when `layout.bytes <= sizeof(InlineCopyMetadata)`, value-initialize a stack `InlineCopyMetadata`, write it via the shared checked writer, and skip the metadata pool entirely; otherwise run the pooled path exactly as 63-AR-004 delivered it (`metadata_pool_.acquire`, `ensure_slot_capacity`, host write, `copy_from_host` H2D). Then call `state_->acquire()` (fault check first, throw pre-link with no slot allocated) to obtain a stable `Slot&`; set `slot.attached_metadata_slot` to the pooled slot index or `kNoAttachedSlot`; launch the matching kernel variant through the matching `launch_grid_stride_copy` overload; keep `check_kernel(copy_kernel_operation())` and `after_grid_stride_launch()` unchanged; record the pooled event via the unchanged `record_event` (the `event_record` seam stays per-recording); publish `task.event = slot.event` and `task.fence = &slot` (the worker-callback opaque); build the registry `detail::Fence` via the backend `make_fence` builder that fills `EventLeaseWithFailure{state_, slot_index, std::move(retained_failure)}` and pass it by `const&` into `register_copy_entries`. Failure cleanup: pre-link (before the launch is enqueued) calls `state_->release(slot)` without synchronize (event never recorded, no cached_result overwrite concern) plus `metadata_pool_.release(metadata_slot)` when one was acquired; post-link keeps today's `record_event_no_fault`-then-publish shape and routes the fence through the (rewritten) `on_worker_destroy` boundary.
12. **No per-submission heap resources, no intrusive refcounts, no Task ref, no std::function/SBO fits.** After this task the only heap allocations on the queued-copy path are the `std::shared_ptr<EventRingState<Policy>>` refcount bumps (lease copies, queue construction) and the registry/outcome/std::function-side allocations owned by 73-PF-003. The lease copies perform control-block refcount operations, not heap allocations — the zero-alloc claim is scoped to the `shared_ptr` copy/move (which adjusts the control block's atomic refcount) and the `exception_ptr` copy/move (which adjusts its refcount); both are non-allocating per the standard library contract. `grep -rn "CudaFenceResource\|HipFenceResource\|destroy_cuda_resource_noexcept\|destroy_hip_resource_noexcept\|add_ref\|release_ref" src/cuda src/rocm` returns zero matches; `grep -rn "cudaEventCreateWithFlags\|hipEventCreateWithFlags" src` finds the runtime call only inside the two policies, invoked only from `state_->acquire`'s lazy-growth path; `grep -rn "cudaEventDestroy\|hipEventDestroy" src` finds the runtime call only in `destroy_event_noexcept`, reached only from `~EventRingState`. The previous per-submission intrusive `new` + refcount dance is gone.

- Adding absolute latency gates to any always-run test target (NT-001's contract); the timing evidence below is remote measurement, not a ctest gate.

- Growing `detail::kFenceStorageBytes` or changing `kFenceStorageAlign` (73-PF-003 pins both); if `EventLeaseWithFailure` fails the `static_assert` on a supported platform, the design must be restructured to fit, not the budget grown.
- Any Device-level bookkeeping (refcount counter, lease counter, `~CudaDevice`/`~RocmDevice` assertion) — the public Device contract is the precondition, not a runtime check.
