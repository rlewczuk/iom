### What the outputs mean

- **Host elapsed time** measures the caller's wall clock, including launch, synchronization, runtime, and possibly profiling overhead. It is not automatically GPU kernel time.
- **Dispatch/API trace** attributes runtime calls, copies, launches, and sometimes vendor-provided device intervals. A launch timeline is useful for locating work; it does not imply hardware counters.
- **Device duration/counters** require a supported device, metric, driver/runtime, and permitted access. Replay-based counters can serialize or replay kernels and perturb duration. Do not compare profiler durations with unprofiled benchmark timing.
- **Modeled CPU cost** (e.g. Callgrind instruction/cache events) is simulated/instrumented attribution, not native PMU time.
- **Correctness diagnostics** (sanitizers, Memcheck, debuggers) identify faults; they are not performance measurements.

For comparable measurements, sync the exact local workspace before every remote execution, record exact revision/workload/host/tool, and serialize on a host with `flock -w 120 /tmp/iom-perf.lock`; GPU work additionally acquires `flock -w 120 /tmp/agent-gpu0.lock` in that order. Bound the full operation with `timeout --kill-after=30s`. These cooperative locks cannot exclude unrelated workloads.

## References and measurement discipline

Project precedents above are retained historical evidence, **not new profiler executions**. The CUDA `nsys` report attributed launched kernels and included device-time statistics; ROCm `rocprofv3` traced dispatches but had no native timing/counters; SYCL `sycl-trace` established dispatch attribution without device timing/counters. Host IOM observations use a monotonic clock and do not become device duration merely because a profiler is installed.

Before any new measurement, sync the exact selected workspace using [csw-remote](../../.omp/skills/csw-remote/SKILL.md); run only on the selected remote host. Take `/tmp/iom-perf.lock` first and `/tmp/agent-gpu0.lock` second for GPU work, each with bounded acquisition; put the **entire** setup/timed command under a bounded `timeout`. A profiler run and an unprofiled benchmark are different experiments; keep their evidence separate. This inventory intentionally does not install packages, alter sysctl/driver security, or assert unsupported profiler capability.
